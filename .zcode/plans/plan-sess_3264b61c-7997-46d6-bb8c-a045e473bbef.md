## 终版合并实施计划

### 一、目标目录

在 `design/` 下新建：

```text
design/产品优化方案终版-0727/
├── README.md
├── 产品优化方案终版.md
├── 三方案差异分析.md
└── 路线图.md
```

采用 4 文件而非拆成十余个文件：既能保持单一权威，又方便按角色阅读和后续维护。

### 二、`README.md`：终版入口与权威声明

内容包括：

- 终版定位、适用范围和阅读顺序；
- 明确 v1/v2/v3 作为历史评审与专项记录保留，但终版是后续执行唯一主规格；
- 文件导航；
- 与 `design/roadmap-data-stats.md`、设计稿和 HANDOFF 的关系；
- 当前代码事实快照，避免把目标状态误写成已完成。

### 三、`三方案差异分析.md`：系统比较与冲突裁决

详细对比三套方案的：

- 产品定位与信息架构；
- UI/UX、暗色、动效、响应式、无障碍；
- 布局数量、命名、主题模型和自由构图；
- 自定义编辑器；
- 技术架构、Schema、服务端和桌面端；
- 数据闭环、测试、性能、优先级和风险。

每项给出“v1 / v2 / v3 / 终版裁决”矩阵，并明确：

- 保留 v1 的产品论证、演出后台叙事、动效细节和“先验证再做编辑器”的节奏；
- 保留 v2 的布局子系统细节、analyze → plan → render 契约、Shape/FreeformLayout 和“挑模板→微调→导出”动线；
- 以 v3 的 Layout/Palette/Skin/Preset、产品闭环、Electron、测试、性能和发布门作为总框架；
- 修正现有方案中的过时或矛盾内容：两态状态模型、画布目前只有 2 个预设、当前只有 grid-wrap、S1–S3 已完成而 S4/S5 未完成、Electron 仅 spike、anchors/palettes/skins 尚未实现、benchmark 尚未建立等。

### 四、`产品优化方案终版.md`：合并后的唯一主规格

按以下结构编写：

1. 执行摘要和最终重构结论；
2. 当前代码事实、产品边界和兼容铁律；
3. 产品定位、用户分层、完整任务闭环与目标信息架构；
4. UI/UX：工作台、模板中心、预览/对比/编辑、参数检查器、暗色、动效、响应式、无障碍；
5. 架构：保留项、重构项、三段式 LayoutPlugin、WorkspaceDocument、服务端拆分；
6. 四领域模型：Layout / Palette / Skin / Preset，含回退链和内置/用户资源边界；
7. 统一布局体系，消除 v1/v2/v3 命名重复：
   - grid-wrap
   - magazine-flow
   - polaroid-collage
   - notebook-lines
   - live-set
   - artist-rail
   - subject-orbit（吸收 halo/vinyl-rings，含 orbit/contour/split-flow/wreath/satellite）
   - free-flow（吸收 flow/cloud-flow）
   - editorial-cover 作为增强模板
8. 背景主体、Shape、锚点、路径、碰撞、分页和归一化坐标；
9. 自定义编辑器：数据容器优先、预览画布与 PIL 最终渲染分离、统一 zone/layout mode 词汇；
10. CanvasSpec、ParamSpec、Schema、API 和迁移；
11. 数据统计、数据驱动海报、Electron 和置顶速查；
12. 测试金字塔、性能预算、可观测性和回退；
13. 验收标准、伪升级黑名单和最终决策清单。

关键裁决：

- 不整项目重写；
- `grid-wrap` 继续固定 2 页以保护旧金标准，新布局才使用自动分页和背景策略；
- Palette v1 先保留现有 5 个颜色角色 + font roles，其他 UI 角色后续扩展；
- anchors 默认采用 0–1 归一化坐标；
- 顶层 `themes/` 作为内置兼容资源，用户可写布局/预设放在用户数据目录；
- `halo`、`vinyl-rings` 统一为 `subject-orbit` 的模式，不重复实现；
- 不新增 `Song.pinned`，主推使用手动预设或“最近学会 + 热度”等规则；
- 首批 UI 仍只展示当前两个画布预设，扩展预设在工作台阶段追加；
- 用户编辑器在内置布局经过真实使用验证后启动，不提前造完整图片编辑器。

### 五、`路线图.md`：单一执行路径

整合三份路线图为 P0–P9：

- P0：事实基线、ADR、Schema、去魔数、字体缓存与 benchmark；
- P1：四模型兼容层、Preset、用户目录决策、server deps/routers；
- P2：Shape、路径、碰撞、分页、FreeformLayout 运行时；
- P3：首批高价值布局（magazine、collage、live-set）；
- P4：自由与数据布局（notebook、artist、subject-orbit、free-flow）；
- P5：工作台 UI/UX 系统性重构；
- P6：预设、主题、历史、S4/S5 统计及数据反哺创作；
- P7：正式 Electron 壳、用户目录、置顶速查与全局快捷键；
- P8：可视化自定义布局编辑器（触发条件：内置布局被真实高频使用）；
- P9：性能、无障碍、数据可靠性和正式发布门。

路线图开头明确与 `roadmap-data-stats.md` 的分工：S1–S3 已完成，S4/S5 的事件 Schema 和统计口径仍以该文档为单一真相，终版仅在 P6 合流，不重复定义。

每个 Phase 均包含目标、依赖、任务、关键产出、守护、退出条件和验收；另含 S/P/M 映射、并行支线、里程碑和提交边界。

- 校验 4 个终版 Markdown 的标题、术语、布局名、Phase、相互链接；

- 创建原子提交：`docs(plan): 合并三套产品优化方案为 0727 终版`；

- 推送后核实本地与远程一致并报告提交哈希。
