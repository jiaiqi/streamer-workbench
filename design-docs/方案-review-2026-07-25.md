## 二、P0 级缺口（立即处理）

**结论**：无需修正数据，保留现状。

### P0-2 背景预处理缓存 ✅ 已实现（2026-07-25）

**位置**：`core/engine.py::render_page`  
**问题**：每次渲染都重新读背景图 → 去水印 → 全屏延展 → 画柔光。但参数调整（字号/边距/栏数）时这部分完全不变。  
**设计承诺**：《设计结论》§9.2「达标关键手段：背景预处理缓存……无此缓存，单页 <500ms 目标难以达到」。  
**建议**：

```python
# 在 engine.py 加模块级缓存
_BG_CACHE: dict = {}  # key: (theme_name, page, canvas_w, canvas_h)

def _get_base(theme, page, spec):
    key = (theme.name, page, spec.width, spec.height)
    if key not in _BG_CACHE:
        # 现有背景+水印+延展+柔光逻辑
        _BG_CACHE[key] = _compose_base(...)
    return _BG_CACHE[key].copy()  # 返回副本，避免污染缓存
```

### P0-3 自动备份 ✅ 已实现（2026-07-25）

**设计承诺**：《设计结论》§4.3「save() 写入前复制到 data/backups/，保留最近 20 份」。  
**当前**：`SongLibrary.save()` 只有原子写，无备份。  
**建议**：在 `save()` 入口加 `_backup_if_exists(path, backup_dir, keep=20)`。

### P0-4 版本迁移框架 ✅ 已实现（2026-07-25）

**设计承诺**：《设计结论》§4.3「App 启动时检查 version 字段，低于当前引擎版本则自动执行纯函数迁移」。  
**当前**：`version: 1` 硬编码，无迁移钩子。  
**建议**：

```python
CURRENT_VERSION = 1
MIGRATIONS = {}  # {from_version: migrate_fn}

def load_from_json(cls, path):
    data = json.load(...)
    v = data.get("version", 1)
    while v < CURRENT_VERSION:
        data = MIGRATIONS[v](data)
        v += 1
    ...
```

## 五、设计层面值得保留的好决策

复习一下那些做得很对的决策，未来不要走回头路：

1. **纯函数引擎 + core 禁 import UI**：这是项目最值钱的设计，让 Electron / 未来 Flutter / Web 壳都能用同一个心脏。
2. **金标准 diff=0 死线**：哪怕 Pillow 升一个小版本都可能崩，但这是精度的唯一保障。
3. **主题 JSON 驱动 + 新增主题零代码**：loader 扫描目录即可，运营/用户自助加主题。
4. **JSON 为唯一数据源 + 原子写**：拒绝 SQLite / localForage 的决策非常对（详见本报告附录 A）。
5. **状态模型简化为 active/draft**：设计文档明确写了简化理由——「个人单机工具不需要 wishlist/archived 的精细区分」。
6. **决策记录完整**：5 次推翻与重建（PySide6 → PWA → TS → Qt → Electron）全部有记录，未来避免重复讨论。

## 六、附录 A：为什么不用 SQLite / localForage

（已在 2026-07-25 主对话中讨论，此处存档）

| 方案 | 问题 |
|---|---|
| **localForage / IndexedDB** | ① 数据已在 Python 后端，会形成双数据源；② 无法做文件级备份；③ 跨工具兼容性丢失（VS Code 改不了）；④ Electron 打包后路径混乱 |
| **SQLite** | ① 178 首 × 15 字段用不到 SQL；② 金标准/备份逻辑要重写；③ 破坏「md ↔ json」同步约定；④ 二进制 blob 无法 git diff |
| **JSON + 原子写 + 备份** | ✅ 简单、可备份、可版本控制、可人工修复——个人桌面工具的最优解 |
