## 四、排版规格（精确到像素）

### 4.1 全局参数

| 参数 | 值 | 说明 |
|---|---|---|
| 左边距 MARGIN | 58 px | 所有分类最左列对齐的垂直轴线 |
| 右边界 R（标准） | 1022 px | 即 1080 − 58 |
| 右边界 R（抖音避让） | 按行动态取值 1022 / 856 px | 绕排避让，分界线下 R_BELOW=856（右缩约一栏，硬禁文边界 940 留 84 px 余量），见第八章 |
| 歌名字号 FONT_SONG | 36 px（避让版 34 px） | 全画面统一，任何情况不缩小长歌名 |
| 标签字号 FONT_LABEL | 40 px，粗体 | |
| 行高 ROW_H | 44 px | |
| 标签区高 LABEL_H | 74 px | 含标签下方间距；网格首行 y = 标签文字起点 y + LABEL_H |
| 分类间距 SEC_GAP | 26 px | |
| 首行起始 y | 100 px（全屏版 +240 偏移） | |

### 4.2 分栏规则

| 分类 | 页 | 栏数 | 排列 |
|---|---|---|---|
| 一字 | 1 | 左窄栏 1 列 | 歌名 x=62（MARGIN+4），纵排；**与二字并排**，见下方说明 |
| 二字 | 1 | 5 栏 | 区域 [200, R]，行优先（每行从左到右 5 个） |
| 三字 | 1 | 6 栏 | 区域 [MARGIN, R]，行优先 |
| 四字 | 1 | 6 栏 | 区域 [MARGIN, R]，行优先 |
| 五字 | 2 | 4 栏 | 区域 [MARGIN, R]，行优先 |
| 六字 | 2 | 3 栏 | 区域 [MARGIN, R]，行优先 |
| 长歌名/英文 | 2 | 2 列 + 独占行 | 见 4.4 |

**一字/二字并排布局（易错点，必须实现）**：一字与二字**共享同一个横向条带**，不是上下堆叠——

1. 「一字」标签画在 `(MARGIN, y)`，「二字」标签画在 `(200, y)`，两个标签**同一行 y**。
2. 标签下方 LABEL_H 后：一字歌名从 `x = MARGIN + 4 = 62` 纵排；二字网格从同一首行 y 开始，区域 `[200, R]`。
3. 该条带纵向占用行数 = `max(一字行数, 二字行数)` = `max(2, ceil(36/5)) = 8` 行；条带结束后 `y += 8 × ROW_H + SEC_GAP`，再画「三字」标签。
4. 因此一字歌名窄栏（x=62）是「最左列对齐 x=58」规则的**唯一例外**：一字的**标签**对齐 x=58 轴线，歌名本身从 x=62 起。

### 4.3 统一边距网格算法（核心，必须严格实现）

对每一个分类网格：

1. 按**行优先**（`row, col = divmod(i, cols)`）分配歌名到栏位。
2. 计算每栏的**栏内容最大宽度** `colws[c]` = 该栏内所有歌名的实测文字宽度最大值（指字体 advance width，PIL 中为 `ImageDraw.textlength()`，不要用 `textbbox` 的视觉包围盒）。
3. 栏间距 `gutter = (x1_area − x0_area − Σcolws) / (cols − 1)`，下限 12 px。
4. 第一栏文字从 `x0_area` 开始，之后每栏起点 = 前一栏起点 + 前一栏内容最大宽度 + gutter。
5. 效果：每一行最左歌名贴左边距、最右歌名贴右边界，**所有分类共享同一组左右边距，最左列严格对齐在 x=58 的轴线上**（唯一例外见 4.2 一字窄栏），各行左右留白一致。
6. 纵向推进：每个分类网格占用行数 = `ceil(歌名数 / 栏数)`；下一分类标签的 y = 当前网格首行 y + 行数 × ROW_H + SEC_GAP。各分类标签（除「二字」在 x=200 外）都画在 x = MARGIN。

### 4.4 长歌名/英文排列规则

1. 数据分两组：英文组 LONG_EN（After 17、Forever 21、April Encounter，保持原顺序）和中文长歌名组 LONG_CN。中英文按**是否含汉字（CJK 字符）**划分：不含汉字的归英文组，含汉字的归中文组（「恋爱ing」这类含汉字即归中文）。
2. 中文组长度口径：按**字符数**计（每个汉字、字母、数字各算 1 个字符，即 Python `len()`；例：「第57次取消发送」= 8），按长度从短到长**稳定排序**（同长度保持原顺序）。
3. **长度分流只适用于中文长歌名**：中文 ≤ 9 字进两列流、> 9 字独占行；**英文歌名无论多长都不参与分流，无条件进入两列流**（例如「Forever 21」按字符数超过 9，仍留在两列流）。
4. 两列流内容 = 英文组（在前）+ ≤ 9 字中文（在后），共 16 条；对半分：`half = ceil(16/2) = 8`，前 8 条为左列（从上到下），后 8 条为右列。
5. 左列从 `x = MARGIN` 开始；右列起点 `rx = R − 右列最宽歌名的实测文字宽度`（即右列最宽歌名的右缘贴 R）。
6. 两列流结束后 `y += half × ROW_H + 12`，再逐行画独占行（当前 3 条：一个像夏天一个像秋天 / 我喜欢上你时的内心活动 / 遇见你的时候所有星星都落到我头上），每条从 `x = MARGIN` 开始，行距 `ROW_H + 4`；需要换行时只换行、**不缩小字号**。

### 4.5 分类标签绘制规格

设标签文字起点为 `(x, y)`，文字实测宽 `tw`，文字行高 `th = 标签字号 + 6`（即 40 号字时 th=46）：

1. 圆角矩形底色胶囊：范围 `(x − 18, y − 8, x + tw + 18, y + th + 8)`，圆角半径 18 px。即水平内边距 18 px、垂直内边距 8 px。
2. 标签文字画在 `(x, y)`。
3. 下划线：位于**胶囊底边下方 4 px** 处（uy = 胶囊底边 y + 4），范围 `(x − 2, uy, x + tw + 2, uy + 3)`——宽 = 文字宽 + 4 px（**左右各外延 2 px**），高 3 px，圆角 2 px。
4. 标签是画面中**唯一的装饰性 UI 元素**，无描边、无阴影、不可点击感。

### 4.6 柔光遮罩（薄雾层）

1. 在与画布同大的透明层上画一个**溢出画布**的圆角矩形：(−60, −60, W+60, 1410+偏移)，圆角 80 px。其中「偏移」= 8.2 的全屏偏移 OFF（标准版为 0，全屏版为 240，即底边 y=1650）。
2. 填充半透明白色（见 5.1 mist 色）。
3. 对该层做高斯模糊（半径 34 px）后与背景做 alpha 合成。
4. 效果：无边框、向四周消散的柔光，只托住文字对比度，**绝不能看起来像卡片**。

## 八、移动端与抖音适配（重要）

### 8.1 比例问题

- 抖音全屏为「填满裁剪」模式。9:16（0.5625）的图片在 9:20（≈0.448）手机上会被左右裁掉约 110 px，切到歌名。
- **全屏版画布固定 1080×2400（9:20）**：主流安卓完美全屏；iPhone（19.5:9）只裁上下无内容区；21:9 极端屏左右各裁约 2 px。

### 8.2 全屏版生成方法

1. 背景等比缩放到宽 1080（高约 1919），贴到画布底部（保住底部装饰）。
2. 取背景顶部 80 px 拉伸填满剩余顶部空间，高斯模糊 6 px 柔化接缝。
3. 全部排版 y 坐标增加偏移 `OFF = (2400 − 1920) / 2 = 240`，即首行标签从 y=340 开始，内容落在中央安全区（240–2160 为 9:16 设备的安全区）。按 4.2–4.4 规则累加后的实际内容范围：**第 1 页 y ≈ 340–1625**（四字末行文字底部），**第 2 页 y ≈ 340–1600**（独占行末行文字底部）。不要反向硬编码这些数值——它们是从首行 y=340 按 LABEL_H / ROW_H / SEC_GAP 逐节累加的结果，实现时应按规则推进 y 而不是抄绝对坐标。

### 8.3 抖音 UI 避让（--avoid-rail 规则：绕排避让）

- 右侧头像/点赞/评论/收藏栏区域：**x > 940 且 y > 1080 禁止出现任何文字**（硬禁文边界）。
- 实现为「绕排」而非整版收窄：右边界 R **按行所属区域动态取值**——
  1. 歌名文字顶部 y 满足 `y + 36 <= 1080` 的行：R = 1022（即 W − MARGIN，满宽）。
  2. 其它行：R = **R_BELOW = 856**（约等于满宽 6 栏布局第 5 栏的右缘，整体右缩约一栏；相对硬禁文边界 940 留有 84 px 安全余量）。
  3. 歌名字号按备用规则 36→34，**全画面统一 34 px**，不混用 36。
  4. 网格分类跨越分界线（y=1080）时，采用「同列减栏」而不是各自独立重排：
     a. 先按**整版满宽 R=1022、全部歌名、原栏数**计算统一列布局（每栏内容最大宽度 colws、栏间距、每栏 x 坐标 positions），与无避让时完全一致；
     b. 分界线上方的行：按原栏数、用这组 positions 正常绘制；
     c. 分界线下方的行：**沿用同一组 positions 的前缀**，只从右端去掉会越界的栏——取最大的 k 使 `positions[k-1] + colws[k-1] <= R_BELOW`，剩余歌名按行优先、每行 k 个重排；
     d. 上下两块的列 x 坐标逐列严格相等，下方行只是少了最右栏，形成「上宽下窄」的绕排效果；
     e. 分类纵向推进按实际行数计算：`r_cut + ceil(剩余歌名数 / k)`，不硬编码行数。
  5. 第 1 页一字/二字并排条带：二字网格区域为 [200, R_at(行)]（条带整体在分界线之上，实际 R=1022，满宽）。
  6. 第 2 页长歌名/英文的两列流与独占行：均在分界线之下，右列最宽歌名右缘贴 **R_BELOW=856**（`rx = 856 − 右列最宽歌名实测宽`）、独占行从 x=58 起，通过同一个 R_at 逻辑实现，不硬编码；五字、六字在分界线上方，保持满宽不变。
  7. 分类标签都在左侧（x=58 或 x=200），不受 R 影响。
  8. 整块都在分界线下方的分类（四字）：不跨线，避让版从 6 栏减为 **5 栏两端对齐到 [58, 856]**——栏间距随之加大（约 13→29 px），右缘收到约 856；没有上块需要对齐。非避让模式保持 6 栏满宽。
  9. **柔光层底边随内容下延**：避让版四字 5 栏后行数 7→9（+88 px），柔光圆角矩形底边从 1410+OFF 下延到 **1498+OFF**，保证所有文字仍落在柔光上；非避让模式保持 1410+OFF 不变。
- 参考效果（177 首数据下）：第 1 页一字/二字条带满宽；三字 43 首在 y≈1086 处减栏，上 5 行每行 6 个（满宽），下 3 行为 5/5/3（去掉最右栏，列位与上块逐列对齐，右缘约 850）；四字 5 栏 9 行（5×8+1），右缘约 856。第 2 页五字、六字两块满宽；长歌名两列流右缘约 856。两页内容底部约 y=1704 / 1590，远在 1900 之上。这些数值是按规则累加的结果，不要反向硬编码。
- 底部标题/功能区 y > 1900 同样不放文字（当前内容最低约 y=1704，天然满足）。

### 批量重新生成全部主题（更新歌单后）

更新歌单数据（脚本顶部列表，与歌单数据同格式）后，用循环一次重出全部 7 个主题的全屏绕排版（Git Bash）：

```bash
for t in 海洋柔光 梦幻海洋 奶油花园 青提气泡 卡通音符 奶油玻璃 轻复古唱片; do
  python build_playlist.py --theme "$t" --fullscreen --avoid-rail --tag 糖圆体全屏绕排
done
```

- 会**同名覆盖**各主题文件夹内的现有 `…-糖圆体全屏绕排-1/2.png`；如需保留旧版，先改 `--tag` 或手动备份。
- 跑完后按「第十章 · 输出前检查清单」逐主题抽检（总数、避让区、无截断）。
- 新增主题后，把主题名加进循环列表即可。

- 新增/更换主题背景：把新图按预设的文件名（`background-1/2.png` 或 `bg1/2.png`）放入对应主题文件夹即可；带左下角「AI生成」水印的 AI 背景，把主题预设的 `watermark` 设为 True 让脚本自动修复；水印在其它位置需先人工修复。
- 更新歌单：只改脚本顶部数据列表（与歌单数据同格式），其余不动。
- 新增主题：在脚本顶部 THEMES 字典加一条预设（前缀、背景文件名、是否去水印、两页 STYLE 配色）。
- 唯一可为搭配新背景调整的视觉参数：主题预设里的 `style` 配色（海洋柔光见 5.1）。
