## 1. 评审结论总览

| 视角 | 结论 | 动作 |
|---|---|---|
| 产品经理 | 产品已实际长成"直播歌单工作台"，但叙事与信息架构还停留在"海报生成器"；海报创作面是半成品。**不需要推倒产品** | 主线收敛：日常面（歌单管理）+ 创作面（海报工坊）；布局升为一等功能 |
| UI/UX | 「晨光纸感」视觉语言方向正确，**保留**；但 React 对设计规范对齐率仅 ~15%、暗色模式实现方式会腐烂、动效规范未落地；**工作台交互需要局部重设计**（不是推翻视觉） | 视觉还债（令牌/暗色/动效）+ 工作台以"模板卡片 + 实时预览 + 语义参数"重做 |
| 架构师 | `core/` 纯函数引擎 + 金标准（16/16 diff=0）+ LayoutPlugin 插件体系**底子好，保留**；但避让区硬编码、主题×布局耦合、无声明式布局载体，**"布局子系统"需要专项重构** | 引擎不动，重构避让/锚点/色板分层/字体角色/Schema 解释器五件事 |

**一句话**：方向对、地基好，不推翻；做三件事——① 布局多套装 + 一等功能化；② 工作台交互重做；③ 布局子系统重构让新布局变成"写配置"。

## 2. 产品经理视角：产品定位与主线收敛

### 2.1 现状诊断

产品实际能力（已实现）：

- 海报渲染：7 主题 × 1 布局（grid-wrap）× 2 画布预设，逐像素金标准；
- 歌曲库：178 首，active/draft 状态、全字段编辑、原子写 + 滚动备份；
- 学歌管理：标记学会、`learned_at` 回填；
- 曲谱管理：附件上传/预览/直播 T 键看谱（S3）；
- 直播速查（/quick）：已会✅/在学📖/不会❌ + 今晚点歌队列；
- 事件日志（S1）+ 点歌双写（S2）已上线，S4 打卡 / S5 统计在 roadmap 上。

产品层暴露的问题：

1. **导航 6 项有 3 项占位**（主题管理/场景预设/导出历史），信息架构未收敛；
2. **布局不是一等功能**：
   - `ui/src/App.tsx:352` 底栏"全行网格绕排版"是硬编码文本；
   - `App.tsx:114` 预览 URL 未传 `layout` 参数，靠后端默认值兜底；
   - 前端对接了 `/api/layouts/{id}/params` 却写死 `grid-wrap`（`App.tsx:92`）；
   - 全产品没有任何布局选择入口——后端的 LayoutPlugin 契约零曝光；
3. 海报创作动线缺失"模板"概念：用户面对的是"主题列表 + 参数面板"，而不是"挑一张好看的海报 → 微调"。

### 2.2 产品重新定位

> **歌单海报生成器 = 主播的直播歌单工作台。**
> 日常面管"歌"（库/学歌/曲谱/速查/统计），创作面管"图"（海报 = 主题 × 布局 × 画布 × 内容）。

双主线：

```
直播歌单工作台
├── 日常面（已主线化，按 roadmap-data-stats.md 继续 S4/S5）
│   ├── 歌曲库 / 学歌管理 / 曲谱 / 速查 /quick / 统计
└── 创作面（本方案主线，从半成品升级为完整产品）
    ├── 模板中心：主题 × 布局 的组合卡片，所见即所得
    ├── 布局工坊：内置布局 + 自定义布局编辑器
    ├── 主题工坊：主题管理（后续，见 §9 范围外说明）
    └── 导出中心：单页/批量导出 + 导出历史
```

### 2.3 信息架构调整

导航从 6 项（含 3 占位）收敛为 5 项实功能：

| 导航项 | 内容 | 状态 |
|---|---|---|
| 海报工作台 | 模板卡片 + 实时预览 + 语义参数 + 导出 | 重设计（本方案 §3.3） |
| 布局工坊 | 内置布局浏览 + 自定义布局编辑器 + 我的布局 | 新增（本方案 §6） |
| 歌曲库 | 现状保留 | 保留 |
| 学歌管理 | 现状保留 + S4 打卡 | 保留 + 迭代 |
| 统计 | S5 统计视图 | 按 roadmap 新增 |

原"主题管理"并入创作面（主题卡片即管理入口）；"场景预设"降级为工作台内的"保存我的配方"（主题×布局×参数快照）；"导出历史"基于 `poster_exported` 事件实现为工作台抽屉，不占导航位。

### 2.4 产品边界（保持不变）

个人单机工具、不做账号/云同步/素材市场、不做弹幕互动工具。自定义布局的"分享"仅限导出/导入 JSON 文件，不做在线市场。

## 3. UI/UX 视角：视觉保留、工作台交互重设计

### 3.1 视觉系统：保留 + 还债（不推翻）

「晨光纸感」（奶油纸底 `#f7f6f2` + 海洋青 `#2f8f7a` + 暖珊瑚 `#d9764f` + 衬线标题）方向正确、与 7 套海报背景气质一致，**视觉语言保留**。需要还的三笔债：

**债 1：暗色模式实现方式重构（高优先级）**

现状：`dark` 作为 prop 逐层透传，每个元素写两遍三元表达式 className（`App.tsx` 全文件如此）。问题：

- 每加一个视图都要手写两套样式，必然不一致、必然腐烂；
- 与设计稿的 `.dark` 令牌覆盖机制（`shared.css` 已定义全套暗色令牌）背道而驰。

目标：改回**令牌化暗色**——`index.css` 用 `:root` / `.dark` 双令牌块，组件只用语义类（`bg-card text-foreground`），切换暗色 = `<html>` 加 class。组件代码里的 dark 三元全部删除。同时加防 FOUC 内联脚本（设计稿已有范式）。

**债 2：React 组件对齐设计规范（中优先级）**

HANDOFF §5 承认 React 对齐率 ~15%（2/13 组件类）。按 `design-tokens.json` + `shared.css` 的 13 个组件类（`.gp-card/.gp-btn/.gp-chip/.gp-switch/...`）逐个对齐，原生 `<input type=number>/<select>/<details>` 替换为设计规范控件（滑杆、分段选择器、手风琴）。

**债 3：动效落地（中优先级）**

设计稿定义了 `.gp-stagger/.gp-rise` 入场动效与 `prefers-reduced-motion` 降级，React 端基本未用。落地清单：

- 视图切换：150–200ms 淡入 + 8px 上浮；
- 列表/卡片：stagger 30ms 逐项入场；
- 主题/布局卡片选中：ring 动画 + 缩略图轻微 scale；
- 预览图切换：crossfade（见 §3.3）；
- 所有动效包 `prefers-reduced-motion` 降级。

### 3.2 预览性能与体验（感知性能优先）

现状：整图 `<img>` 重载 + 全屏 loading 遮罩，调参防抖 300ms 后闪一次。目标体验是"拖滑杆时海报在手下流动"：

1. **双图 crossfade**：新旧两张 `<img>` 绝对定位叠放，新图 onLoad 后旧图 200ms 淡出；不再出现空白遮罩；
2. **渐进式预览**：`/api/render` 增加 `quality=draft`（输出宽 540 JPEG，渲染耗时大头是文字层布局，底版已有 `_BG_CACHE` 缓存），调参走 draft，停手 500ms 后补一张 full PNG；
3. **HTTP 缓存修复**：预览 URL 的 `&t=${renderKey}` 破坏缓存（HANDOFF #15），改为内容寻址（参数 hash 作 query，相同参数直接命中浏览器缓存）；
4. loading 遮罩只在首次渲染或错误重试时出现。

### 3.3 工作台交互重设计（本方案 UI 主线）

**创作动线反转**：从"选主题 → 看预览 → 调参"反转为"**挑模板 → 微调 → 导出**"。

```
┌──────────────────────────────────────────────────────────────┐
│ header：歌单海报 · 已会 152 · 未会 26 · 渲染 180ms/张          │
├──────────┬────────────────────────────────────┬──────────────┤
│ 模板中心  │           实时预览区                │  参数面板     │
│          │                                    │              │
│ ┌──────┐ │    ┌──────────────────┐           │ ▸ 内容       │
│ │模板卡 │ │    │                  │           │   分类方式    │
│ │主题×  │ │    │   海报预览        │           │   显示范围    │
│ │布局   │ │    │  (crossfade)     │           │ ▸ 版面       │
│ ├──────┤ │    │                  │           │   密度 ─○──  │
│ │模板卡 │ │    │  避让区可拖拽     │           │   字号 ──○─  │
│ ├──────┤ │    │                  │           │ ▸ 主题微调    │
│ │模板卡 │ │    └──────────────────┘           │ ▸ 我的配方    │
│ └──────┘ │  页 1|2 · 画布预设 · 缩放           │              │
│ + 布局筛选│                                    │  [导出…]     │
├──────────┴────────────────────────────────────┴──────────────┤
│ 底栏：主题 · 布局 · 画布 · 快捷键提示            [下载][导出…] │
└──────────────────────────────────────────────────────────────┘
```

关键交互决策：

1. **模板卡片 = 主题 × 布局的组合缩略图**（真实渲染的缩略图，不是图标）。左栏顶部加布局筛选 chip（全部/网格/环绕/杂志/拼贴/曲线/极简/我的）。点卡片 = 同时选定主题 + 布局。
2. **布局选择器独立于主题**：底栏"布局"处可单独切换布局（保持当前主题），切换时布局参数重置为该布局默认值。
3. **参数语义化分层**：
   - 内容层：分类方式（按字数/按歌手/按首字母/按标签——由布局声明支持哪些）、显示范围（全部/仅新歌/点歌 TOP N）；
   - 版面层：密度（紧凑↔宽松，映射 row_h/cols/gap 的参数包）、字号、留白——滑杆 + 3 档预设（紧凑/标准/宽松），高级用户可展开"专家参数"（即现有 ParamSpec 数值）；
   - 主题微调：文字色/标签色取色器（写回 skin 覆盖，不改主题源文件，见 §4.3）。
4. **避让区可视化编辑**：预览图上避让形状以半透明红色区域 + 手柄渲染，可拖拽调整，结果写回 theme.json 的 anchors（见 §4.1）。这是"这条花别被字压住"的直接答案。
5. **我的配方**：当前（主题×布局×参数×画布）一键存为命名配方，出现在模板中心顶部。
6. **导出**：单页下载 / 单张导出 / 批量导出（当前布局 × 全主题）保留；批量导出进度从轮询改为已有的 job 机制 + 前台 toast。

### 3.4 布局工坊（新视图）

- 左：布局列表（内置 6 套 + 我的自定义），卡片含示意缩略图 + 适用说明；
- 右：选中布局的详情——参数说明、支持的分类方式、支持的避让、示例海报；
- 自定义布局：「新建布局」进入编辑器（§6.3）。

## 4. 架构师视角：布局子系统专项重构

### 4.0 保留不动的部分

- `core/` 纯函数引擎、金标准测试（16/16 diff=0）、`LayoutPlugin` 插件接口、`DrawContext` 零件下沉、背景底版 `_BG_CACHE`、JSON 持久化 + 原子写 + 滚动备份 + 事件日志哲学。**引擎不重写。**

### 4.1 避让区形状化 + 背景锚点（最核心的重构）

**现状**：`core/context.py:20-31` 三个魔数（`AVOID_CUTOFF_Y=1080`、`AVOID_HARD_X=940`、`R_BELOW=856`）是 grid-wrap 为抖音评论区拍的固定值；`CanvasSpec.avoid_zones` 只有矩形元组；避让策略（`_r_at`）绑死 grid-wrap 语义。

**目标模型**：

```python
# core/spec.py
@dataclass(frozen=True)
class Shape:
    """避让/锚点形状。kind: rect | ellipse | polygon"""
    kind: str
    points: tuple          # rect: (x0,y0,x1,y1); ellipse: (cx,cy,rx,ry); polygon: ((x,y),...)
    margin: int = 0        # 外扩呼吸带

# CanvasSpec.avoid_zones: Tuple[Shape, ...]
```

**theme.json 按页声明锚点**（背景里的视觉主体位置，人工标注一次，编辑器可辅助框选）：

```jsonc
// themes/奶油花园/theme.json（增量字段）
"anchors": {
  "1": [
    {"id": "花束", "kind": "polygon", "points": [[0,1500],[1080,1500],[1080,2400],[0,2400]], "margin": 24},
    {"id": "月亮", "kind": "ellipse", "points": [620, 1700, 60, 70], "margin": 40}
  ],
  "2": [ ... ]
}
```

**引擎提供通用"绕形状排文"零件**（DrawContext 新增，替代 grid-wrap 私有的 `_r_at`）：

```python
# DrawContext 新增公共能力
def flow_right_edge(self, y: int, shapes) -> int: ...
    """给定 y，返回该行可用右边界（被形状切掉后的最近边缘）"""
def flow_segments(self, y: int, shapes) -> list[tuple[int, int]]:
    """给定 y，返回该行所有可用水平线段（形状把一行切成多段时）——环绕布局的核心"""
```

实现要点：按 y 采样行高，逐行计算 `flow_segments`，文字流依次填充线段；矩形/椭圆/多边形统一走"形状与水平线求交"的几何例程。grid-wrap 的旧行为 = 一个 rect 形状 + 只取最左线段的特例，**旧魔数迁移为 grid-wrap 的默认 shape 声明，金标准保证像素不变**。

### 4.2 页数与背景解耦

现状：`theme.backgrounds` 固定 `{"1": ..., "2": ...}`；`engine._compose_base` 按 page 取图。新布局可能 1 页或自动分页（`pages=None`）。

- `Theme.background_path(page)` 增加取图策略字段 `bg_strategy: "fixed" | "cycle" | "extend"`：fixed = 现状（页数必须匹配）；cycle = 页码取模循环使用背景；extend = 超出页用最后一页 + 柔光延展。
- `page_capacity=1920` 硬编码改为从 `CanvasSpec.height` 推导（HANDOFF #14）。

### 4.3 主题 × 布局解耦：palettes × skins 两层

设计结论 §3.1 早已规划，现在落地：

```
现状：themes/<主题>/theme.json = 背景 + 配色（为 grid-wrap 调的）+ 字体
目标：
  palettes/<色板>/palette.json   → 纯颜色角色（text/label/pill/line/mist + 扩展角色）
  themes/<主题>/theme.json       → 背景图 + anchors + 引用 palette + 可选布局级覆盖(skins)
  skins 覆盖：theme.json 内 "skins": {"halo": {"text": [...]}, "collage": {"card": [...]}}
```

- 布局通过 `LayoutPlugin.extra_colors()` 声明扩展颜色角色（卡片底、描边、装饰色——`base.py:53` 钩子已存在，未启用）；
- 主题未提供某布局的 skin 时，回退到 palette 默认映射，**保证任意主题 × 任意布局都能渲染**（可能不是最好看，但不出错）；
- UI"主题微调"取色器写的是 skin 覆盖层，不动 palette 源文件。

### 4.4 字体角色多阶化

现状：全局 `font_song` / `font_label` 两个字号角色 + 单一字体文件。杂志版需要刊头大标题，拼贴版需要注释小字，halo 需要弧线上的小标签。

```python
# Style 扩展（向后兼容：font_song/font_label 保留为默认角色）
font_roles = {
  "title":  {"size": 96, "font": None},      # 刊头/大标题
  "label":  {"size": 40, "font": None},      # 分类标签
  "song":   {"size": 36, "font": None},      # 歌名正文
  "note":   {"size": 24, "font": None},      # 注释/日期/序号
}
```

- 布局声明所需角色，主题可按角色覆盖字体文件（theme.json 的 `font` 升级为 `{role: path}` 字典，旧字符串值兼容）；
- 引擎按角色缓存 `ImageFont.truetype` 实例（现在每页渲染都新建两次 truetype，角色多了之后必须缓存）；
- 避让降字号硬编码 `34`（`engine.py:79`）改为布局声明的 `avoid_font_scale: 0.94`。

### 4.5 声明式布局 Schema + FreeformLayout 解释器

详见 §6.2。架构定位：**与 Python 插件平行的第二种布局载体**。

```
LayoutPlugin（抽象基类，不变）
├── Python 插件（复杂逻辑）：grid-wrap / halo / flow / ...
└── FreeformLayout（解释器插件）：读 layout.json 的 zones，翻译为 DrawContext 调用
    └── 杂志版、极简版等"规整"布局也用 Schema 实现（吃自己的狗粮）
```

## 5. 多布局规划：首批 6 套内置布局

> 设计原则：**布局要跟背景图谈恋爱**。7 套背景的视觉重心各异（奶油花园花在底部、梦幻海洋有月亮、卡通音符有漂浮元素），所以锚点（§4.1）是布局与背景之间的通用语言：布局引用锚点绕排，而不是硬编码坐标。
>
> 每套布局都需交付：Python 插件或 Schema、ParamSpec 参数集、各主题适配的 skin 默认值、金标准快照（新布局单独建金标准，不动现有 16 张）。

### L1 全行网格绕排版（grid-wrap）——现有，保留

- 排法：分类胶囊标签 + 全行分布网格 + 右下矩形避让；
- 角色：**保底布局**，信息密度最高（178 首全量无压力）；
- 动作：仅做魔数迁移（§4.7），渲染结果金标准保证像素不变。

### L2 环绕主体版（halo）★ 本方案旗舰

- **排法**：以背景主体（月亮/花束/唱片，来自 theme anchors）为圆心，歌名沿主体外缘**环形带绕排**；环带按分类分段，分类标签嵌在弧线起点；主体周围留出呼吸带（shape.margin）。环形装不下的剩余分类回落到底部/侧翼的流式区（flow_segments 双列分流）。
- **与背景关系**：强耦合。无 anchors 的主题自动降级为"以画面几何中心为虚拟圆心"的环绕。
- **参数**：环绕起始角、环带宽度、呼吸带间距、环内/环外字号比、剩余区列数。
- **技术依赖**：`flow_segments`（§4.1）+ 沿弧线排文（逐字定位 + 旋转，PIL 支持单字 rotate 后粘贴）。
- **页数**：自动分页（pages=None），环带容量按周长动态计算。
- **风险**：弧线排文是全方案技术峰值，放在第二批第一个做，失败回退 = 用 flow_segments 的"双侧分流"近似环绕（视觉上仍是"绕着元素排"）。

### L3 杂志双栏版（editorial）

- **排法**：衬线刊头（主播名 + 日期 + 期号，title 字体角色）+ 细分割线 + 双栏/三栏分类正文，栏间距大、大量留白；长歌名单独一个"深读区"通栏。
- **与背景关系**：弱耦合，主体压底部留白区，避让用矩形即可。
- **参数**：刊头文案、栏数（2/3）、密度、是否显示期号/日期。
- **实现**：用 FreeformLayout Schema 实现（吃狗粮第一犬）。
- **场景**：封面感最强，适合社交平台发布图。

### L4 便签拼贴版（collage）

- **排法**：每个分类一张"撕纸便签"卡片（圆角 + 微投影 + 纸胶带角标），随机微旋转 ±3°、错落叠放；歌名在便签内竖排/双列；便签尺寸随内容自适应，装箱用轻量碰撞检测（按高度排序贪心放置 + 锚点避让）。
- **与背景关系**：中耦合，便签避开 anchors 区域。
- **参数**：旋转幅度、便签底色（skin 的 card 角色，首个启用 extra_colors 的布局）、装箱松紧、是否显示纸胶带。
- **种子固定**：随机旋转用 `hash(theme+layout+日期)` 做种子，保证同一配方每次渲染一致（金标准可测）。
- **场景**：手账感，与奶油花园/奶油玻璃/卡通音符绝配。

### L5 河流曲线版（flow）

- **排法**：歌名沿 1~2 条贝塞尔曲线（海浪线/五线谱线）逐字排布，文字沿线微旋转；分类在曲线间分区。曲线来源：theme.json 声明 `curves`（控制点），未声明则自动沿背景主色带边缘提取（二期，首期用声明）。
- **与背景关系**：强耦合，是梦幻海洋/海洋柔光/卡通音符的 signature 布局。
- **参数**：曲线选择、沿线字号、字间距、起止点。
- **依赖**：与 L2 共享"逐字定位 + 旋转"零件，排在 L2 之后。

### L6 极简清单版（minimal）

- **排法**：单列大留白竖排，仅歌名 + 细分隔线；字号分级——本周新学/标记主推的歌放大一号（消费 `added_at`/`learned_at`）；顶部小字刊头。
- **与背景关系**：无耦合，任何主题可渲染。
- **参数**：每页容量、主推歌放大倍率、是否显示序号。
- **实现**：Schema 实现（吃狗粮第二犬）。
- **场景**：歌少时、本周新歌单、高级感封面。

### 二期候选（不在首批承诺内）

- **歌手分区版**：按 `artists` 字段分区（曾轶可/汪苏泷/花粥专区），数据已具备；
- **首字母索引版**：A–Z 索引（消费已有的 `pinyin` 字段）；
- **气泡词云版**：字号 = 点歌/演唱频次（消费 events.jsonl 的 `song_sung`），**直播数据反哺海报的闭环**，与 S5 统计同期做；
- **点歌 TOP 榜版**：本月点歌 TOP20 排行榜海报。

### 布局能力矩阵（前端据此渲染"布局详情"）

| 布局 | 页数 | 密度上限 | 避让需求 | 锚点依赖 | 分类方式 | 技术载体 |
|---|---|---|---|---|---|---|
| grid-wrap | 固定 2 | ★★★★★ | 矩形 | 无 | 字数 | Python（现有） |
| halo | 自动 | ★★★ | 任意形状 | 强 | 字数/歌手 | Python |
| editorial | 自动 | ★★★★ | 矩形 | 弱 | 字数/歌手/首字母 | Schema |
| collage | 自动 | ★★ | 任意形状 | 中 | 字数/标签 | Python |
| flow | 固定 1 | ★★ | 曲线 | 强 | 字数 | Python |
| minimal | 自动 | ★★★ | 无 | 无 | 全部 | Schema |

## 6. 自定义布局：两级方案与声明式 Schema

### 6.1 第一级：模板参数化（人人可用）

每套布局的 ParamSpec 从"实现参数"升级为"语义参数 + 专家参数"两层（§3.3-3）。用户不改结构，只调旋钮：密度、倾角、呼吸带、曲线、配色强度。**零新架构，ParamSpec 机制直接扩展**（`kind` 增加 `"slider"` 与 `"preset"`，预设展开为参数包）。

### 6.2 第二级：声明式布局 Schema（进阶用户）

**布局包 = 一个目录，不进代码库，用户可增删改、可导出分享：**

```
data/layouts/我的杂志风/
├── layout.json        # 布局定义（Schema）
├── thumb.png          # 缩略图（编辑器自动生成）
└── notes.md           # 用户备注（可选）
```

**Schema 草案（v1）**：

```jsonc
{
  "schema": 1,
  "id": "my-editorial",
  "name": "我的杂志风",
  "base": "freeform",               // 固定，走 FreeformLayout 解释器
  "pages": "auto",                  // "auto" | 固定页数
  "supports_avoidance": true,
  "classify": "chars",              // 分类方式: chars | artist | pinyin | tag | flat
  "zones": [
    {
      "id": "title", "type": "text",
      "content": {"text": "{author} 的歌单 · {date}"},   // 模板变量
      "at": {"x": 80, "y": 120},
      "style": {"font_role": "title", "color_role": "label"}
    },
    {
      "id": "main", "type": "grid",
      "content": {"source": "category", "filter": [1, 2, 3, 4]},
      "at": {"x": 58, "y": 300},
      "flow": {"mode": "columns", "cols": 2, "gutter": 48},
      "avoid": {"shapes": "theme-anchors", "gap": 32}     // 绕主题锚点
    },
    {
      "id": "side", "type": "list",
      "content": {"source": "category", "filter": [5, 6, 7]},
      "at": {"x_from": "anchor:月亮.right + 40", "y": 300},
      "flow": {"mode": "vertical", "row_h": 44},
      "style": {"font_scale": 0.9}
    }
  ],
  "params": [ /* ParamSpec，暴露到参数面板 */ ]
}
```

**zone 类型（v1 四个，对应 DrawContext 已有/新增零件）**：

| type | 排法 | 底层零件 |
|---|---|---|
| `grid` | 列网格（全行分布） | `draw_grid`（已有） |
| `list` | 单列/双列竖排 | 直接 text 绘制（已有） |
| `wrap` | 绕形状流式排文 | `flow_segments`（§4.1 新增） |
| `text` | 静态文本（模板变量） | 直接 text 绘制（已有） |

二期 zone 类型：`curve`（沿曲线，依赖 L5 零件）、`cards`（拼贴装箱，依赖 L4 零件）。

**坐标表达式**：`at`/`x_from`/`y_from` 支持 `anchor:<id>.<edge> ± n` 与画布百分比，让布局能"跟着背景元素走"。

**安全与校验**：加载时 JSON Schema 校验 + 渲染时 zone 越界/重叠告警（不阻断，画警告水印到预览右下角）；坏布局包不拖垮 `/api/layouts`（单个失败降级为"损坏"标记）。

### 6.3 可视化布局编辑器（布局工坊内）

**核心交互：在真实背景图上拖 zone。**

1. 画布 = 当前主题第 1 页背景（低清）+ 网格吸附（8px）；
2. 从工具条拖入 zone（文本/网格/列表/绕排），拖出矩形或椭圆区域；
3. 右侧面板绑定内容源：分类（按字数多选）/ 标签 / 歌手 / 点歌 TOP N / 静态文本；
4. 选排法（网格列数、绕排间距、对齐）——只暴露该 zone 类型的合法参数；
5. **锚点拾取**：切换到"锚点模式"，点击背景上的花/月亮框出形状（矩形/椭圆/套索多边形），存入 theme.json 的 anchors——这一步同时服务内置布局（halo/flow）；
6. 实时预览：服务端 `quality=draft` 渲染当前 Schema，500ms 防抖；
7. 保存 = 写 `data/layouts/<名>/layout.json` + 自动生成缩略图；「导出布局包」下载 zip，「导入」上传 zip。

**不做的事**：不做自由绘图、不做图片素材上传（v1 布局只排文字）、不做多人协作。

## 9. 风险、兼容与回退策略

| 风险 | 等级 | 对策 |
|---|---|---|
| 避让魔数迁移破坏金标准 | 高 | 每步迁移后跑 `tests/test_golden.py` 16/16 diff=0；Shape 缺省值逐一对齐现魔数；分小步提交 |
| halo 弧线排文技术不达标 | 中 | 回退方案：flow_segments 双侧分流近似环绕，视觉仍成立 |
| 任意主题 × 任意布局组合"能渲染但丑" | 中 | skin 回退链：theme.skins[layout] → palette 默认 → 内置默认；模板中心缩略图让用户所见即所得，丑的组合自然被跳过 |
| 用户布局 Schema 写坏 | 低 | 加载校验 + 单包失败不拖垮列表 + .trash 软删除 |
| 前端暗色重构回归 | 中 | 重构独立于功能开发单走一支线，截图回归对比 |
| palettes/skins 迁移遗漏主题 | 低 | 迁移脚本 + 迁移后全主题 × grid-wrap 金标准复跑 |
| 范围蔓延 | 高 | 主题在线市场、素材上传、多画布比例扩展均**明确不做**（本期） |

**兼容性总原则**：旧 theme.json、旧 songs.json、旧 events.jsonl 全部零迁移成本可跑；所有新字段可选，缺省值 = 现行为；金标准是每一步的底线。
