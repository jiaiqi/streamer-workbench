# 产品优化方案 v3 · 实施路线图（2026-07-27）

> **配套文档**：`产品优化方案v3-详细版.md`；布局几何与 Schema 专项可参考 `../产品优化方案2-0727/产品优化方案v2-详细版.md`。
> **使用方式**：按依赖门逐 Phase 推进；每项任务对应明确产出、守护与退出条件；阶段未过验收门不得以“后续再补”带病进入下阶段。
> **核心原则**：不以人工或时间成本压缩最终品质；保留已验证承重结构；旧金标准不退让；用户数据可迁移、可备份、可回退。
> **提交原则**：功能、重构、迁移、文档和测试原子提交；每个提交只解决一个可验证问题。

## 全程质量门

每个 Phase 都必须遵守：

1. `core/` 不引入 UI/服务器依赖；
2. 触及旧引擎输出时运行 `PYTHONPATH=. python tests/test_golden.py`，保持 16/16 diff=0；
3. 触及 Python 逻辑时运行单元测试；
4. 触及 React/TypeScript 时运行 `cd ui && npx tsc --noEmit`；
5. 持久化格式变更必须有 schemaVersion、迁移、备份和失败回退；
6. 新 UI 必须同时考虑亮色、暗色、键盘、reduced motion 和 800/1100/1440px；
7. 文档、HANDOFF 和实际状态同步；
8. 阶段结束形成可独立演示、可回退的里程碑提交。

## Phase 0 · 基线冻结、架构决策与去魔数

> **目标**：在不改变旧输出的前提下，为多画布、多布局和用户数据建立稳定地基。
> **依赖**：无。
> **退出条件**：旧输出 16/16 diff=0；核心 Schema 与 ADR 获得冻结版本；所有关键魔数有明确归属。

| # | 任务 | 关键产出 | 守护 |
|---|---|---|---|
| 0.1 | 冻结现状基线 | 记录 Python/Pillow/字体版本、16 张金标准、热/冷渲染基线、API 快照 | 不允许用新引擎自举金标准 |
| 0.2 | 编写 ADR：产品定位与保留/重构边界 | 产品定位、四领域模型、兼容原则、数据目录原则 | 与 v3 方案一致 |
| 0.3 | 冻结 Schema v1 草案 | CanvasSpec、Shape、LayoutDefinition、Palette、Skin、Preset、WorkspaceDocument、LayoutDocument | 每个格式含 schemaVersion |
| 0.4 | CanvasSpec 去固定比例 | baseline、safe area、输出比例、逻辑坐标与像素坐标约定 | 旧画布默认输出不变 |
| 0.5 | 避让魔数收编 | 固定禁文区转为 Shape；grid-wrap 通过默认 Shape 复刻 | 金标准逐像素不变 |
| 0.6 | 字号与柔光魔数收编 | `avoid_font_scale`、`mist_bottom`、动态 page capacity | 缺省值等于现行为 |
| 0.7 | 字体角色与缓存 | title/label/song/note 角色；字体实例缓存 | 旧 font_song/font_label 兼容 |
| 0.8 | 测试工具补强 | Schema fixture、批量组合巡检框架、性能 benchmark 脚本骨架 | CI 可运行 |
| 0.9 | 数据目录决策 | 区分内置只读资源、开发数据、Electron 用户可写数据 | 不写 `_MEIPASS` |

### Phase 0 验收

- [ ] 16/16 金标准 diff=0；
- [ ] `content_offset`、柔光底边、避让字号、page capacity 不再是无归属魔数；
- [ ] 画布、形状、布局、色板、皮肤、预设和编辑文档 Schema 有版本；
- [ ] benchmark 输出热/冷渲染基线；
- [ ] ADR 明确哪些模块禁止重写。

## Phase 1 · Layout / Palette / Skin / Preset 解耦

> **目标**：把“怎么排、什么颜色、什么背景适配、用户保存了什么”拆成四个稳定概念。
> **依赖**：P0 Schema 与数据目录决策。
> **退出条件**：旧主题可无感加载；新模型可表达一个完整模板组合；预设可保存和恢复。

| # | 任务 | 关键产出 | 守护 |
|---|---|---|---|
| 1.1 | Palette 模型与 loader | 颜色角色、字体角色、扩展角色、系统默认 | 缺角色走明确回退链 |
| 1.2 | Skin 模型与 loader | 背景、主体、锚点、避让、安全区、布局默认覆盖 | 旧 theme.json 自动适配 |
| 1.3 | LayoutDefinition 元数据 | 能力、参数、分类方式、数据依赖、分页和缩略图 | Python 插件和 Schema 统一暴露 |
| 1.4 | Preset 仓储 | CRUD、复制、排序、默认、软删除、导入导出 | 原子写 + 备份 |
| 1.5 | 主题迁移工具 | 从 7 个 theme.json 提取 Palette/Skin；支持 dry-run | 原文件保留备份 |
| 1.6 | 组合回退链 | Preset → Skin → Palette → Layout → 系统默认 | 任意组合不崩溃 |
| 1.7 | API v1 | `/layouts`、`/palettes`、`/skins`、`/presets` | 旧端点保持兼容 |
| 1.8 | 真实缩略图缓存 | 按歌曲数据、布局、Skin、参数 hash 失效 | 不用时间戳破坏缓存 |

### Phase 1 验收

- [ ] 7 套旧主题 × grid-wrap 输出不变；
- [ ] 一个 Preset 可完整恢复歌曲查询、布局、Palette、Skin、Canvas 和参数；
- [ ] 删除/损坏单个用户资源不拖垮资源列表；
- [ ] UI 可获取推荐组合和兼容等级；
- [ ] 迁移工具支持 dry-run、备份和失败恢复。

## Phase 2 · 布局运行时：几何、路径、碰撞与分页

> **目标**：建立真正支持自由构图的公共运行时，不让每套布局重复造轮子。
> **依赖**：P0 Shape/Canvas；P1 Layout/Skin。
> **退出条件**：公共零件可以完成矩形避让、主体两侧分流、路径排文、确定性拼贴和自动分页。

| # | 任务 | 关键产出 | 守护 |
|---|---|---|---|
| 2.1 | Shape 几何库 | rect/ellipse/polygon/path 边界、求交、外扩 | 单元测试覆盖边界情况 |
| 2.2 | 可用线段计算 | `available_segments(y, shapes)` | grid-wrap 旧避让可复刻 |
| 2.3 | 文本测量与 fitting | 字形缓存、最小字号、换行、截断禁用策略 | 不静默丢正文 |
| 2.4 | 路径采样与弧线排文 | 等弧长采样、切线、字形旋转、可读方向 | 中英文混排测试 |
| 2.5 | 碰撞运行时 | AABB 快速层 + 精确层；移动/缩放/回落决策 | draft/full 结果语义一致 |
| 2.6 | 分页器 | 容量估算、孤儿标题、跨页续组、背景策略 | 少量/标准/超量 fixture |
| 2.7 | 确定性随机 | 拼贴/散点使用稳定 seed | 同输入输出一致 |
| 2.8 | FreeformLayout v1 | text/grid/list/wrap/shape/image/collection zone | Schema 校验和损坏隔离 |
| 2.9 | draft/full 渲染等级 | draft 近似、full 精确；结果版本化 | full 不降低导出正确性 |

### Phase 2 验收

- [ ] 一个椭圆主体可让正文自动在两侧流动；
- [ ] 一段文字能沿路径保持可读朝向；
- [ ] 拼贴重复渲染完全一致；
- [ ] 自动分页不出现孤儿分类标题；
- [ ] 超量内容不会静默裁切；
- [ ] draft P95 目标 ≤ 100ms，full 热预览 P95 目标 ≤ 250ms；未达标必须记录瓶颈与优化计划。

| 5.2 | 撤销/重做 | past/present/future；滑杆操作合并 | UI 状态不污染历史 |
| 5.3 | 资源栏 | 布局、皮肤、模板卡、筛选和搜索 | 真实缩略图、键盘可用 |

| 5.8 | 组件系统 | card/button/input/segment/dialog/toast/tooltip 等统一 | 状态和焦点一致 |

## Phase 8 · 可视化自定义布局编辑器

> **目标**：用户不写代码即可创建、保存、复用和分享布局。
> **依赖**：P2 FreeformLayout；P5 工作台状态/组件；P7 用户文件能力可在桌面发布前合流。
> **退出条件**：用户能用数据容器创建一个围绕背景主体的布局并导出布局包。

| # | 任务 | 关键产出 | 守护 |
|---|---|---|---|
| 8.1 | 编辑器文档状态 | LayoutDocument、选择、图层、历史、校验 | 与 WorkspaceDocument 边界清楚 |
| 8.2 | 画布交互 | 拖拽、缩放、旋转、多选、吸附、对齐、分布 | 60fps 交互目标 |
| 8.3 | 元素库 | text/image/shape/QR/page/date | 每类有默认样式 |
| 8.4 | 数据容器 | songs/category/artist/queue/stats | 数据为空策略 |
| 8.5 | 自动布局 | grid/flow/columns/wrap/orbit/path/cards | 使用 P2 公共运行时 |
| 8.6 | 属性面板 | frame/layout/style/binding/responsive | ParamSpec v2 复用 |
| 8.7 | 主体与锚点标注 | rect/ellipse/polygon/path；safe/avoid/anchor/fallback | 可视化开关 |
| 8.8 | 分页与响应式预览 | 多画布、多页、断点覆盖 | 不只支持 1080×2400 |
| 8.9 | 实时校验 | 越界、碰撞、溢出、缺数据、缺角色 | 告警可定位元素 |
| 8.10 | 保存/复制/恢复 | 自动保存、恢复草稿、复制内置布局 | 不直接修改内置资源 |
| 8.11 | 导入导出 | zip、缩略图、说明、Schema 安全校验 | 防路径穿越/脚本执行 |
| 8.12 | 编辑器教程 | 首次引导、示例布局、快捷键面板 | 可跳过、可重看 |

### Phase 8 验收

- [ ] 用户可拖入标题和歌曲集合；
- [ ] 可标注一个圆形主体并让歌曲围绕它排布；
- [ ] 可撤销/重做所有文档编辑；
- [ ] 可保存、重开、复制、导入和导出；
- [ ] 损坏包被隔离并给出可理解错误；
- [ ] 超量内容通过分页或明确告警处理；
- [ ] 编辑器不要求用户逐首歌手动摆放。
