## 1. 执行摘要与最终结论

### 1.1 三视角结论

| 视角 | 结论 | 建议动作 |
|---|---|---|
| 产品经理 | 产品已从单一海报工具成长为歌曲资产、学习、直播速查和海报创作共存的本地工作台，但统一叙事与使用闭环尚未形成 | 产品定位升级为“音乐主播内容与直播运营工作台”；按创作、资产、直播、预设、洞察组织功能 |
| 产品 + UI/UX | “晨光纸感”设计方向可保留，但 React 实现与设计系统对齐不足；工作台缺少布局选择、自定义和清晰的创作路径 | 不重新发明视觉语言，系统性重做工作台、组件体系、暗色、动效、响应式和无障碍 |
| 系统架构师 | PIL 引擎、数据层、LayoutPlugin 思想和金标准是可靠资产；固定画布魔数、主题/布局边界、参数协议和前端状态模型不满足下一阶段需求 | 保留引擎主干，重构布局运行时、主题/皮肤模型、画布与参数协议、工作台文档状态 |

### 1.2 明确判断

**不建议整项目推倒重写。**

应保留：

- `core/` 纯函数渲染主干；
- `LayoutPlugin` 插件思想；
- 五角色颜色契约与主题目录扫描思想；
- `core/data/` 的本地数据、原子写、备份和事件流；
- FastAPI 本地服务模式；
- React + Vite 工程载体；
- 16 张独立预言机金标准和 CI 质量门。

必须系统升级：

1. 将布局从“内部插件”提升为用户可感知的一等产品能力；
2. 将主题拆为 Palette 与 Skin，并与 Layout、Preset 建立清晰组合关系；
3. 建立可表达环绕、路径、拼贴、分栏、自由区块的布局运行时；
4. 重做工作台创作流程和状态模型；
5. 完成场景预设、导出历史、统计、正式 Electron 壳和直播置顶小窗；
6. 最终交付可视化自定义布局编辑器。

### 1.3 产品升级的一句话

> 从“给同一版式换七张背景”升级为“主播可以选择、组合、微调和创造真正不同构图，并把歌曲、直播和历史数据转化为视觉作品的桌面创作工作台”。

### 1.4 不接受的伪升级

以下方案不算完成本次目标：

- 仅增加左对齐、居中、右对齐三个变体；
- 仅复制 `grid_wrap.py` 后修改几个坐标；
- 将布局和背景继续打包为不可组合的大型主题；
- 用大量 X/Y 数字输入框冒充自定义布局；
- 只制作静态设计稿，不落地真实组件和交互；
- 通过降低清晰度、取消动画或减少主题组合掩盖性能问题；
- 为追求“架构整洁”破坏现有金标准输出。

## 2. 当前产品画像与目标产品定义

### 2.1 当前能力

当前系统已经具备：

- 7 套视觉主题、2 页背景、2 种画布；
- 单页和批量 PNG 导出；
- 歌曲库增删改、状态切换和搜索；
- 学歌管理、学会时间和曲谱附件；
- `/quick` 直播速查、今晚点歌队列、T 键看谱；
- `events.jsonl` 事件沉淀；
- 参数化渲染、缓存、快捷键和本地设置；
- Electron + PyInstaller 打包链路 spike；
- 金标准、单元测试和 TypeScript 编译检查。

当前事实边界：

- 用户为个人音乐主播；
- 手机负责直播，电脑运行工具；
- 本地优先，不需要账号和云同步才能工作；
- 数据唯一真相仍是本地文件；
- 当前只有 `grid-wrap` 一个真实布局。

### 2.2 目标用户

#### 核心用户：音乐主播

需要在直播前准备歌单、直播中快速查歌/看谱/管理点歌、直播后复盘内容。

#### 次级用户：长期经营个人歌单的音乐内容创作者

需要管理会唱与在学歌曲、按不同场景生成海报、制作社交平台内容。

#### 高阶用户：希望建立个人视觉品牌的创作者

需要可组合主题、自由布局、场景预设、数据驱动海报和自定义模板。

### 2.3 核心任务闭环

```text
维护歌曲资产
   ↓
学习与曲谱管理
   ↓
策划直播场景 / 选择歌曲范围
   ↓
选择布局 + 主题皮肤 + 画布
   ↓
实时微调 / 对比 / 保存预设
   ↓
导出海报并用于直播
   ↓
直播速查 / 点歌 / 演唱 / 看谱
   ↓
事件数据沉淀
   ↓
统计、推荐和下一场预设
```

### 2.4 目标价值主张

1. **快**：日常场景可以选预设后一步出图；
2. **美**：布局、主题和内容互相适配，不是简单换背景；
3. **强**：支持多布局、自由构图、批量导出和自定义；
4. **稳**：本地可用、导出一致、数据不丢、旧作品可重现；
5. **懂直播**：直播前、中、后形成完整工具链；
6. **越用越有价值**：历史数据能反哺歌单、布局和内容策划。

### 2.5 产品边界

本阶段明确不以以下能力为前置：

- 账号体系；
- 强制云同步；
- 在线模板市场；
- 多人协作；
- 在线直播弹幕平台；
- 完整图片编辑器或视频剪辑器。

但架构不得阻断未来通过导入/导出文件分享布局、皮肤和预设。

## 3. 产品经理视角：产品结构与功能闭环

### 3.1 当前产品问题分级

| 级别 | 问题 | 产品影响 |
|---|---|---|
| P0 | 7 主题共用一个布局 | 用户感知为“一套模板换皮”，创作价值不足 |
| P0 | 主题、背景、颜色、布局适配关系不清 | 新增组合会重复资源、难维护、无法自由组合 |
| P0 | 工作台没有布局选择入口 | 后端插件能力没有变成产品能力 |
| P1 | 创作、歌曲管理、学歌、直播之间缺少统一闭环 | 功能多但产品叙事分裂 |
| P1 | 主题管理、预设、历史仍是占位 | 信息架构承诺未兑现 |
| P1 | 事件数据没有统计出口 | 已沉淀数据不能产生用户价值 |
| P1 | 速查没有正式置顶窗口和全局热键 | 直播场景仍有关键摩擦 |
| P2 | 缺少布局/主题对比、撤销重做、一键出图 | 高频创作效率和信心不足 |
| P2 | 没有自定义歌曲集合和数据驱动海报 | 内容策划能力受限 |

### 3.2 目标信息架构

```text
音乐主播工作台
├── 创作
│   ├── 海报工作台
│   ├── 模板与布局
│   ├── 场景预设
│   └── 导出历史
├── 资产
│   ├── 歌曲库
│   ├── 自定义歌单
│   ├── 学歌管理
│   └── 曲谱附件
├── 直播
│   ├── 速查小窗
│   ├── 今晚点歌
│   └── 当场演唱记录
├── 洞察
│   ├── 总览
│   ├── 学习趋势
│   ├── 点歌与演唱排行
│   └── 内容建议
└── 设置
    ├── 输出与画布
    ├── 字体与资源
    ├── 数据与备份
    └── 桌面行为
```

桌面侧栏不必一次展示所有二级项；一级导航建议保持 6 个以内：工作台、歌曲、学歌、直播、统计、设置。模板、预设和历史作为工作台内标签页或抽屉，减少占位导航。

### 3.3 高频用户旅程

#### 日常一键出图

1. 打开应用；
2. 首页恢复上次场景或默认场景；
3. 选择“周末常规直播”预设；
4. 检查预览与歌曲数量；
5. 点击“一键出图”；
6. 自动打开输出目录并记录导出历史。

目标：除确认外，不要求用户重新选择主题和调整参数。

#### 新主题探索

1. 进入模板中心；
2. 按“杂志 / 拼贴 / 环绕 / 直播”筛选布局；
3. 查看真实缩略图；
4. 开启对比模式，选择 2–4 个组合；
5. 应用最佳组合；
6. 微调色板、密度和背景主体避让；
7. 保存为预设。

#### 直播中使用

1. 全局快捷键唤起置顶速查；
2. 输入拼音、歌手或歌名；
3. Enter 加入今晚队列；
4. T 打开曲谱；
5. 标记已唱；
6. 数据双写并在失败时保序补报。

### 3.4 场景预设定义

Preset 必须保存完整可重现状态：

- 歌曲查询与排序；
- 布局；
- 色板；
- 皮肤；
- 画布；
- 页码策略；
- 参数覆盖；
- 元素覆盖；
- 导出设置；
- Schema 版本。

预设应支持：新建、复制、重命名、排序、设为默认、导入、导出、软删除和回滚。

### 3.5 数据驱动产品机会

利用 `events.jsonl` 和歌曲字段，支持：

- 本月点歌 TOP20 海报；
- 很久没唱提醒；
- 新学会歌曲海报；
- 歌手专场自动歌单；
- 曲风/语言专题；
- 直播队列实时版节目单；
- 年度歌单总结；
- 推荐下一场应覆盖的冷门歌曲。

## 4. UI/UX 视角：从功能可用到创作体验优秀

### 4.1 设计方向

保留“晨光纸感 · 清新文艺”：

- 奶油纸底；
- 海洋青主色；
- 暖珊瑚强调；
- 衬线标题与圆润正文；
- 轻阴影、纸感和柔和浮层。

暗色作为“演出后台”模式存在，但必须由同一语义令牌系统驱动，而不是组件内大量 `dark ? ... : ...`。

### 4.2 UI 重构边界

不需要重新发明：

- 品牌气质；
- 基础色彩；
- 圆角与纸感；
- 既有设计稿中的组件语言。

需要系统重做：

- 工作台布局；
- 组件状态与令牌；
- 暗色模式；
- 选择布局和皮肤的交互；
- 参数检查器；
- 预览和对比；
- 响应式面板；
- 动效和无障碍。

### 4.3 目标桌面布局

```text
┌──────────────────────────────────────────────────────────────────┐
│ 文件  编辑  视图  布局  主题  帮助       撤销 重做   当前预设 ▾ │
├────────────┬───────────────────────────────┬─────────────────────┤
│ 创作资源   │                               │ 属性检查器          │
│            │                               │                     │
│ 布局       │                               │ ▾ 内容              │
│ [环绕]     │          实时画布             │ ▾ 布局              │
│ [杂志]     │        预览 / 对比 / 编辑     │ ▾ 视觉              │
│ [拼贴]     │                               │ ▾ 背景与锚点        │
│            │                               │ ▾ 导出              │
│ 主题皮肤   │                               │                     │
│ [海洋]     │                               │                     │
│ [奶油]     │                               │                     │
├────────────┴───────────────────────────────┴─────────────────────┤
│ 周末常规直播 · 178 首 · 2 页 · 33ms       保存预设  一键出图  ▾ │
└──────────────────────────────────────────────────────────────────┘
```

### 4.4 创作模式

#### 预览模式

用于日常出图。隐藏编辑手柄，保持界面安静。

#### 对比模式

支持 2 或 4 宫格比较：

- 不同布局，同一主题；
- 同一布局，不同主题；
- 不同参数版本；
- 自动同步缩放和页码。

#### 编辑模式

显示安全区、避让区、锚点、容器边界、吸附线和图层选择。仅在用户主动进入时增加复杂度。

### 4.5 参数检查器

按语义分组，而不是直接暴露实现变量：

| 分组 | 普通用户控件 | 专家控件 |
|---|---|---|
| 内容 | 歌曲范围、分类方式、排序、主推歌曲 | 过滤表达式、缺失字段策略 |
| 布局 | 紧凑/标准/宽松、列数、环绕方向 | margin、row_h、轨道间距、溢出策略 |
| 视觉 | 色板、字体、字号、强调强度 | 颜色角色覆盖、字距、行高、阴影 |
| 背景 | 背景页、主体避让、柔光 | anchor/avoid zone、mist 参数 |
| 导出 | 画布、范围、命名、格式 | DPI、压缩、透明背景、元数据 |

所有控件都要显示：标签、单位、范围、默认值、重置按钮和影响说明。

### 4.6 预览体验

- 新旧图叠放 crossfade，不出现空白闪烁；
- 滑杆拖动走 draft 预览，停手后补 full；
- 请求使用序列号或 AbortController，只接收最后一次结果；
- 内容寻址缓存，相同输入直接复用；
- 首次渲染、后台渲染、失败重试使用不同状态反馈；
- 错误提示包含可执行动作，不只显示“失败”。

### 4.7 动效规范

| 类型 | 时长 | 曲线 | 说明 |
|---|---:|---|---|
| Hover/按压 | 120–180ms | ease-out | 不改变布局尺寸 |
| 折叠/抽屉 | 180–240ms | standard | 内容高度平滑变化 |
| 页面切换 | 220–320ms | ease-out | 淡入 + 8px 上浮 |
| 主题切换 | 220–320ms | crossfade | 背景与色板协同过渡 |
| 布局切换 | 300–450ms | spring-soft | 内容重新构图，但避免眩晕 |
| 对话框 | 180–260ms | ease-out | 遮罩和面板分层进入 |

必须尊重 `prefers-reduced-motion`，禁用位移和旋转，只保留必要的透明度反馈。

### 4.8 响应式窗口策略

| 窗口宽度 | 模式 |
|---|---|
| ≥ 1440px | 完整三栏，资源和属性同时可见 |
| 1100–1439px | 资源栏窄化，属性栏可折叠 |
| 800–1099px | 单侧面板常驻，另一侧抽屉 |
| < 800px | 紧凑查看模式，不承诺完整编辑；优先展示画布与导出 |

桌面应用还应记忆窗口大小、面板宽度和折叠状态。

### 4.9 无障碍基线

- WCAG AA 正文对比度；
- 所有图标按钮有 `aria-label`；
- 布局卡和皮肤卡可用键盘选择；
- 焦点环不能被移除；
- 对话框有焦点锁定与返回焦点；
- 表单 label 与 input 显式关联；
- 错误不只依赖颜色；
- 图片 alt 包含主题、布局和页码；
- 快捷键可查看、可修改、冲突时提示；
- 屏幕阅读器可获知渲染、导出和保存状态。

## 5. 系统架构师视角：保留承重结构，重构扩展层

### 5.1 应保留的承重结构

| 资产 | 理由 |
|---|---|
| PIL 渲染引擎 | 已经产生稳定目标输出，且有独立金标准保护 |
| `core/` 零 UI 依赖 | 保证 Web、Electron 和未来其他壳层可复用 |
| LayoutPlugin 抽象 | 已具备插件方向，只需扩充能力 |
| 主题目录扫描 | 允许资源驱动扩展，可演进为 Palette/Skin |
| 本地 JSON/JSONL + 原子写 + 备份 | 符合个人桌面产品规模，简单可靠 |
| FastAPI 本地服务 | 能隔离 Python 渲染和前端，便于 Electron child process |
| React + Vite | 足以实现高质量工作台和编辑器，无需换栈 |
| 金标准与 CI | 是所有重构的安全边界 |

### 5.2 必须重构的部分

1. 固定画布魔数和避让魔数；
2. `Theme` 同时承担颜色、背景和布局适配；
3. `ParamSpec` 不足以描述高级控件与约束；
4. `server/main.py` 全局状态和单文件路由；
5. 前端工作台状态分散，缺少可撤销文档模型；
6. 渲染请求缺少取消、内容 hash 和分级预览；
7. 布局页数、容量和背景页数耦合；
8. 自定义布局没有稳定 Schema 和版本迁移。

| 现状 | 目标 |

| content offset 以 1920 为固定基准 | CanvasSpec 明确 baseline 或全部采用归一化坐标 |

## 6. 核心领域模型：Layout、Palette、Skin、Preset

### 6.1 Layout

负责内容如何在空间中组织：

- 区域划分；
- 分栏、网格、环绕、路径、拼贴；
- 自动分页；
- 文字适配；
- 碰撞与避让；
- 参数定义；
- 支持的歌曲分类方式。

Layout 不应硬编码某套主题颜色和背景图片。

### 6.2 Palette

负责视觉角色：

- text；
- label；
- pill；
- line；
- mist；
- surface；
- border；
- accent；
- decoration；
- font roles。

Palette 不应声明具体文本坐标。

### 6.3 Skin

负责某视觉方向对某布局的适配：

- 背景图；
- 主体元素；
- anchor zones；
- avoid zones；
- safe areas；
- 柔光与水印参数；
- Layout 扩展颜色角色映射；
- 某些布局参数默认覆盖。

Skin 是 Layout 与 Palette/Background 之间的适配层。

### 6.4 Preset

负责用户最终可复现的场景：

```text
歌曲查询 + Layout + Palette + Skin + Canvas
+ 参数覆盖 + 元素覆盖 + 导出设置
```

### 6.5 组合与回退链

```text
Preset 显式覆盖
  ↓
Skin 对 Layout 的覆盖
  ↓
Palette 角色值
  ↓
Layout 内置语义默认
  ↓
系统安全默认
```

任意组合必须满足：

- 能渲染；
- 有明确降级；
- UI 提前标识推荐、兼容或实验组合；
- 不允许因为缺少某个扩展颜色角色导致整个主题列表失败。

### 6.6 推荐文件结构

```text
palettes/
  海洋柔光/palette.json
  奶油花园/palette.json

skins/
  海洋柔光/
    grid-wrap/skin.json
    subject-orbit/skin.json

core/layouts/
  grid_wrap.py
  magazine_flow.py
  polaroid_collage.py
  notebook_lines.py
  live_set.py
  artist_rail.py
  subject_orbit.py
  freeform.py

data/
  presets/
  layouts/
  themes/
```

内置只读资源与用户可写资源必须分开，正式打包后用户数据不能写入 `_MEIPASS`。

## 7. 多布局产品规划

> 每套布局交付物必须包括：布局实现或 Schema、参数描述、布局缩略图、适用说明、响应规则、溢出策略、7 主题兼容检查、独立金标准与无数据/少数据/超量数据测试。

### 7.1 L1 全行网格环绕 `grid-wrap`

**定位**：信息密度最高的默认保底布局。

**构图**：按歌名字数分区，标签胶囊 + 多列网格；遇背景禁文区收缩可用宽度。

**适用**：完整歌单、歌曲多、直播前快速出图。

**参数**：边距、歌名字号、行高、分区间距、列间距、标签尺寸。

**响应**：按内容宽度动态列数；按画布高度动态容量；超量自动分页。

**降级**：任何主题和画布都必须可渲染。

**验收**：现有 16 张输出 diff=0；新画布不依赖 1920 魔数。

### 7.2 L2 双栏杂志 `magazine-flow`

**定位**：高密度、编辑感、适合社交发布。

**构图**：刊头、期号、日期、双栏或三栏正文；重点分类可跨栏；长歌名单独通栏。

**适用**：200 首以上歌单、复古/玻璃主题、年度合集。

**数据**：主播名、日期、可选主推歌、歌曲分类。

**参数**：栏数、栏距、刊头文本、密度、是否显示期号、主推区比例。

**响应**：宽画布 2–3 栏，窄画布 1–2 栏；栏目保持阅读顺序。

**溢出**：按栏目平衡分页，禁止最后一页只剩单独标签。

**验收**：长短歌名混排不碰撞；阅读顺序可预测；分页无孤儿标题。

### 7.3 L3 便签拼贴 `polaroid-collage`

**定位**：手账、情绪和个性表达。

**构图**：每个分类是一张撕纸/便签卡片，轻微旋转、错落、叠放；纸胶带与注释作为装饰。

**适用**：奶油花园、奶油玻璃、卡通音符；中小歌单和精选歌单。

**数据**：分类、可选备注、日期、主推标记。

**参数**：旋转幅度、卡片间距、投影、胶带显示、卡片底色、随机种子。

**响应**：卡片按内容自适应；窄画布降低旋转；碰撞后重新装箱。

**溢出**：新页继续装箱；不允许缩到不可读字号。

**确定性**：随机必须使用稳定种子，同一预设重复导出一致。

**验收**：卡片不遮挡正文；布局每次一致；少量歌曲时仍有完整构图。

### 7.4 L4 横线手账 `notebook-lines`

**定位**：学习记录和低密度叙事。

**构图**：歌名吸附在横线或五线谱基线上，分类标签像索引贴；可显示日期和手写批注。

**适用**：本周新学、练习总结、回忆歌单。

**数据**：`learned_at`、练习次数、备注、歌曲状态。

**参数**：基线间距、左边距、索引贴尺寸、日期格式、是否显示练习信息。

**响应**：基线按画布高度重新分配；超长歌名缩放或占两行。

**溢出**：分页保持横线节奏连续；标题和至少一首歌曲同页。

**验收**：文字基线准确；中英文混排不漂移；空数据有友好空状态。

### 7.5 L5 直播节目单 `live-set`

**定位**：直接服务直播现场的业务布局。

**构图**：上部为直播信息、今晚主推、当前点歌或队列摘要；下部为完整可点歌曲。

**适用**：常规直播、点歌专场、主题专场。

**数据**：歌单、今晚队列、点歌热度、直播标题、时间、提示文案。

**参数**：上下区比例、主推数量、是否显示队列、CTA、二维码、热门标记。

**响应**：无队列时自动改为主推区；数据过多时下部自动分页；上部保持固定视觉层级。

**降级**：离线或事件文件为空时仍可生成静态节目单。

**验收**：现场信息 2 秒内可扫读；二维码和关键 CTA 不被正文挤压。

### 7.6 L6 歌手轨道 `artist-rail`

**定位**：以歌手为主要检索入口。

**构图**：每位歌手是一条横向、纵向或弧形轨道；轨道内部排列歌曲，大歌手获得更大区域。

**适用**：歌手专场、歌手覆盖丰富的曲库。

**数据**：`artists`；缺失歌手归入“其他”。

**参数**：排序、最小成组数量、每轨容量、轨道方向、是否显示数量。

**响应**：宽屏横轨，窄屏纵轨；小组自动合并。

**溢出**：同一歌手尽量不跨页；跨页时重复歌手标题并标注“续”。

**验收**：缺失 artists 不报错；同歌多歌手有明确归属策略。

### 7.7 L7 背景主体环绕 `subject-orbit`

**定位**：旗舰自由构图，让文字围绕背景中的花、月亮、唱片、气泡、人物或插画组织。

**构图模式**：

- orbit：同心轨道；
- contour：沿轮廓外缘；
- split-flow：主体两侧分流；
- wreath：沿花环弧段；
- satellite：多个气泡/节点周围分组。

**适用**：轻复古唱片、奶油花园、梦幻海洋、青提气泡、卡通音符。

**数据**：主题 Skin 的 subject/anchor 描述，歌曲分类。

**参数**：起始角、方向、轨道间距、主体呼吸带、弧线文字方式、回落区域。

**响应**：按主体归一化坐标缩放；可用周长不足时进入下一轨；仍不足则流入侧翼或下一页。

**降级**：无主体标注时使用几何中心虚拟主体；弧线排文不可用时降为两侧分流。

**验收**：文字不覆盖主体；弧线文字保持可读方向；多页结果视觉连续。

### 7.8 L8 编辑封面 `editorial-cover`（增强候选）

**定位**：强调少量主推歌曲和内容叙事。

**构图**：上 1/3 为 TOP5 或本月主推的大字号封面，下 2/3 为完整清单。

**数据**：手动主推或事件统计排行。

**适用**：月度总结、新歌推荐、专场宣传。

该布局可与 `magazine-flow` 共用栏排零件，但产品上是独立模板，不应只做一个隐藏开关。

### 7.9 布局能力矩阵

| 布局 | 密度 | 主体依赖 | 自动分页 | 数据依赖 | 技术载体 |
|---|---:|---:|---:|---|---|
| grid-wrap | ★★★★★ | 无 | 是 | 歌曲 | Python |
| magazine-flow | ★★★★ | 弱 | 是 | 歌曲/主推 | Schema + Python 零件 |
| polaroid-collage | ★★ | 中 | 是 | 分类/备注 | Python |
| notebook-lines | ★★ | 无 | 是 | 学习数据可选 | Schema |
| live-set | ★★★ | 弱 | 是 | 队列/事件可选 | Python |
| artist-rail | ★★★ | 无 | 是 | artists | Python |
| subject-orbit | ★★–★★★ | 强 | 是 | anchor | Python 几何运行时 |
| editorial-cover | ★★★ | 弱 | 是 | 主推/排行 | Schema |

## 8. 背景主体环绕与自由构图系统

### 8.1 核心理念

背景不再只是被动底图，而是拥有语义的构图参与者。Skin 应声明：

- 主体是什么；
- 主体在哪里；
- 哪些区域不可覆盖；
- 哪些位置适合放标题、标签或装饰；
- 哪些曲线可以承载文字；
- 当画布改变时如何缩放。

### 8.2 形状模型

```ts
type Shape =
  | { kind: "rect"; x: number; y: number; width: number; height: number }
  | { kind: "ellipse"; cx: number; cy: number; rx: number; ry: number }
  | { kind: "polygon"; points: Point[] }
  | { kind: "path"; points: Point[]; closed: boolean }
```

坐标默认使用 0–1 归一化值，必要时允许像素值并带 `coordinateSpace`。

### 8.3 区域语义

| 类型 | 含义 |
|---|---|
| safeArea | 内容优先区域 |
| avoidZone | 正文禁止或尽量避免覆盖 |
| anchorZone | 标题、标签、装饰可吸附位置 |
| subject | 背景视觉主体 |
| flowPath | 文字或元素可沿其排列的路径 |
| fallbackZone | 主构图装不下时的回落区域 |

### 8.4 行流式避让

布局运行时对每条文字基线计算可用线段：

```python
segments = available_segments(y, canvas_bounds, avoid_shapes)
```

矩形、椭圆、多边形和路径统一转为水平线交点，再从画布宽度中减去占用区。这样可以支持：

- 主体左侧和右侧同时排文；
- 花环中心留白；
- 人物轮廓两侧分流；
- 不规则插画边缘环绕。

### 8.5 路径排文

路径排文流程：

1. 将贝塞尔或多段线采样为等弧长点；
2. 测量每个字形宽度；
3. 沿路径累计放置；
4. 使用局部切线确定旋转角；
5. 保持字形朝向可读，超过阈值自动翻转；
6. 计算包围盒并参与碰撞检测；
7. 容量不足时进入下一轨或 fallback zone。

### 8.6 碰撞检测

分两层：

- 快速层：AABB 包围盒，实时预览使用；
- 精确层：旋转矩形或多边形，最终渲染使用。

碰撞解决优先级：

```text
移动到同一区域下一个槽位
→ 扩大轨道半径/降低旋转
→ 使用允许范围内的字号缩放
→ 进入 fallback zone
→ 自动分页
→ 报告无法排版
```

禁止静默裁切正文。

### 8.7 Skin 示例

```json
{
  "schemaVersion": 1,
  "id": "retro-vinyl.subject-orbit",
  "layout": "subject-orbit",
  "palette": "retro-vinyl",
  "backgrounds": {"1": "bg1.png"},
  "subjects": [
    {
      "id": "vinyl",
      "kind": "ellipse",
      "center": [0.5, 0.37],
      "radius": [0.23, 0.23],
      "margin": 0.035
    }
  ],
  "fallbackZones": [
    {"id": "bottom-list", "kind": "rect", "frame": [0.08, 0.68, 0.84, 0.25]}
  ]
}
```

## 9. 自定义布局编辑器

### 9.1 产品原则

自定义布局不是让用户逐首歌拖 178 个文本框，而是让用户放置“数据容器”，再指定自动布局规则。

用户操作对象分两类：

- 原子元素：标题、图片、形状、线条、二维码；
- 数据容器：歌曲集合、歌手组、点歌榜、队列、学习记录。

### 9.2 编辑器结构

```text
左侧：元素与数据源
中间：画布、图层、吸附、背景
右侧：位置、布局、样式、绑定、响应式
顶部：撤销/重做、预览、画布、缩放、保存
底部：校验告警、页码、渲染状态
```

### 9.3 元素库

- 静态文本；
- 动态标题；
- 歌曲集合；
- 分类标签；
- 歌手组；
- 点歌 TOP；
- 今晚队列；
- 图片；
- 二维码；
- 矩形、圆形、线条；
- 装饰图层；
- 页码和日期。

### 9.4 数据绑定

歌曲容器可绑定：

- 全部已会；
- 最近学会；
- 指定歌手；
- 指定标签；
- 指定状态；
- 手动歌单；
- 点歌 TOP N；
- 很久没唱；
- 今晚队列。

查询必须可预览结果数量，并在数据为空时提供占位或隐藏策略。

### 9.5 自动布局模式

- grid；
- flow；
- columns；
- wrap；
- orbit；
- path；
- scatter；
- cards；
- manual（仅少量元素）。

### 9.6 编辑能力

- 拖拽、缩放、旋转；
- 多选；
- 对齐、分布；
- 8px 网格与智能吸附；
- 图层排序；
- 锁定与隐藏；
- 复制、粘贴、组合；
- 撤销、重做；
- 安全区、锚点和避让区可视化；
- 背景主体矩形、椭圆、多边形标注；
- 越界、遮挡、溢出实时告警。

### 9.7 响应式与分页

每个容器可声明：

- frame 使用百分比还是像素；
- 最小/最大尺寸；
- 画布断点覆盖；
- 内容不足时是否收缩；
- 内容过多时缩放、续页或截断；
- 分页时标题是否重复；
- 是否允许跨页拆组。

### 9.8 LayoutDocument Schema 草案

```json
{
  "schemaVersion": 1,
```

### 9.9 保存、分享与安全

- 用户布局保存到可写用户目录；

- 导出为 zip，包含 `layout.json`、缩略图和可选说明；

## 10. 目标工作台与关键交互流程

### 10.1 模板卡与独立选择并存

模板卡是推荐的快捷入口，代表 Layout + Palette + Skin 的优质组合；高级用户仍可以分别切换布局、色板和皮肤。

模板卡必须显示：

- 真实渲染缩略图；
- 布局名；
- 主题名；
- 推荐场景；
- 密度等级；
- 页数估计；
- 是否依赖歌手/事件/锚点数据。

### 10.2 一键出图

一键出图不是固定导出当前页，而是执行 Preset：

1. 验证资源；
2. 计算页数；
3. 渲染；
4. 按命名规则保存；
5. 写 `poster_exported`；
6. 保存历史快照；
7. 成功后提供打开目录、复制路径和再次导出。

### 10.3 撤销与重做

进入历史的操作：

- 切布局/皮肤/画布；
- 改参数；
- 拖动元素；
- 改数据绑定；
- 删除/新增布局元素。

不进入历史：

- 缩放；
- 面板开关；
- 当前选中元素；
- 预览页码。

连续滑杆输入应合并为一个历史记录。

### 10.4 保存状态提示

工作台应明确显示：

- 已保存；
- 有未保存更改；
- 正在保存；
- 保存失败；
- 当前预设已被修改。

关闭窗口或切换预设时，不允许无提示丢失修改。

### 10.5 导出历史

每条历史记录包含：

- 时间；
- 文件路径；
- 预设快照；
- 主题/布局/画布；
- 页数；
- 文件状态；
- 重新生成入口。

文件被移动或删除时显示“文件缺失”，但仍可用快照重新生成。

## 11. 主题、画布、参数、文件与 API 方案

### 11.1 CanvasSpec

CanvasSpec 应支持：

- 任意 width/height；
- logical scale / output scale；
- safe area；
- avoid zones；
- baseline；
- page margin；
- export DPI；
- 预设名称。

首批画布：

- 抖音全屏 1080×2400；
- 标准竖版 1080×1920；
- 小红书 3:4；
- 方形 1:1；
- 横版 16:9；
- 自定义尺寸。

### 11.2 ParamSpec v2

```ts
type ParamKind =
  | "number"
  | "slider"
  | "boolean"
  | "choice"
  | "color"
  | "font"
  | "position"
  | "rect"
  | "spacing"
  | "text"
  | "group"
```

字段至少包括：key、label、description、kind、default、min、max、step、unit、choices、group、advanced、visibleWhen、resetBehavior。

### 11.3 推荐 API

| API | 目的 |
|---|---|
| `GET /api/layouts` | 内置和用户布局、能力、依赖、缩略图 |
| `GET /api/layouts/{id}` | 布局完整定义 |
| `GET /api/layouts/{id}/params` | ParamSpec v2 |
| `POST/PUT/DELETE /api/layouts/custom*` | 用户布局 CRUD |
| `POST /api/layouts/import` | 导入布局包 |
| `GET /api/layouts/{id}/export` | 导出布局包 |
| `GET /api/palettes` | 色板列表 |
| `GET /api/skins?layout=` | 适用于布局的皮肤 |
| `GET/PUT /api/skins/{id}/anchors` | 主体和锚点编辑 |
| `GET/POST/PUT/DELETE /api/presets*` | 场景预设 |
| `GET /api/templates` | 推荐组合卡 |
| `GET /api/render` | 增加 quality、内容 hash、layout/palette/skin/preset |
| `POST /api/render/document` | 渲染完整 WorkspaceDocument |
| `GET /api/export/history` | 导出历史 |
| `POST /api/export/replay/{id}` | 按历史快照重新生成 |
| `GET /api/stats/*` | 总览、学习、直播统计 |

### 11.4 版本与迁移

所有持久格式必须带 `schemaVersion`。迁移规则：

- 只向前迁移，不静默降级；
- 迁移前备份；
- 迁移失败保留原文件；
- 加载旧 theme.json 时适配为临时 Palette + Skin；
- 旧 API 在一个完整发布周期内保留；
- Preset 保存布局、皮肤和 Schema 版本，确保历史可重现。

## 13. 兼容迁移、测试、性能与回退

### 13.1 迁移顺序

1. 冻结现有输出和测试基线；
2. 去魔数，但旧默认输出不变；
3. 引入新模型的兼容适配器；
4. 迁移内置主题；
5. 新布局运行时；
6. 前端正式接入新模型；
7. 用户数据迁移；
8. 删除过渡接口必须单独决策。

### 13.2 测试金字塔

#### 单元测试

- Shape 求交；
- 路径采样；
- 文本测量；
- 碰撞；
- 分页；
- Schema 校验；
- 回退链；
- 预设迁移；
- 查询与统计口径。

#### 金标准

- 现有 16 张永远保留；
- 每套布局选择代表性主题、画布和数据量建立基准；
- 不建议机械地将全部组合都设为逐像素金标准，全部组合应做批量渲染巡检；
- 固定字体、Python 和 Pillow 版本。

#### API 测试

- 正常、缺字段、损坏包、并发导出；
- 路径穿越和非法 zip；
- 旧 API 兼容。

#### UI 测试

- 工作台主流程；
- 键盘导航；
- 撤销重做；
- 保存失败；
- 对比模式；
- 暗色和 reduced motion；
- 800/1100/1440 宽度。

#### 桌面测试

- 首次启动；
- 后端崩溃；
- 用户目录权限；
- 置顶窗口；
- 多显示器；
- 打包后导出和重启恢复。

### 13.3 性能预算

| 行为 | 目标 |
|---|---:|
| 热缓存 draft 预览 | P95 ≤ 100ms |
| 热缓存 full 预览 | P95 ≤ 250ms |
| 参数反馈启动 | ≤ 50ms |
| UI 动画 | 60fps；低端设备不低于 45fps |
| 工作台首次可交互 | ≤ 2s（本地桌面） |
| 批量导出 | 有真实进度、可取消、不阻塞 UI |
| 速查搜索 | 178 首规模下感知即时 |

如复杂环绕无法达到 full 预算，可让 draft 使用近似碰撞，但最终导出不得牺牲正确性。

### 13.4 可观测性

- Python 使用结构化 logging，替代 print；
- Electron 收集后端启动和崩溃日志；
- 导出任务记录阶段、耗时和失败原因；
- UI 错误显示 correlation id；
- 本地日志有大小和数量上限；
- 提供“一键打开日志目录”。

### 13.5 回退策略

- 新布局可逐个禁用；
- Palette/Skin loader 支持旧 theme.json；
- Preset 迁移失败时只读打开；
- 自定义布局删除采用软删除；
- Electron 更新失败不破坏用户数据；
- 每个架构阶段单独提交并通过金标准；
- 禁止使用 force push 或重写已发布数据格式。

## 15. 风险登记与最终决策清单

### 15.1 风险登记

| 风险 | 等级 | 应对 |
|---|---|---|
| 去魔数破坏旧输出 | 高 | 小步迁移；每步跑 16 张金标准；旧默认值逐项复刻 |
| Layout/Palette/Skin 过度抽象 | 高 | 先由 3 套真实布局验证模型，再冻结 v1 Schema |
| 主题 × 布局组合能渲染但不美观 | 中 | Skin 推荐组合、真实缩略图、兼容等级与回退链 |
| 环绕/路径文字性能不足 | 中 | draft 近似、full 精确；缓存字形和几何；设置回落区域 |
| 自定义编辑器范围失控 | 高 | 以数据容器为核心，不做完整图片编辑器；先交付 v1 元素集 |
| 前端重构与功能开发互相冲突 | 中 | 先定 WorkspaceDocument 和设计令牌，再逐视图迁移 |
| Electron 用户路径错误导致数据丢失 | 高 | 所有可写数据外置；升级前备份；打包专项测试 |
| 金标准数量膨胀 | 中 | 代表性金标准 + 全组合巡检，不机械锁定所有像素组合 |
| 文档与实现再次漂移 | 中 | 路线图任务关联规格章节；每阶段更新 HANDOFF 和 ADR |
| 数据字段不完整影响布局 | 中 | 明确缺失值策略；UI 显示数据覆盖率；布局自动降级 |

### 15.2 最终决策

- [x] 不整项目重写；
- [x] 保留 PIL 引擎、数据层、FastAPI、React 和金标准；
- [x] 产品定位升级为音乐主播内容与直播运营工作台；
- [x] Layout、Palette、Skin、Preset 成为四个独立领域概念；
- [x] 首批目标不少于 7 套真实不同布局；
- [x] 背景主体环绕是旗舰能力，不以简单对齐变体替代；
- [x] 自定义布局最终采用可视化编辑器；
- [x] 工作台需要系统性重做，但沿用现有视觉方向；
- [x] 正式 Electron 壳、统计和直播置顶小窗属于产品闭环，不是可有可无的附属项；
- [x] 质量、兼容、可访问性和性能作为发布门槛，而不是收尾装饰。
