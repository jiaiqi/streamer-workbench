# 主播工作台 · 整体项目分析（2026-08-01）

> **目的**：在 R4.0 Phase 1 收口后，对项目做一次 4 维度盘点，识别下一步最值得投入的减债和优化点。
> **基准**：commit `6dbdc63`（R4.0 Phase 1 收口）；R0–R5 + R2.5 + R3.5 全部完成；675+ 测试 0 失败。
> **结论先说**：
> 1. **不是"再做新功能"，而是"把已经做出来的东西串起来"**——4 套 layout、6 个视图都在，但用户从"日常出图"路径接触不到 live-set / learning-report。
> 2. **App.tsx 686 行 god component 拆解**是 R4.0 → R4 之间缺失的过渡，已经无法再往里加东西。
> 3. **海报导出走真保存**是 Electron / 浏览器体验一致性的最后一步。
> 4. **暗色 hardcode 散落**是技术债的具体表现，影响后续任何视觉调整。
> 5. **R3.6 数据→创作**还差 Top 歌曲 / 时间线 → 创建海报的快捷路径。

## 2. 4 维度分析

### 2.1 功能维度

#### 痛点 1：4 套 layout 在 UI 上分两层

`/api/layouts` 只返回 `grid-wrap` 和 `magazine-flow`（2 套）；`live-set` 和 `learning-report` 走另外的端点和触发位置（LiveView 会话详情、StatsView 头按钮）。

| 入口 | 触发位置 | 路径 | 用户认知 |
|---|---|---|---|
| grid-wrap | 工作台 + LayoutPicker | `/api/render` | "选歌→选主题→出图" |
| magazine-flow | 工作台 + LayoutPicker | `/api/render/document` | 同上 |
| live-set | LiveView 会话详情「复盘海报」按钮 | `POST /api/live-sessions/{id}/poster` | "看一场直播→出图" |
| learning-report | StatsView 头「导出学习报告」按钮 | `POST /api/learning-report/poster` | "看统计→出图" |

**问题**：
- 用户在工作台切 layout 时根本看不到 live-set / learning-report；
- 切到 LiveView 才能导复盘海报——路径违反"海报工作台"的心智模型；
- 4 套 layout 的"对应数据源"在 UI 上没有可见的对应关系。

**建议方案（R4.0.2 升级版）**：
- 工作台左栏"当前作品"区上方新增"专用海报"分类，列出：
  - **复盘海报**（live-set）：最近 3 场直播 + "全部直播"链接
  - **学歌报告**（learning-report）：最近 3 次时间窗口 + "自定义"入口
- 点"复盘海报"→ 弹"选一场直播"浮层（复用 LiveView 会话选择）
- 点"学歌报告"→ 弹"选时间窗口"（7d / 30d / 90d / 自定义天数）
- 这正好对应"日常出图 / 直播现场 / 学歌循环"3 个用户闭环

#### 痛点 2：创作入口分散无统一视图

3 个海报创作入口（工作台 / 直播视图复盘 / 统计视图学习报告），但没有"作品中心"：
- 看不到历史海报大图
- 没有"最近 10 次导出"列表
- 没有"按时间分组"的海报浏览

**建议**：工作台右栏"版式与输出"区增加"我的作品"折叠区，列出最近 5 张已保存海报（含缩略图 + 名称 + 最后保存时间 + 一键加载到工作台）。

#### 痛点 3：统计结果 → 创作的"快捷路径"只覆盖 learning-report

R3.6 退出门"至少一个统计结果可直接创建并导出海报"——只完成了 learning-report，Top 歌曲 / 时间线还没有"基于此创建 Preset"或"创建海报"按钮。

**建议**：StatsView 各 tab 增加"据此创建海报"按钮，落到工作台：
- Top 歌曲 tab：选 Top 20 → 跳工作台并预填 SongSourcePicker.selected_song_ids
- 时间线 tab：选时间段 → 同上
- 难度分布 / Key 分布：暂不接（数据维度不对应"出图"）

#### 痛点 4：live-set / learning-report 不可"自动保存"

它们是事件流快照，不是文档——所以无 PosterRequest，无自动保存。但用户每次想"再生成一次"得重新找 LiveSession 路径。

**建议**：在 LiveView / StatsView 导出按钮旁加"导出历史"，显示最近 5 次生成的同类型海报缩略图（读 `data/posters_export_log.jsonl` 类似——若不存在则新建）。

#### 痛点 5：撤销/重做只在 PosterRequest 范围

撤销/重做栈只针对工作台的海报文档；LibraryView 歌曲编辑、LearningView 标记学会、LiveView 记录演唱——这些写操作都没撤销能力。

**优先级**：低。用户能承受"误操作后改回去"——但 LibraryView 的删除歌曲必须有二次确认（**当前已有**，但 export 失败回退没提示）。

#### 痛点 6：导出流程在 Electron 下是"新开 webContents 窗口"

`openLivePoster` / `openLearningReportPoster` 都用 `window.open(blob URL, "_blank")`：
- 浏览器里：弹下载
- Electron 里：开新 BrowserWindow 展示 PNG——不是原生保存对话框

**建议（R4.0.3 实施）**：
- 检测 `isElectron()` → IPC 调 `dialog.showSaveDialog` → 后端 `FileResponse` 写盘
- 浏览器：保留 `<a download>` 路径
- 兼容：保留 `window.open(blob URL)` 作为最终 fallback

### 2.2 交互维度

#### 痛点 1：3 处 spinner 风格不统一

| 位置 | 样式 | 大小 |
|---|---|---|
| App.tsx 主预览 | `w-6 h-6 border-2 border-primary border-t-transparent rounded-full animate-spin` | 24px |
| LiveView / StatsView 按钮 | `w-3 h-3 border-2 border-current border-t-transparent rounded-full animate-spin` | 12px |
| LibraryView / LearningView | `<span className="spinner" />` (Tailwind 工具类) | 未确认 |

**建议**：抽 `<Spinner size="sm|md" tone="primary|current" />` 组件统一。

#### 痛点 2：快捷键不跨视图

工作台有 `Cmd+E` 导出、`Cmd+R` 刷新、`Cmd+1~7` 切主题、`Cmd+Z` 撤销、`Cmd+,` 设置、`←→` 翻页。**其他视图没有任何快捷键**。

**建议**：
- 跨视图：`Cmd+K` 命令面板（模糊搜 + 操作）；`Cmd+/` 快捷键帮助
- 视图内：LearningView `L` 标记学会、`E` 编辑；LiveView `R` 标记已唱、`S` 跳过

#### 痛点 3：跨视图状态保持

切到"统计"再切回"工作台"——主题/画布/参数是否保留？

代码上看：localStorage `gp-workspace` 在 App mount 时读回，但只覆盖 `selTheme / page / canvas / avoid / params`；**不**覆盖 `lastRenderMs / songStats`——这俩不算状态。

但 Library 切到 Learning 会重新拉数据——是合理的（视图独立）。

**问题**：导出对话框的 scope 选择"page / theme / all" 关闭后再次打开默认回到 "all"（reset 逻辑）——这里合理。

**潜在问题**：`PostersSidebar` 的海报列表切换文档后 `current` 变了，**layout_id 写入 store 但 App 的 `selLayout` state 不动**——切 layout 实际只影响 store，不影响主预览。**这其实是 `selLayout` 死代码的根源**。

#### 痛点 4：删除/重命名海报的入口缺失

`PostersSidebar` 有"删除当前"，但**没有重命名**。要改名字只能：
- `store.update({ name: "..." })` 没暴露 UI
- 在工作台 `<input>` 改造 name 字段——目前没做

**建议**：海报列表项双击/右键 → 弹重命名输入框。

#### 痛点 5：导出后"打开目录"是唯一反馈

ExportDialog 完成态显示"完成 N 张"+ "打开目录"按钮。但用户：
- 不知道文件命名规则（`歌单海报-{主题}-p{页}.png` 之类）
- 不知道是否被 Dropbox / iCloud 同步走了
- 找不到"上次导出了什么"

**建议**：完成态增加"显示文件位置"行（展开可看所有文件名 + 单个"在 Finder 显示"）。

#### 痛点 6：键盘导航主题列表不可达

左侧主题缩略图是 `<button>`，可 Tab 聚焦但**无 ↑↓ 方向键导航**。要切换主题必须 Tab 走完所有。

**建议**：箭头键在主题列表内上下移动焦点，Enter 选中（Listbox 模式）。

#### 痛点 7：LearningView 批量导入格式文档缺失

输入框占位符是"一行一首：歌手 歌名"——但实际解析规则：
- 空行跳过
- `" - "` 分隔歌手和标题
- 多歌手用 `/` 分隔
- 纯文本作为歌名

这些规则**不在 UI 上提示**。导入失败无具体错误（"无法识别任何歌曲"）。

**建议**：占位符补充示例（如"周杰伦 - 晴天\n/陈奕迅 - 十年"），并对每行标注解析结果（✓ 解析 / ✗ 跳过原因）。

#### 痛点 8：海报"水印修正"字段含义不可见

`Theme.watermark_fix: boolean`——用户在小卡片看不到含义。这是"技术概念"包装成 UI 字段，没解释清楚。

**建议**：把 `watermark_fix` 从用户可见字段移除（或在"当前主题"折叠区加 tooltip 解释："修复生成时图片水印的影响"）。

#### 痛点 9：直播"主播加歌"按钮不跨视图

`LiveView` 有"主播加歌"入口，但工作台编辑海报时也想加歌——只能切到 LiveView。

**优先级**：低。流程合理：海报编辑归工作台，加歌归直播台账。

### 2.3 UI 维度

#### 痛点 1：5 个视图的"无数据"状态风格各异

| 视图 | 状态 |
|---|---|
| 工作台 | `<div className="text-center space-y-3">` 自写 |
| 歌曲库 | `AsyncStateNotice` 组件 + `<div className="panel-empty">` |
| 学歌 | `AsyncStateNotice` + 自写空状态 |
| 直播 | `AsyncStateNotice` + 列表空态 |
| 统计 | `<ErrorNotice message={...} />` + `<EmptyNotice note={...} />` + `<LoadingCard />` |

**建议**：抽 `<EmptyState icon="..." title="..." description="..." action={...} />` 统一。

#### 痛点 2：左侧主题缩略图加载失败兜底视觉打架

```tsx
<div className="absolute inset-0 flex items-center justify-center px-3 text-center text-xs text-muted-foreground">{t.name}</div>
<img src={...} onError={(e) => { e.currentTarget.style.display = "none"; }} />
```

主题名文字居中 + 缩略图叠加——失败时文字应该凸显，成功时缩略图覆盖文字。当前实现里文字一直在那，**被缩略图遮挡**——视觉上**字 + 图**打架。

**建议**：图片加载成功（`onLoad`）后**才**隐藏 fallback 文字；或直接用 `data:image` placeholder + `onLoad` swap。

#### 痛点 3：状态徽章颜色未统一

| 位置 | 颜色来源 |
|---|---|
| `PostersSidebar.status` | `var(--color-primary)` / `var(--destructive, #c0392b)` |
| `StatsView.OverviewCard` 9 卡片 | `from-primary/20`、`from-amber-500/20` 等硬编码 Tailwind 色 |
| `LearningView` 状态 | 暂无统一 |
| `LiveView` 会话状态 | `STATE_LABEL` 字典无颜色 |

**建议**：抽 `<StatusBadge kind="saved|error|loading|active|closed" />` 组件统一色。

#### 痛点 4：图标系统存在但未充分使用

`icons.tsx` 有 `Icon.layout / list / book / live / barChart / music / sun / settings / download / refresh` 等。**但很多地方用 inline SVG**：
- `App.tsx:414` 缩放按钮 SVG
- `App.tsx:608, 654, 469` chevron / spinner
- `App.tsx:70, 84` 撤销 / 重做

**建议**：把这些抽到 `icons.tsx` 或新建 `icons-ui.tsx`。

#### 痛点 5：底部状态栏信息密度可提升

当前只显示：`{themes} 个主题 · {maxPage} 页 · 已会 N · 未会 N · 渲染 Nms/张`

**建议**：增加快捷键提示（`⌘E 导出 · ⌘R 刷新 · ⌘K 命令面板`）在 hover 时高亮。

#### 痛点 6：shadcn/ui 进一步统一空间

| 组件 | 当前实现 | shadcn 等价 |
|---|---|---|
| ExportDialog | 完全自写 | `Dialog` + `RadioGroup` + `Progress` |
| ParamInspector | 完全自写 | `Form` + `Input` + `Select` + `Slider` |
| ColumnTemplatePicker | 自写 | `Select` + `Tabs` |
| LiveView 会话详情 | 自写 | `Card` + `Table` |
| StatsView 9 卡片 | 自写 | `Card` |

**优先级**：低。shadcn 改完不一定更易维护；先做 EmptyState / Spinner / StatusBadge。

#### 痛点 7：暗色 mode 下 `dark:bg-zinc-800/50` 散落 30+ 处

包括 App.tsx、PostersSidebar、LibraryView、LearningView、LiveView、StatsView、SettingsView、ParamInspector、ColumnTemplatePicker 等。

**建议（R4.0.9）**：用 `bg-card` / `bg-muted` / `bg-background` token 替换；保留 `dark:bg-zinc-800/50` 之类仅当"找不到合适 token"时。

#### 痛点 8：海报详情 hover 卡片未打磨

主题卡片有 hover 渐变，但 hover 弹出的"主题详情"——`当前主题` 折叠区**只能点开看**，不能 hover preview。

**建议**：hover 主题卡片 → 弹 1.5x 缩略图 preview。

### 2.4 细节维度

#### 痛点 1：localStorage key `gp-workspace` 是旧名

`gp = gallery poster` —— 项目已改名 `streamer-workbench`（`sw`），key 没改。

**建议**：读时兼容 `gp-workspace`，写时统一为 `sw-workspace`。

#### 痛点 2：App.tsx 注释残留旧阶段编号

```tsx
// P0-1: 排版参数受控
// P2 R4: 类型放宽为 unknown
// Phase 2: 参数面板动态渲染
// P2 R4: magazine-flow 栏数模板
// Phase 2: 视图路由
// Phase 2: 导出对话框
// Phase 2: 状态栏歌曲统计
// Phase 2: 启动恢复
```

**建议**：清理为 `R0.x` / `R1b.x` / `R4.0.x` 等最新编号；或删"Phase 2"这种含糊词。

#### 痛点 3：asQueueEntry / asPerformance 大量 narrow helper 散落

LiveView 自写 2 个 `asXxx` 函数用于 unknown→强类型 narrow。LearningView、StatsView 等**没用 narrow helper**——靠 TS 直接 cast。

**建议**：抽 `lib/narrow.ts` 公共工具（`asRecord / asString / asNumber / asArray`）统一 narrow 风格。

#### 痛点 4：App.tsx `selLayout` state 死代码

```tsx
const [selLayout, setSelLayout] = useState<string>("grid-wrap");
...
useEffect(() => {
  if (!selLayout) return;
  // 拉 /api/layouts/{selLayout}/params
}, [selLayout]);
```

UI 上没有触发 `setSelLayout` 的入口——`selLayout` 永远 = "grid-wrap"。`usePosterStore.current.layout_id` 才是真相。

**建议**：删 `selLayout / setSelLayout` 改从 `usePosterStore` 读 `current.layout_id`。

#### 痛点 5：`useLatestRequest` 与 `usePosterStore` 风格不一致

- `useLatestRequest`：useState + useRef + useCallback 混合
- `usePosterStore`：useState × 10 + useRef × 7 + safeSet* 包装

**建议**：长期抽 `useRequest<T>(key, fetcher, { isEmpty })` 通用 hook，统一 `useLatestRequest` + `usePosterStore` + 散落 useEffect 拉数据模式。

#### 痛点 6：错误反馈风格不统一

| 位置 | 模式 |
|---|---|
| LiveView `setActionError` | 顶部红条，message-only |
| StatsView `setPosterError` | 右角红卡片，data-testid |
| LibraryView `setActionError` | 顶部红条 |
| PostersSidebar `store.error` | 状态徽章变红 + 重试按钮 |
| ExportDialog `setError` | 对话框内红条 |
| App `setResourceError` | 顶部"资源异常·重试"按钮 |

**建议**：抽 `<ErrorBanner severity="warning|error" retry={...}>message</ErrorBanner>` 统一。

#### 痛点 7：`PosterRequest.parameters` 类型不安全

```ts
parameters: {}  // Record<string, unknown>
```

ParamInspector 写值时是 `Record<string, unknown>`，但 ParamSpec 知道每个 key 的 kind。**类型完全没约束**。

**建议**：长期看，把 ParamSpec 移到类型层生成 `parameters: { margin?: number; ... }`。**短期**：约束到 `Record<string, number | boolean | string | string[] | Record<string, number>>` 联合类型。

#### 痛点 8：`uuid()` LiveView 内手写

```ts
function uuid(): string {
  if (typeof crypto.randomUUID === "function") return crypto.randomUUID();
  ...
}
```

**建议**：抽 `lib/uuid.ts` 公共工具（虽然 R2 的 QuickView queue 已经用，但 LiveView 没用）。

## 5. 结论

**项目当前是"做完了一个非常扎实的核心"的状态**——4 套 layout、6 个视图、675+ 测试、桌面壳 + 打包齐备。下一步不是"扩展能力"，而是**把已经做出来的能力**：

1. **收口**（暗色 hardcode / selLayout 死代码 / localStorage key 改名）
2. **串起来**（三套新布局接工作台 / 海报真保存 / 跨视图状态）
3. **统一**（EmptyState / Spinner / StatusBadge / ErrorBanner）

**做完这三件事之后**，项目就真正到了可以"装机自己用"的状态——这就是 R7 发布门之前的最后一段。

R4 Runtime v1 抽象**仍然是技术债**——但有了 P0 收口和真实使用证据（专用海报区产生日活），再做抽象就不会是"凭空设计"。
