## 1. 产品优先级：三个用户闭环

所有任务必须服务至少一个闭环，否则进入候选池而不是主路线。

### A. 日常出图

```text
打开 → 恢复常用模板/预设 → 确认 → 导出
```

产品门：默认场景 3 个用户动作内完成导出；失败可恢复；再次打开不丢状态。

### B. 直播现场

```text
唤起速查 → 搜歌/看谱 → 入队 → 标记已唱 → 事件补报
```

产品门：核心操作可完全键盘完成；后端断开不丢现场队列；退出无孤儿进程。

### C. 学歌循环

```text
记录练习 → 标记学会 → 查看下一步建议 → 创建学习/直播内容
```

产品门：打卡比外部备忘录更省步骤；数据不足时不伪造趋势；结果可直接创建海报。

## 3. 全程质量门

1. `core/` 不依赖 FastAPI、Electron、React 等 UI/服务框架；
2. 触及旧渲染路径必须保持 16/16 diff=0；
3. 禁止用新引擎自举覆盖旧金标准；
4. 持久格式必须 `schemaVersion`、备份、迁移和往返测试；
5. 核心用户数据只有 Python 后端一个写入权威（ADR-003）；
6. 歌曲关系使用不可变 `song_id`，不得继续创造 title 主键（ADR-004）；
7. 每个纵向切片必须同时包含 UI、API、数据、错误态和验证；
8. 无障碍、错误恢复、日志和安全不允许全部推迟到最后；
9. 阶段完成以退出条件和真实使用证据为准，不以“类和接口已创建”为准；
10. 每个提交只解决一个可验证问题；不 force push，不改写发布历史。

## R4 · 从真实场景冻结 Layout Runtime v1

> **目标**：在 magazine、live-set、learning-report 三个场景验证后，才冻结公共运行时。
> **依赖**：R1/R2/R3 至少完成可用版本。

仅提取被两个及以上真实场景使用的能力：

- 文本测量、换行和最小字号；
- 栏排、可用线段和分页；
- LayoutAnalysis / LayoutPlan / render 三段式契约；
- 确定性随机；
- draft/full 正确性一致的预览等级；
- Shape/AABB 基础碰撞。

路径排文、复杂 polygon、orbit、scatter 不作为 Runtime v1 必需项；由后续真实布局拉动。

### R4 退出条件

- [ ] 三个场景使用同一稳定计划格式；
- [ ] 公共能力至少被两个场景复用；
- [ ] 不存在只为假想布局服务的必选接口；
- [ ] draft/full 语义结果一致；
- [ ] grid-wrap 仍固定两页且 16/16。

## R5 · 工作台系统化（分段交付）

> **目标**：避免一次性“大重构”，按状态可靠性 → 创作效率 → 高级体验推进。
> **依赖**：R1–R3 已有真实场景。

### R5a 状态可靠性

- WorkspaceDocument；
- 文档/UI/服务/持久状态分离；
- 自动保存、失败恢复、离开保护；
- 最后请求胜出、Abort、错误态；
- 基础键盘和可见焦点。

### R5b 创作效率

- Template/Preset 资源抽屉；
- 语义属性检查器；
- 参数防抖和预览 crossfade；
- 导出历史使用独立 ExportSnapshot；
- 明暗令牌同源生成，禁止手工多处同步。

### R5c 高级体验

- 撤销重做；
- 2/4 宫格对比；
- 三断点响应式；
- WCAG AA 和 reduced motion；
- 快捷键查看、修改和冲突提示。

“编辑模式”只有出现自由元素或 LayoutDocument 真实编辑需求时才启用；仅调参数不单独设模式。

## R6 · 数据反哺与可选布局扩展

> **目标**：基于真实使用数据扩展，而不是为达到“八套”数量扩展。
> **依赖**：R4/R5；至少积累可解释的数据样本。

候选按证据进入：

1. `artist-rail`：歌手专场高频时；
2. `notebook-lines`：学习场景需要更强表达时；
3. `polaroid-collage`：用户确有社媒视觉差异需求时；
4. `subject-orbit` / `free-flow`：路径和主体环绕需求被真实验证后。

发布策略改为：**3 套正式场景 + 若干实验布局**。八套是能力候选清单，不是首次发布门。

## Optional Lab · 自定义布局编辑器

完整编辑器不属于承诺发布范围。仅当以下条件同时满足后单独立项：

- 至少 3 套正式场景已持续真实使用；
- 用户频繁要求无法由参数或新模板解决的自定义；
- WorkspaceDocument、LayoutPlan、撤销重做稳定；
- 代理画布与 PIL 精确计划完成 POC；
- 有明确的安全包格式和维护预算。

继续坚持“数据容器编辑器”，不做通用图片编辑器，不要求逐首拖动歌曲。

## 4. 阶段状态记录规则

每个阶段只允许三种状态：

- `⬜ 未开始`：没有进入执行；
- `🟡 进行中`：部分产出存在但退出条件未全部满足；
- `✅ 已完成`：退出条件全部有证据，README/AGENTS/路线图已同步。

禁止用提交数量、代码文件存在或 UI 占位入口作为阶段完成证据。
