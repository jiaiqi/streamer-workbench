## 1. 产品优先级：三个用户闭环

所有任务必须服务至少一个闭环，否则进入候选池而不是主路线。

### A. 日常出图

```text
创建/恢复海报 → 选择歌曲来源 → 选择布局 → 筛选兼容主题/比例 → 分类排序 → 自动分页 → 预览 → 导出
```

产品门：首次使用可借助样例数据完成完整流程；重复使用最近海报或 Preset 时 3 个用户动作内完成导出；无需创建直播场次；歌曲不因分页变化丢失；失败可恢复；再次打开不丢状态。

### B. 直播现场

```text
唤起速查 → 搜歌/看谱 → 入队 → 标记已唱 → 事件补报
```

产品门：核心操作可完全键盘完成；后端断开不丢现场队列；退出无孤儿进程。

### C. 学歌循环

```text
记录练习 → 标记学会 → 查看下一步建议 → 创建学习/直播内容
```

产品门：打卡比外部备忘录更省步骤；数据不足时不伪造趋势；结果可直接创建海报。

## 3. 全程质量门

1. `core/` 不依赖 FastAPI、Electron、React 等 UI/服务框架；
2. 触及旧渲染路径必须保持 16/16 diff=0；
3. 禁止用新引擎自举覆盖旧金标准；
4. 持久格式必须有显式版本字段、备份、迁移和往返测试；配置类 JSON 使用 `schemaVersion`，事件 JSONL 使用 `schema_version`；
5. 核心用户数据只有 Python 后端一个写入权威（ADR-003）；
6. 歌曲关系使用不可变 `song_id`，不得继续创造 title 主键（ADR-004）；
7. 模块运行时边界和本地服务安全服从 ADR-005，海报/场次边界服从 ADR-006，点歌规则服从 ADR-007；
8. 每个纵向切片必须同时包含 UI、API、数据、错误态和验证；
9. 无障碍、错误恢复、日志和安全不允许全部推迟到最后；
10. 阶段完成以退出条件和真实使用证据为准，不以“类和接口已创建”为准；
11. 每个提交只解决一个可验证问题；不 force push，不改写发布历史。

### 产品定位（区别于通用音乐 App）

主场景：**直播时打开"弹唱模式"** → 屏幕大字号歌词滚动给观众看 + 曲谱跟着唱到哪高亮到哪。次场景：练习时跟唱 / 学歌时辅助记忆。**不是**音乐发现、社交、评论、付费。

UI/UX 三条特色：
1. **舞台感大于播放感**：默认"大歌词 + 简化播放器"模式，类似卡拉 OK 但不土味；
2. **曲谱不只阅读，要"跟着唱"**：chordpro 解析后 chord 高亮 + 行跟随 + 一键"切到这一行"；
3. **跟直播队列联动**：弹唱当前曲目自动与 LiveSession 队列项同步，弹完自动点"已唱"。

### 数据模型增量（向后兼容，旧字段不动）

```python
# core/data/songs.py
@dataclass
class Song:
    # ... 已有字段 ...
    # R8 弹唱：歌词（双通道：LRC 带时间戳 / 纯文本兜底）
    lyrics_lrc: str = ""              # LRC 格式 [mm:ss.xx] 歌词
    lyrics_plain: str = ""            # 无时间戳纯文本（无 LRC 时按行均分）
    # R8 弹唱：音频（本地优先，避免在线版权）
    audio_vocal_path: str = ""        # 原声 data/audio/{song_id}/vocal.{mp3|m4a|ogg|wav}
    audio_instrumental_path: str = "" # 伴奏 data/audio/{song_id}/instrumental.{...}
    audio_duration_ms: int = 0        # 主音频时长缓存（避免每次解码）
```

存储目录 `data/audio/{song_id}/` 复用 `data/tabs/{song_id}/` 的白名单/最大 50MB/unlink 校验模式。

### 事件类型增量（复用 events.jsonl）

- `playback_started (song_id, source: "vocal"|"instrumental", position_ms)`
- `playback_paused (song_id, position_ms)`
- `playback_completed (song_id, duration_ms)`
- `playback_progress` 可选（30s 心跳，给统计看"这歌听过几次 / 哪里停"）

### 视图与组件

**新增第 6 视图** `PlayView`（不破坏现有 5 视图结构）：
- 顶栏：返回 / 歌名 - 歌手 / 切换 vocal-instrumental（仅当两轨都有时显示） / 关队列 / 全屏
- 中央左：歌词区（LRC 时间轴 + 当前行高亮 + 居中滚动；纯文本时按行均分）
- 中央右：曲谱区（chordpro 解析 + 行跟随 + chord 高亮；tab_files 图片时全屏放大镜）

**3 个入口**（不破坏现有视图）：
1. 工作台底部快捷栏「弹唱」按钮 → PlayView
2. 歌曲库行内 ▶ 按钮 / 双击行 → PlayView 加载该歌
3. LiveView SessionCard「弹唱」按钮 → PlayView + 同步当前队列项

### 技术要点

| 关注点 | 设计 |
|---|---|
| LRC 解析 | `core/lrc.py` 纯函数：`parse_lrc(text) -> list[(time_ms, text)]`；空 LRC 用 `lyrics_plain` 兜底（按行均分时间）；单测 30+ 项 |
| chordpro 解析 | `core/chordpro.py` 纯函数：`parse_chordpro(text) -> list[Section]`；识别 `{chord}`、行号、section 标签（前奏/主歌/副歌）；单测 20+ 项 |
| 音频路径管理 | `core/audio.py` 路径白名单 + sanitize；复用 `data/tabs/{song_id}/` 模式 |
| 时间同步 | requestAnimationFrame 跑 `audio.currentTime * 1000` → 二分找 LRC 当前行 → 居中+高亮；避免频繁 setState（用 ref + transform） |
| chord 高亮 | 行内 chord token 套 `<span data-active>`，CSS transition 颜色 |
| Electron 音频 | desktop 模式用 `MediaSession` API（系统媒体键 / 锁屏控制）；浏览器模式用 `<audio>` 标准 API |
| 桌面壳权限 | macOS 不需要；Windows 需要 manifest 声明 `microphone`（仅 R8.2 录音时） |
| 性能 | 大曲谱（1000+ 行）虚拟滚动；歌词 200+ 行虚拟滚动 |
| 测试 | Python 30+ LRC + 20+ chordpro + 20+ audio；vitest 25+（滚动同步 + 高亮 + chord 渲染 + virtual scroll） |

### 与现有架构对接

- **R4 Runtime v1**：PlayView 走新 `DataChannel` `playback_snapshot`（R8.1 时按需扩展，不强制）
- **LiveView 联动**：PlayView mount 时接收 `linkedSessionId` prop，从 `LiveService` 拉当前队列项；用户点"下一首"调 `POST /live-sessions/{id}/record` 标记 sung

- **新布局？**：弹唱屏幕**不是海报**，不走 `core/layouts`；单独 `core/player/` 模块

## 4. 阶段状态记录规则

- `⬜ 未开始`：没有进入执行；
- `🟡 进行中`：部分产出存在但退出条件未全部满足；
- `✅ 已完成`：退出条件全部有证据，README/AGENTS/路线图已同步。
