## 1. 执行摘要与最终结论

### 1.1 三视角结论

| 视角 | 结论 | 最终动作 |
|---|---|---|
| 产品经理 | 当前已不是单一海报脚本，而是歌曲资产、学歌、曲谱、直播速查和海报创作共存的工作台；但产品叙事和闭环尚未统一 | 定义为“音乐主播内容与直播运营工作台”，对外可称“主播演出后台” |
| 产品 + UI/UX | 晨光纸感方向正确，React 落地和工作台创作体验不足；布局没有成为用户可理解的选择 | 保留视觉语言，系统重做工作台、暗色、组件、预览、动效、响应式和无障碍 |
| 系统架构师 | PIL 引擎、数据层、FastAPI、React、插件思想和金标准是有效资产；布局运行时、主题模型、状态和桌面能力需升级 | 保留承重结构，专项重构扩展层，不整项目重写 |

### 1.2 明确结论

**不推倒重写。**

保留：

- PIL 纯函数渲染管线；
- `core/` 与 UI/服务器隔离；
- `LayoutPlugin` 思想；
- songs.json + events.jsonl 本地数据哲学；
- FastAPI 本地服务；
- React + Vite 工程载体；
- 16 张独立预言机金标准；
- 已完成的歌曲库、学歌、曲谱、速查和导出能力。

重构/新增：

- Layout/Palette/Skin/Preset 四模型；
- 从真实布局中逐步提取 Shape、锚点、碰撞和分页运行时；
- 首发 3 套正式场景，其他布局作为经需求验证后启用的候选；
- 工作台文档状态、保存恢复、撤销重做和按需启用的对比/编辑能力；
- 场景预设、主题皮肤管理、导出历史、统计反哺创作；
- 正式 Electron 壳与置顶速查；
- 满足真实需求触发条件后才立项的数据容器式自定义布局编辑器；
- 测试、性能、无障碍、日志和数据恢复发布门。

### 1.3 一句话升级

> 从“一套网格版式换七张背景”，升级为“主播可选择、组合、微调和创造多种构图，并让歌曲、学习、点歌与演唱数据持续反哺直播内容”的桌面工作台。

### 1.4 执行策略

完整能力不等于一次性建设范围。执行采用三条原则：

1. **先正确、再扩展**：先解决歌曲不可变身份、事件 Schema、用户数据目录和现有渲染正确性；
2. **纵向切片**：每个阶段同时交付核心、API、UI、错误态和测试，不先建设无人使用的完整通用平台；
3. **从实例提取抽象**：先完成 magazine、live-set、learning-report 三个真实场景，再冻结 Layout Runtime v1。

产品只承诺三个核心闭环：日常出图、直播现场、学歌循环。主题管理、更多布局、统计大屏和编辑器必须证明能增强其中至少一个闭环。

## 2. 当前事实、产品边界与铁律

### 2.1 当前事实

| 项目 | 当前状态 |
|---|---|
| 主题 | 7 套扁平 `theme.json`，背景 + 五颜色角色 |
| 布局 | 仅 `grid-wrap`，固定 2 页 |
| 画布 | 标准 9:16（1080×1920）和抖音 9:20（1080×2400） |
| 数据 | songs.json v4，178 首，`active/draft` 两态 |
| 时间维度 | S1–S3 代码已完成；S3.5 Song v5 / Event v2 是当前前置，S4/S5 等待身份升级 |
| UI | 工作台/歌曲库/学歌/设置 + `/quick` Web 页；主题/预设/历史仍占位 |

| 测试 | 单元测试 + 16 张金标准 + TypeScript 编译检查 |

| 自定义 | Palette/Skin/Preset 已有领域模型骨架，但未完整接入渲染和工作台；anchors/Freeform/编辑器未实现 |
| 后端工程 | deps + routers 已拆分；仍有 Preset/导出模块级引用、CORS 全开和统一错误缺口 |

| 组件 | React 组件对齐 `shared.css` 设计规范率约 15%，gp-* 组件类基本未用（HANDOFF §5） |
| 动效 | 当前无 `@keyframes`、无 FLIP、无 staggered animation、无 `prefers-reduced-motion` 查询；仅有 `transition-colors` 和 `animate-spin` 两种基本过渡 |
| 无障碍 | 无系统 `aria-label`（按钮仅靠 title）、无焦点锁定、无键盘导航路由、无 `prefers-reduced-motion`；WCAG AA 为零起步 |

### 2.2 产品边界

本产品面向个人音乐主播，电脑运行、手机直播。本阶段不把以下能力作为前置：

- 账号和强制云同步；
- 在线素材/模板市场；
- 多人实时协作；
- 手机端完整编辑器；
- 完整图片编辑或视频剪辑；
- 直播平台弹幕中台。

布局、Skin 和 Preset 可以通过文件导入/导出分享，架构不得阻断未来扩展。

### 2.3 不可破坏铁律

1. `core/` 不 import FastAPI、Electron、React 或任何 UI 框架；
2. 旧 `grid-wrap` 金标准 16/16 diff=0；禁止用新引擎自举覆盖旧基线；
3. songs.json 是当前状态真相，events.jsonl 是历史；统计只算不存；
4. 旧 theme.json 可继续加载；
5. 用户数据迁移前备份，失败保留原文件；
6. API 拆分时路径兼容优先；
7. 内置只读资源与用户可写数据必须分开；
8. 所有持久格式有 schemaVersion。
9. Python 后端是核心用户数据的唯一写入权威（ADR-003）；
10. 歌曲关联使用不可变 `Song.id`，不得继续创造 title 主键（ADR-004）。

## 3. 产品定位、用户闭环与信息架构

### 3.1 产品定义

产品定义：**音乐主播内容与直播运营工作台**。

对外语言：**主播演出后台**。

三个核心闭环：

```text
日常出图：恢复模板/预设 → 确认 → 导出
直播现场：速查/看谱 → 入队 → 标记已唱 → 离线补报
学歌循环：打卡 → 学会 → 下一步建议 → 创建内容
```

### 3.2 用户分层

| 用户 | 核心需求 |
|---|---|
| 核心：日常音乐主播 | 快速出图、直播查歌、看谱、点歌、记录已唱 |
| 次级：音乐内容创作者 | 管理长期曲库，制作专题/新歌/总结海报 |
| 高阶：个人品牌创作者 | 自定义布局、主题皮肤、预设和数据驱动视觉内容 |

### 3.3 完整闭环

```text
维护歌曲与曲谱
  ↓
学习、打卡和标记学会
  ↓
策划直播场景 / 选择歌曲集合
  ↓
挑模板（内部组合 Layout × Palette × Skin）
  ↓
微调 / 对比 / 保存 Preset
  ↓
一键出图
  ↓
直播置顶速查 / 点歌 / 看谱 / 标记已唱
  ↓
事件沉淀
  ↓
统计、提醒和下一场内容建议
  ↓
用统计结果直接创建下一张海报
```

### 3.4 目标信息架构

```text
音乐主播工作台
├── 工作台（创作、模板、预设、历史）
├── 歌曲（歌曲库、自定义歌单、曲谱）
├── 学歌（状态、打卡、时间线）
├── 直播（速查、今晚队列、已唱）
├── 统计（总览、学习、直播）
└── 设置（输出、字体、资源、数据、快捷键、桌面行为）
```

原则：侧栏一级项不超过 6 个。主题、布局、预设和导出历史优先作为工作台内标签、资源面板或抽屉；只有复杂度和频率证明有必要时才拆独立页。

### 3.5 高频旅程

#### 日常一键出图

打开 → 恢复默认 Preset → 确认预览 → 一键出图。目标为 3 个用户动作内完成。

#### 探索新方案（有多套正式模板后启用）

浏览真实模板缩略图 → 应用 → 微调 → 保存 Preset。2/4 宫格对比不是首个新布局的前置能力。

#### 直播中

全局快捷键唤起速查 → 拼音/歌手/歌名查询 → Enter 入队 → T 看谱 → 标记已唱 → 本地真相 + 后端保序双写。

### 3.6 用户概念与状态模型

普通用户只需要理解：

- **模板**：可直接使用的 Layout + Palette + Skin 推荐组合；
- **风格**：背景和颜色的简单选择；
- **我的预设**：保存的创作配方。

Layout、Palette、Skin 是内部和高级模式概念，不在默认流程中要求用户逐一选择。

Preset 保存：

```text
SongQuery + Layout + Palette + Skin + Canvas
+ 参数覆盖 + 元素覆盖 + 导出设置 + schemaVersion
```

Preset 是可复用配方；动态 SongQuery 的结果可随曲库变化。需要精确历史重现时使用独立 `ExportSnapshot`，保存当次歌曲 ID/标题快照、完整渲染配置和引擎版本。

| 模型 | 职责 |
|---|---|
| WorkspaceDocument | 当前编辑会话和撤销历史 |
| Preset | 可复用的歌曲查询与创作配置 |
| LayoutDocument | 可复用的布局结构定义 |
| ExportSnapshot | 不可变的历史导出快照 |

## 4. UI/UX 终版方案

> **2026-07-27 设计方向更新**：从原”晨光纸感”单品牌升级为「暗色舞台 Cinematic Stage × 画廊白 Art Gallery」双品牌体系。工具界面默认使用画廊白品牌（干净专业、长时间不累），落地页默认使用暗色舞台品牌（聚光灯美学、记忆点强）。设计令牌单源真值已更新为 `design/design-tokens.json` v2。React 工作台 `ui/src/index.css` 已同步。

### 4.1 视觉系统

双品牌设计令牌体系：

- **画廊白 Art Gallery**（工具界面默认）：暖纸白底 `#FAF8F5`，海洋青主色 `#2F8F7A`，暖珊瑚 `#D9764F`。博物馆留白，干净专业，长时间操作不累。
- **暗色舞台 Cinematic Stage**（落地页 + 可选演出模式）：深暖黑 OLED `#0A0F0D`，亮海洋青 `#3BAF94` + 舞台金 `#E8A33D`。聚光灯美学，大气克制，记忆点强。
- 每种品牌含亮/暗双模（`[data-brand=”stage|gallery”][data-mode=”dark|light”]`），共 4 种状态。CSS 属性选择器驱动，不写两套样式。
- 令牌单源真值：`design-tokens.json` v2（`colors.stage.*` / `colors.gallery.*`），React 端从 `gallery.light` 节派生。

### 4.2 目标工作台

```text
┌──────────────────────────────────────────────────────────────────┐
│ 文件 编辑 视图 布局 主题 帮助        撤销 重做   当前预设 ▾    │
├────────────┬───────────────────────────────┬─────────────────────┤
│ 创作资源   │                               │ 属性检查器          │
│ 模板       │          实时画布             │ ▾ 内容              │
│ 布局       │     预览 / 对比 / 编辑        │ ▾ 布局              │
│ 主题皮肤   │                               │ ▾ 视觉              │
│ 我的预设   │                               │ ▾ 背景与锚点        │
│            │                               │ ▾ 导出              │
├────────────┴───────────────────────────────┴─────────────────────┤
│ 178 首 · 2 页 · 渲染状态              保存预设  一键出图  ▾   │
└──────────────────────────────────────────────────────────────────┘
```

### 4.3 创作三模式

- **预览**：日常安静出图，不显示编辑手柄；
- **对比**：2/4 宫格比较布局、Skin 或参数，统一缩放和页码；
- **编辑**：显示安全区、主体、锚点、避让区、容器、图层和吸附线。

### 4.4 模板中心

模板是优质的 Layout + Palette + Skin 组合，不等于锁死三者。模板卡显示：

- 真实缩略图；
- 布局与主题名；
- 推荐场景；
- 密度；
- 页数估计；
- 数据依赖；
- 推荐/兼容/实验等级。

高级用户可分别切布局、Palette、Skin。

### 4.5 属性检查器

| 分组 | 普通控件 | 专家控件 |
|---|---|---|
| 内容 | 歌曲范围、分类、排序、主推 | SongQuery、缺失字段策略 |
| 布局 | 紧凑/标准/宽松、栏数、方向 | 间距、轨道、分页、overflow |
| 视觉 | Palette、字体、字号、强调 | 颜色角色、字距、行高、阴影 |
| 背景 | 背景页、主体避让、柔光 | anchors/subjects/fallback zones |
| 导出 | 画布、范围、命名、格式 | DPI、压缩、元数据 |

每个控件必须有说明、单位、合法范围、默认值、重置和影响提示。

### 4.6 预览管线

1. 双图叠放 crossfade；
2. 连续输入走 draft，停手后补 full；
3. AbortController/序列号取消旧请求；
4. 参数内容 hash 缓存，不用时间戳破坏缓存；
5. 首次加载、后台重绘、导出、失败重试使用不同反馈；
6. 错误给出重试、恢复默认、查看日志等动作；
7. draft 是新能力，不能把历史 33.8ms 当作其已测结果。

### 4.7 撤销、保存和历史

进入撤销历史：切布局/Skin/Canvas、参数、元素、绑定。缩放、面板开关、当前选择和页码不进入。滑杆等 300ms 内连续输入合并为一次。

保存状态：已保存、未保存、保存中、失败、当前 Preset 已修改。离开或关闭不得静默丢失。

导出历史保存文件状态与 Preset 快照；文件缺失仍可重新生成。

### 4.8 动效

> ⚠️ **当前状态**：代码中无系统性动效。仅 `transition-colors duration-500`、`transition-all duration-200` 和 `animate-spin` 三种基础过渡，无 `@keyframes`、无 FLIP、无 staggered animation、无 `prefers-reduced-motion`。本节为 P5 目标规范。

| 场景 | 时长 | 原则 |
|---|---:|---|
| Hover/按压 | 120–180ms | 不改变布局尺寸 |
| 面板/折叠 | 180–240ms | 高度与透明度协调 |
| 页面切换 | 220–320ms | 淡入 + 轻上浮 |
| 主题切换 | 220–320ms | 背景和色板 crossfade |
| 布局重排 | 300–450ms | 柔和 spring/FLIP，不眩晕 |
| 对话框 | 180–260ms | 遮罩与面板分层 |

尊重 `prefers-reduced-motion`；复杂共享动画是否引入 Motion 以 POC 为准，不预设禁止或强制。

### 4.9 响应式和无障碍

> ⚠️ **当前状态**：无障碍为零起步——无系统 `aria-label`（按钮仅靠 `title`）、无焦点锁定、无键盘导航路由、无 `prefers-reduced-motion`。本节为 R5 工作台系统化的目标基线，并在 R7 发布门复验。

| 宽度 | 策略 |
|---|---|
| ≥1440 | 完整三栏 |
| 1100–1439 | 资源栏窄化，属性栏可折叠 |
| 800–1099 | 一侧常驻，另一侧抽屉 |
| <800 | 紧凑查看/导出，不承诺完整编辑 |

核心无障碍：WCAG AA、图标 `aria-label`、可见焦点、显式 label、对话框焦点锁定、键盘卡片选择、错误不只依赖颜色、图片 alt 含布局/主题/页码、快捷键可查看修改并检测冲突。

## 5. 目标系统架构

### 5.1 分层

```text
Presentation
├── React Workspace
├── QuickView
└── Electron Windows / Menu / Shortcut

Application
├── WorkspaceService
├── RenderService
├── ExportService
├── PresetService
└── StatsService

Domain（core/）
├── Song / SongQuery / Event
├── CanvasSpec / Shape
├── LayoutDefinition / LayoutPlan
├── Palette / Skin / Preset
├── LayoutDocument
└── ExportSnapshot

Infrastructure
├── PIL Renderer
├── loaders / repositories
├── FastAPI routers
└── Electron filesystem/process bridge
```

### 5.2 LayoutPlugin 终版契约

> ⚠️ **当前版本**：`core/layouts/base.py` 为 v0 兼容版，实际接口为 `params() / categorize() / render_page() / extra_colors()`。本文描述的是 R4 在三个真实场景验证后冻结的 target 契约；R1–R3 只实现当前场景需要的最小子集，`grid-wrap` 通过适配层兼容旧接口。

```python
class LayoutPlugin:
    id: str
    name: str

    def metadata(self) -> LayoutDefinition: ...
    def params(self) -> list[ParamSpec]: ...
    def analyze(self, library, canvas, params) -> LayoutAnalysis: ...
    def plan(self, analysis, skin, params) -> LayoutPlan: ...
    def render(self, ctx, plan, palette) -> None: ...
    def extra_colors(self) -> dict: ...  # 保留
```

- `analyze`：内容分类、测量、容量和数据缺口；
- `plan`：生成可序列化几何计划，便于预览、编辑、测试；
- `render`：只按 plan 绘制，不重新做业务决策；
- Python 插件和 FreeformLayout 共用元数据与计划格式；
- 旧 grid-wrap 可通过适配层逐步迁移，不一次重写。

### 5.3 WorkspaceDocument

```ts
type WorkspaceDocument = {
  schemaVersion: number
  songQuery: SongQuery
  canvas: CanvasSelection
  layout: LayoutSelection
  palette: PaletteSelection
  skin: SkinSelection
  parameters: Record<string, unknown>
  elementOverrides: ElementOverride[]
  exportSettings: ExportSettings
}
```

文档状态、UI 状态、服务状态和持久设置分离。撤销历史只保存文档状态。WorkspaceDocument 不等于 Preset，导出历史也不直接保存可变 WorkspaceDocument，而是生成 ExportSnapshot。

### 5.4 服务端演进

```text
server/
├── main.py
├── deps.py
├── routers/
│   ├── render.py
│   ├── layouts.py
│   ├── themes.py
│   ├── presets.py
│   ├── songs.py
│   ├── export.py
│   ├── events.py
│   └── settings.py
└── services/（只有复杂业务需要时再提取）
```

顺序：先 `app.state/deps` 替换全局对象，再拆 routers，最后按复杂度提 service。API 路径不变，CORS 收敛到本地桌面需要的来源。

核心用户数据只能由后端仓储写入。React 不通过 File System Access API 或 Electron fs bridge 直接修改 songs/events/tabs/presets；壳层只负责选择目录和打开文件/目录。

### 5.5 魔数治理

> ⚠️ 注意：以下魔数分布在多个模块中。`server/main.py` 有三处独立硬编码禁文矩形（L341/L413/L521），去魔数时不能只改 `core/`。

| 当前魔数 | 精确位置 | 终版归属 |
|---|---|---|
| `content_offset` 基准 1920 | `core/spec.py:26` + `core/engine.py:33`（两处独立计算） | CanvasSpec baseline/坐标变换 |
| 柔光底边 1498/1410 | `core/mist.py:12` | Skin 页面参数 |

| `page_capacity = 1920` | `core/layouts/base.py:35`（基类默认）+ `core/layouts/grid_wrap.py:42`（子类覆盖） | 布局按可用内容区计算；grid-wrap 兼容值保留 |

## 6. Layout、Palette、Skin、Preset 四模型

### 6.1 Layout

定义空间组织、分类能力、数据依赖、参数、测量、避让、碰撞、分页和 overflow，不包含具体主题颜色和背景文件。

### 6.2 Palette

v1 只定义海报已有角色：

```text
text / label / pill / line / mist
font_roles: title / label / song / note
```

应用 UI 的 background/card/border 等 token 不放进海报 Palette。布局额外颜色由 `extra_colors()` 声明，Skin 提供映射。

### 6.3 Skin

负责：

- 背景及页面策略；
- subjects、anchors、safe/avoid/fallback zones；
- 柔光、水印和背景延展参数；
- 某 Layout 的参数默认覆盖；
- 扩展颜色角色；
- 推荐组合信息。

### 6.4 Preset

负责可重现的用户场景，保存 SongQuery、Layout、Palette、Skin、Canvas、参数、元素覆盖和导出设置。

“可重现”指配方可恢复，不表示动态查询永远得到相同歌曲集合。历史精确重现由 ExportSnapshot 负责。

### 6.5 回退链

```text
Preset 覆盖
  ↓
Skin 的 Layout 覆盖
  ↓
Palette
  ↓
Layout 语义默认
  ↓
系统安全默认
```

缺少扩展角色或 anchor 不得导致整个资源列表失败。

### 6.6 文件边界

```text
themes/              现有内置主题兼容源，继续可加载
palettes/            新内置 Palette（逐步引入）
skins/               新内置 Skin（逐步引入）
core/layouts/         内置 Python/Schema 布局
data/                 开发期用户数据兼容入口
  presets/
  layouts/
  backups/
```

正式 Electron 中，用户可写 data/output/logs 映射到系统用户目录；内置 themes/palettes/skins/fonts 留在只读资源区。迁移期间旧 theme.json 可动态适配为临时 Palette + Skin。

默认 UI 不直接暴露四模型。Template 作为用户入口，Palette/Skin 的分离只在高级模式和资源管理中出现。

## 7. 统一多布局体系

> 每套布局必须交付：能力元数据、参数、缩略图、推荐场景、数据依赖、少量/标准/超量测试、分页/降级、代表性金标准和全主题巡检。

发布优先级不是按数量推进：

1. `magazine-flow`：日常出图第一纵向切片；
2. `live-set`：直播闭环；
3. `learning-report`：复用 magazine/editorial 零件的数据模板，不新造核心布局算法。

`polaroid-collage`、`artist-rail`、`notebook-lines`、`subject-orbit`、`free-flow` 是候选能力。只有真实使用证据拉动时进入正式范围。首次发布门从“八套全部完成”改为“3 套正式场景达到发布质量”。

### 7.1 `grid-wrap`：全行网格绕排

- 当前保底布局，最高密度；
- 固定 2 页兼容模式，保护 16 张旧金标准；
- 只做魔数归属迁移，不改变像素；
- 新画布适配不得反向改变旧两个画布输出。

### 7.2 `magazine-flow`：杂志双/三栏

- 刊头、期号、日期、栏目和通栏重点区；
- 适合全量歌单、年度合集和复古主题；
- 支持栏目平衡分页和孤儿标题保护；
- 参数：栏数、栏距、密度、刊头、重点区。

### 7.3 `polaroid-collage`：便签拼贴

- 分类形成撕纸/便签卡，轻旋转、叠放、胶带和投影；
- 稳定 seed 确保重复导出一致；
- AABB + 精确碰撞装箱；
- 容量不足新页继续，不缩到不可读。

### 7.4 `notebook-lines`：横线手账

- 歌名吸附横线/谱线，分类为索引贴；
- 消费 learned_at/practice 数据可生成本周学习总结；
- 中英文基线一致；
- 超长歌名允许两行，分页保持线条节奏。

### 7.5 `live-set`：直播节目单

- 上部直播标题、主推、队列或 CTA；下部完整可点歌单；
- 无事件数据自动退化为静态主推区；
- 二维码为可选元素，具体库在 POC 后定；
- 关键现场信息 2 秒可扫读。

### 7.6 `artist-rail`：歌手轨道

- 按 artists 聚合，每位歌手一条横/纵/弧轨；
- 缺失歌手归“其他”，小组可合并；
- 同一歌手尽量不跨页，跨页重复标题并标“续”。

### 7.7 `subject-orbit`：背景主体环绕

吸收 v1 `vinyl-rings` 和 v2 `halo`，不重复实现。模式：

- `orbit` 同心轨道；
- `contour` 沿主体轮廓；
- `split-flow` 主体两侧分流；
- `wreath` 花环弧段；
- `satellite` 多气泡/节点分组。

无主体标注时使用几何中心或 split-flow 降级；容量不足进入下一轨、fallback zone 或下一页。

### 7.8 `free-flow`：曲线/海浪/谱线

- 沿声明的 path 排文；
- 适合梦幻海洋、海洋柔光、卡通音符；
- 首版由 Skin 人工声明路径，不做自动图像边缘识别；
- 与 subject-orbit 共用等弧长采样和旋转字形零件。

### 7.9 `editorial-cover`：增强封面模板

TOP5/本月主推大字号区域 + 完整清单。复用 magazine 栏排零件，产品上作为独立模板。主推来自 Preset 手选或规则，不新增 `Song.pinned`。

`learning-report` 作为 editorial-cover/magazine 的数据模板：展示本月新学、练习次数、下一步歌曲集合。它不计为新的核心 Layout。

### 7.10 能力矩阵

| 布局 | 密度 | 主体依赖 | 数据依赖 | 分页 | 实现建议 |
|---|---:|---:|---|---|---|
| grid-wrap | ★★★★★ | 无 | songs | 固定 2 页兼容 | Python |
| magazine-flow | ★★★★ | 弱 | songs/主推 | 自动 | Freeform + 公共栏排 |
| polaroid-collage | ★★ | 中 | 分类 | 自动 | Python |
| notebook-lines | ★★ | 无 | 学习可选 | 自动 | Freeform |
| live-set | ★★★ | 弱 | queue/events 可选 | 自动 | Python |
| artist-rail | ★★★ | 无 | artists | 自动 | Python |
| subject-orbit | ★★–★★★ | 强 | subjects | 自动 | Python 几何 |
| free-flow | ★★ | 强 | paths | 自动/固定 | Python 几何 |
| editorial-cover | ★★★ | 弱 | 主推/排行 | 自动 | Freeform |

## 8. 背景主体环绕与布局运行时

### 8.1 坐标和 Shape

subjects/anchors 默认使用 0–1 归一化坐标；像素输入仅作为兼容层。

```ts
type Shape =
  | { kind: "rect"; frame: [number, number, number, number] }
  | { kind: "ellipse"; center: [number, number]; radius: [number, number] }
  | { kind: "polygon"; points: Point[] }
  | { kind: "path"; points: Point[]; closed: boolean }
```

### 8.2 区域语义

- `safeArea`：首选内容区；
- `avoidZone`：正文禁止/尽量避免；
- `anchorZone`：标题或装饰吸附；
- `subject`：背景视觉主体；
- `flowPath`：沿线排文；
- `fallbackZone`：主构图不足时回落。

### 8.3 可用线段

```python
segments = available_segments(y, canvas_bounds, avoid_shapes)
```

统一处理矩形、椭圆和多边形与水平线的交点，实现左右分流、花环中心留白和人物轮廓避让。旧 grid-wrap 的右侧禁文区是一个兼容 Shape 特例。

### 8.4 路径排文

1. 曲线等弧长采样；
2. 测量字形；
3. 沿路径累计放置；
4. 切线决定旋转；
5. 超过方向阈值翻转保持可读；
6. 包围盒进入碰撞检测；
7. 不足时下一轨/fallback/page。

中文旋转质量必须先 POC；可采用 4x 超采样、字体缓存和高质量缩放，最终以视觉验收决定实现。

### 8.5 碰撞与 overflow

实时 draft 用 AABB，full/导出用旋转矩形或多边形。处理优先级：

```text
同区域下一个槽位
→ 调整轨道/旋转
→ 合法范围内缩放
→ fallback zone
→ 自动分页
→ 明确报错
```

禁止静默裁切正文。

### 8.6 分页和背景策略

- grid-wrap 保持固定 2 页；
- 新布局可 `pages=auto`；
- `fixed`：页数需匹配；
- `cycle`：背景循环；
- `extend`：最后背景延展；
- `generate` 仅为未来能力，不进入首期。

分页保护标题、组完整性、跨页“续”语义和最小内容量。

## 9. 自定义布局编辑器

### 9.1 产品原则

编辑器操作数据容器，不要求用户拖 178 个歌名。它不是通用图片编辑器，而是“数据绑定的海报布局编辑器”。

### 9.2 架构分离

- **交互代理画布**：React + DOM/SVG/Canvas，负责 60fps 拖拽、吸附、选择和边界；
- **PIL 精确预览**：防抖调用服务端，验证字体、分页、碰撞和最终视觉；
- **PIL 导出**：唯一最终输出真相。

### 9.3 编辑器结构

```text
左：元素和数据源
中：背景、画布、图层、吸附、主体/锚点
右：位置、自动布局、样式、绑定、响应式
上：撤销重做、画布、预览、保存
下：校验告警、页码、渲染状态
```

### 9.4 统一元素与模式

元素：`text/image/shape/qrcode/page-number/date/collection`。

collection 数据源：`songs/category/artist/manual-playlist/queue/stats`。

layout mode：`grid/list/columns/wrap/cards/orbit/path/scatter/manual`。manual 只用于少量元素。

### 9.5 交互能力

拖拽、缩放、旋转、多选、对齐、分布、8px 网格、智能吸附、图层、锁定、隐藏、复制、组合、撤销重做、安全区/锚点/避让区标注、分页和断点预览。

### 9.6 数据绑定

支持全部已会、最近学会、指定歌手/标签/状态、手动歌单、点歌 TOP N、很久没唱、今晚队列。绑定面板实时显示结果数量；空数据可隐藏、显示占位或阻止导出。

### 9.7 保存和安全

- 用户目录 `layouts/<id>/layout.json + thumb + notes`；
- 原子写、备份、`.trash`；
- zip 导入导出；
- Schema、路径、扩展名、数量和大小校验；
- 禁止脚本和布局包外路径；
- 单包损坏不拖垮系统；
- 内置布局只读，可复制为用户布局。

### 9.8 启动条件

R4 可建立稳定的 LayoutDocument/FreeformLayout 最小契约；完整编辑器单独立项前至少满足：

- 3 套新内置布局已上线并真实使用；
- 用户确实频繁切布局或要求自定义；
- 工作台文档状态、撤销重做和属性检查器稳定；
- 代理画布与 PIL 计划格式完成 POC。
- 用户存在参数和新模板无法解决的高频自定义需求；

目标不取消，但避免在运行时和用户需求未验证前先造完整编辑器。

## 10. Canvas、参数、Schema、API 与迁移

### 10.1 CanvasSpec

目标：width、height、baseline、logical/output scale、safe/avoid zones、margin、DPI。

> ⚠️ **当前版本**：`core/spec.py` CanvasSpec 实际字段为 `width/height/avoid_zones/margin/font_song/font_label/row_h/label_h/sec_gap`，排版字号/间距参数仍寄生在 CanvasSpec 上。去魔数不立即变更字段集合——先归属魔数、后拆分参数。

首批 UI 保留当前两个预设；P5 再增加 3:4、1:1、16:9 和自定义，不让 P0 去魔数扩大为 UI 范围爆炸。

number / slider / boolean / choice / color / font
position / rect / spacing / text / group

字段：key、label、description、default、min/max/step/unit、choices、group、advanced、visibleWhen、resetBehavior。

## 11. 数据闭环、Electron 与直播体验

### 11.1 数据路线分工

S1–S5 统计口径以 `../roadmap-data-stats.md` 为唯一真相。S1/S2/S3 的代码已完成，但 S4/S5 必须先完成 ADR-004 的 Song v5 / Event v2 身份升级。路线图 R3 负责把最小统计结果接入产品和创作，不重复定义口径。

### 11.2 统计视图

- 总览：曲库、状态、本月新学、点歌/演唱、曲谱覆盖；
- 学习：练习天数、热力、趋势、卡住最久；
- 直播：点歌 TOP、已唱 TOP、很久没唱、歌手覆盖、场次趋势；

### 11.5 用户数据目录与跨平台文件管理

> **ADR-003 定案**：用户数据目录默认位置按操作系统确定；Python 后端是核心用户数据的唯一写入权威。目录修改后重启生效，迁移必须先备份并可回退。

| 平台 | 默认数据目录 |
|---|---|
| Windows | `%APPDATA%\streamer-workbench\` |
| macOS | `~/Library/Application Support/streamer-workbench/` |
| Linux | `${XDG_DATA_HOME:-~/.local/share}/streamer-workbench/` |
| 开发期 | 项目根 `data/`（兼容现状，可由启动参数覆盖） |

#### 11.5.1 目录结构

用户数据目录由用户自行指定，目录内结构固定：

```text
{用户数据目录}/
├── songs.json              歌曲数据（目标 v5，含不可变 song_id）
├── events.jsonl            事件流（目标 Schema v2）
├── settings.json           工作区内用户设置
├── backups/                自动滚动备份
├── tabs/                   曲谱附件
├── presets/                场景预设
├── layouts/                自定义布局包
└── output/                 默认导出目录
```

#### 11.5.2 单一数据访问路径

- React 只通过 FastAPI 读写歌曲、事件、曲谱、Preset 和设置；
- Electron 原生对话框选择目录后，只把规范化路径交给后端；
- `contextBridge` 不暴露通用业务文件读写 API；
- 浏览器开发模式通过后端设置 API、启动参数或配置文件指定数据目录；
- File System Access API 仅用于显式导入/导出，不作为核心数据持久化通道；
- 当前数据目录路径保存于平台启动配置，不依赖目标目录内的 settings.json 自我定位。

#### 11.5.3 设置页交互

1. 用户通过设置页「数据目录」区域修改路径；
2. Electron 点击「选择目录」弹出原生目录选择器；Web 开发模式使用后端可验证的路径配置；
3. 若新目录为空，自动创建标准子目录结构；
4. 若新目录已有数据文件，提示「发现已有数据，是否迁移旧目录内容？」；
5. 修改后写入平台启动配置，重启后端生效；
6. 历史 Preset 导出的文件路径记录不受影响（文件缺失时提示「文件已移动」但仍可重生成）。

### 11.6 置顶速查

独立 BrowserWindow、alwaysOnTop、透明度、紧凑/展开、多显示器记忆、全局快捷键和冲突检测。第一版快捷键需避开 OBS 等常见直播软件组合，并允许用户修改。

## 附录 C：Song 模型完整字段参考

终版 §6 中仅提及关键字段。完整 17 字段定义见 `core/data/songs.py`，以下为速览：

```python
@dataclass
class Song:
    title: str              # 歌名（唯一键）
    artists: str            # 歌手（逗号分隔）
    key: str                # 选调（如 "G"、"Am"）
    capo: Optional[int]     # 变调夹品数
    section: int            # 手工分组号（1-7，优先于字数自动分类）
    status: str             # "active" | "draft"
    lyricist: str           # 词作者
    composer: str           # 曲作者
    difficulty: int         # 难度（1-5 星）
    tags: list[str]         # 标签（如 ["弹唱","古风"]）
    pinyin: str             # 歌名拼音（全拼，搜索索引）
    added_at: str           # ISO 日期，首次录入时间
    learned_at: Optional[str]  # ISO 日期，标记学会时回填
    tab_files: list[str]    # 曲谱附件相对路径（相对于 data/）
    notes: str              # 备注
    language: str           # 语言（"中文"/"英文"/...）
    source: str             # 来源备注
```

字段迁移链：v1→v2→v3→v4（`songs.py` 头部注释记录每步变更）。
