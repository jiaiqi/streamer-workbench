# R4 退出条件验证设计稿 — 三个场景同一稳定计划格式

> **目标**：把 R4 退出条件 #1「三个场景使用同一稳定计划格式」从 V2.1/V2.2 抽象层坐实为「可被 3 个真实场景端到端走通 + 自动化测试守住」。
>
> **状态**：🟡 设计稿（本批先收口 #1，#2 草稿/手动分页 UI + #3 专用海报区日活留待下批）
>
> **日期**：2026-08-14

---

## 1. 背景

R4 Runtime v2 全 5 个 spike 已收口（V2.1 核心抽象 + V2.2 三段式契约统一 + V2.3 Palette/Skin 真实接线 + V2.4 Parameters 注入链路 + V2.5 能力矩阵 + UI 灰显），其中 V2.1+V2.2 已经把 `LayoutPlan` 抽象层落地：

- 5 个 frozen dataclass（`LayoutAnalysis` / `LayoutPlan` / `PagePlan` / `SectionPlan` / `SectionLayoutKind`）
- 4 套 layout 都实现了 `analyze(library, ctx)` + `plan(library, ctx)` 统一签名
- `core/engine.py` `render_pages` 解耦写死的 magazine_flow import

但 R4 退出条件 #1「三个场景使用同一稳定计划格式」目前只有单元测试覆盖（`tests/test_runtime_v2.py`），缺：
- 真实数据通道端到端走通（LiveSessionSnapshot / LearningReportSnapshot 走 plan → render 全链路）
- 自动化守住"3 个场景 plan 输出结构一致"
- 演示脚本：CI 跑 + 人工验证用

本批把这块补齐。

---

## 2. 设计目标

### 2.1 收口判据

- [x] 3 个真实数据通道（SongLibrary / LiveSessionSnapshot / LearningReportSnapshot）端到端走 `analyze → plan → render` 全链路
- [x] 3 个场景的 `LayoutPlan` 输出结构一致（同样字段、同样的 nested 关系、page/section 类型统一）
- [x] 同一输入多次 plan 结果稳定（frozen + __hash__ 一致 → 可重复 hash）
- [x] 同一输入多次 render 像素稳定（PNG hash 守恒）
- [x] 自动化测试守住（`tests/test_runtime_v2_three_scenarios.py`，≥ 12 项）
- [x] 演示脚本可手动跑（`tools/verify_runtime_v2_three_scenarios.py`）

### 2.2 不在本批范围

- 草稿/手动分页 UI（V3 推动，留给下批）
- 专用海报区日活（需事件埋点 + 展示面板，1 天工作量，独立收口）
- 调整 `LayoutPlan` 字段（V2.1 已稳定，5 dataclass 形态不动）

## 3. 实现方案

### 3.1 新增工具脚本

**`tools/verify_runtime_v2_three_scenarios.py`**

手动运行 — 一键跑 3 个场景端到端，输出统一表格 + 写 PNG + 写 JSON。

```python
#!/usr/bin/env python3
"""R4 Runtime v2 退出条件 #1 验证：3 个场景同一稳定计划格式。

演示：SongLibrary / LiveSessionSnapshot / LearningReportSnapshot
      三个独立数据通道 → analyze → plan → render 全链路

输出：
- 控制台：3 个场景的 plan 结构对比表
- data/verify_runtime_v2/{layout_id}.json：每个场景的 LayoutPlan 序列化
- data/verify_runtime_v2/{layout_id}.png：每个场景的渲染结果

跑法：
  PYTHONPATH=. python tools/verify_runtime_v2_three_scenarios.py
"""
```

输出示例：
```

│ magazine-flow   │ 1       │ 7     │ d4e5f6… │ ✅ 0 px diff │

✓ 3 个场景 plan 输出结构一致

✓ 同一输入 render 像素稳定（hash 一致）
```

### 3.2 新增测试

**`tests/test_runtime_v2_three_scenarios.py`**

12 项自动化测试：
- 3 套场景 × 2 通道（analyze/plan）× 1 断言 = 6 项
- 3 套场景 × 1 渲染稳定性 = 3 项
- 3 套场景 × 1 确定性 = 3 项
- 1 项 cross-scenario 字段一致性

```python
class TestThreeScenariosAnalyze:
    def test_grid_wrap_analyze(): ...
    def test_live_set_analyze(): ...
    def test_learning_report_analyze(): ...

class TestThreeScenariosPlan:
    def test_grid_wrap_plan(): ...
    def test_live_set_plan(): ...
    def test_learning_report_plan(): ...

class TestThreeScenariosRenderStability:
    def test_grid_wrap_render_hash(): ...
    def test_live_set_render_hash(): ...
    def test_learning_report_render_hash(): ...

class TestThreeScenariosDeterminism:
    def test_grid_wrap_plan_hash_same(): ...
    def test_live_set_plan_hash_same(): ...
    def test_learning_report_plan_hash_same(): ...

class TestThreeScenariosUniformContract:
    def test_all_plans_have_same_top_level_fields(): ...
```

## 4. 风险与回退

| 风险 | 概率 | 应对 |
|---|---|---|
| 3 套 layout plan() 字段不一致 | 中 | 已存在统一 dataclass；测试守 cross-scenario 一致性即可暴露 |
| render 像素不稳定 | 低 | 现有 4 套金标准已守恒，复用即可 |
| 演示脚本输出与测试不匹配 | 低 | 脚本和测试共用同一 fixture 构造函数 |
