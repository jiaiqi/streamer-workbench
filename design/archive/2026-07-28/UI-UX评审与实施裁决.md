## 1. 结论

当前视觉方向成立，但产品主线尚未闭合。界面仍然像“海报生成器 + 歌曲库 + 学歌工具 + 直播速查”四个页面的组合，还没有形成围绕一场直播的连续工作流。

**不重做视觉系统，重做任务流和数据绑定。**

保留：

- 画廊白 Art Gallery 的暖纸白、海洋青、留白和卡片语言；
- 桌面端左侧资源 / 中间预览 / 右侧设置的三栏基础；
- 歌曲库的搜索、筛选、分组和就地编辑；
- 学歌页的难度、Key、Capo、备注和标记学会；
- QuickView 的暗色舞台风格和键盘交互。

优先重做：

- 一级导航和产品命名；
- 工作台的场景、歌曲来源和歌曲集合流程；
- 首次打开到第一次导出的闭环；
- Song.id 到前端队列、事件和导出的全链路；
- 错误、空状态、保存和导出反馈；
- 移动端的产品边界，而不是继续压缩桌面三栏。

## 2. 当前体验评估

| 维度 | 评分 | 结论 |
|---|---:|---|
| 视觉一致性 | 8/10 | 方向稳定，不需要推倒重来 |
| 桌面布局基础 | 7/10 | 三栏合理，但参数和资源职责需要重排 |
| 信息架构 | 5/10 | 导航与“主播工作台”定位不完全一致 |
| 核心任务流 | 4/10 | 歌曲如何进入海报、如何服务直播不够明确 |
| 新用户上手 | 3/10 | 缺少样例数据、引导和可执行空状态 |
| 功能闭环 | 5/10 | 歌曲、学歌、直播各自可用，互相反哺不足 |
| 数据可靠性 | 4/10 | 前端仍有以标题作为业务身份的路径 |
| 移动端体验 | 3/10 | 当前主要是桌面布局被裁剪 |
| 无障碍与错误恢复 | 4/10 | 反馈、焦点、ARIA 和恢复动作不完整 |

### 根因判断

1. 产品目标是“主播工作台”，界面主动作仍是“调参数生成海报”；
2. 工作台没有一等公民的 SongQuery、歌曲集合和场景概念；
3. 未完成能力以导航入口出现，稀释了当前真正可用的主线；
4. 标题仍在部分前端关系中充当身份，导致改名和队列/事件关联有风险；
5. 移动端没有独立任务定义，直接复用了桌面端布局。

## 3. 采纳后的产品主线

### 3.1 一级导航

固定为最多 6 项：

~~~text
工作台
歌曲
直播
学歌
统计
设置
~~~

主题、布局、模板、预设和导出历史不作为默认一级导航，优先放入工作台资源抽屉、标签或上下文面板。未完成能力不以可点击但不可用的 soon 入口暴露。

### 3.2 三个核心任务

#### 日常出图

~~~text
选择场景 → 选择歌曲来源 → 确认歌曲集合 → 选择模板 → 预览并导出
~~~

重复使用已保存场景时，目标仍是 3 个用户动作内完成导出；首次使用允许通过样例数据和引导完成完整流程。

#### 直播现场

~~~text
打开速查 → 搜歌/看谱 → 加入队列 → 标记已唱 → 记录事件
~~~

队列使用 song_id，后端不可用时本地现场状态不丢失，恢复后按 event_id 补报。

#### 学歌循环

~~~text
记录练习 → 标记学会 → 查看下一步建议 → 创建直播或海报内容
~~~

统计数据不足时明确显示“正在积累”，不展示伪趋势。

### 3.3 工作台概念

普通用户只需要理解：

- **场景**：今晚直播、新学歌曲、歌手专场、最近常唱、自定义；
- **歌曲来源**：今晚队列、最近常唱、指定歌手、标签、状态筛选、手动选择；
- **模板**：可以直接使用的视觉组合；
- **歌曲集合**：当前这张海报实际包含的歌曲；
- **高级设置**：只在用户主动展开时显示。

Layout、Palette、Skin 是内部模型和专家模式概念，不能成为默认流程的必填步骤。

## 4. 工作台改版方案

### 4.1 页面结构

~~~text
┌─────────────────────────────────────────────────────────────┐
│ 今晚直播                    8 首 · 抖音全屏 · 已保存          │
│ [切换场景]                                      [导出 PNG]  │
├───────────────┬─────────────────────────────┬───────────────┤
│ 歌曲来源       │                             │ 海报设置       │
│               │                             │               │
│ 今晚队列       │                             │ 模板           │
│ 最近常唱       │                             │ 画布比例       │
│ 指定歌手       │          海报预览             │ 标题/副标题    │
│ 手动选择       │                             │ 歌曲排序       │
│               │                             │ ▾ 高级设置     │
│ 已选歌曲       │                             │               │
├───────────────┴─────────────────────────────┴───────────────┤
│ 当前 8 首 · 模板：清透海 · 最近保存：刚刚       [导出 PNG]     │
└─────────────────────────────────────────────────────────────┘
~~~

### 4.2 参数分层

普通设置只显示：模板、画布比例、标题与副标题、歌曲排序、是否显示歌手。

高级设置折叠显示：边距、字号、行高、分组间距、布局模式、分页、overflow、背景主体、锚点、避让区、DPI、压缩和元数据。

每个高级参数必须有说明、默认值、合法范围和重置动作。

### 4.3 首用闭环

空曲库时提供：

~~~text
还没有歌曲

先用示例曲库体验一次完整流程，也可以导入你的歌曲表。

[使用示例曲库] [导入歌曲]
~~~

首用验收路径：首次打开 → 使用示例曲库 → 选择“今晚直播” → 选择歌曲 → 生成海报 → 导出 PNG。

### 4.4 移动端边界

移动端不承诺完整海报编辑，定位为直播伴侣和轻量查看端。

支持：歌曲搜索和详情、Key/Capo/备注/曲谱速查、当前直播队列、上一首/下一首/标记已唱、选择模板和简单导出。

桌面端支持完整歌曲集合编辑、三栏海报创作、高级布局和导出参数、批量导出和历史快照。小于 800px 不再尝试保留完整三栏，而采用单列页面或抽屉。

## 5. 数据和状态决策

### 5.1 Song 身份

所有歌曲关系使用不可变 song_id：歌曲编辑、删除和标记学会、直播队列、练习记录和演唱事件、Preset 手动集合、WorkspaceDocument、ExportSnapshot。

title 只作为显示字段和历史快照字段，不再作为长期关系主键。

### 5.2 工作台状态

~~~text
WorkspaceDocument
├── scene
├── songQuery
├── selectedSongIds
├── templateId
├── canvas
├── title / subtitle
├── parameters
├── exportSettings
└── updatedAt
~~~

UI 界面状态、服务请求状态和可撤销的文档状态必须分离。预览失败不能清空当前文档。

### 5.3 直播状态

QuickView 的正式模型为：

~~~text
LiveSession
├── id
├── startedAt
├── queue: song_id[]
├── currentSongId
├── playedSongIds
└── notes
~~~

localStorage 只作为现场缓存和离线补报队列，不作为唯一业务数据源。

### 5.4 导出状态

每次导出生成独立 ExportSnapshot，至少保存确切的 song_id 集合、标题快照、模板和渲染配置、画布和页数、生成时间、引擎版本和输出路径。

## 6. 实施优先级

### R0：正确性和状态契约

完成 tabs、queue、Preset 的 song_id 关系迁移；统一后端错误结构和前端加载/空/错误/重试状态；清理不可用一级导航；保持金标准 16/16；同步 README、主规格和路线图状态。

### R1：首用和日常出图

样例数据和首次启动引导；SongQuery、场景和歌曲集合；模板而不是 Layout/Palette/Skin 的普通用户入口；工作台三步重复出图流程；magazine-flow 第一套正式场景；保存、恢复、导出失败重试。

### R2：直播闭环

QuickView 使用 song_id；LiveSession 和离线补报；桌面壳、置顶速查和生命周期诊断；移动端优先完成速查和队列，不做完整创作。

### R5：系统化体验

WorkspaceDocument 自动保存、撤销重做和离开保护；高级设置折叠；三断点响应式；WCAG AA、可见焦点、快捷键帮助和 reduced motion。

---

## 7. 明确暂不做

在 R1/R2 的真实使用证据出现前，暂不做：完整自由图片编辑器；单纯为了数量增加更多主题和布局；复杂统计大屏；手机端完整三栏编辑器；用 Song.pinned 表达主推歌曲；以标题作为队列、事件或附件主键；没有 ExportSnapshot 基础的导出历史重生成。

---

## 8. 验收门

- 新用户无需阅读文档即可用样例数据导出第一张海报；
- 用户能明确知道当前海报包含哪些歌曲；
- 修改歌曲标题不会破坏队列、曲谱、事件和学习记录；
- 预览、保存和导出失败都有可执行恢复动作；
- 390px 左右的移动端不出现桌面三栏横向裁剪；
- QuickView 核心操作可键盘完成；
- 普通用户不需要理解 Layout、Palette、Skin 才能出图；
- 旧 grid-wrap 继续保持 16/16 diff=0。
