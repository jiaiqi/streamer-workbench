## 1. 总览

| 方案 | 核心定位 | 主要贡献 | 主要不足 |
|---|---|---|---|
| v1 | 三视角产品审查 + 6+1 布局的轻量落地方案 | 产品论证最强；“演出后台”叙事；动效细节；先用内置布局验证、再决定编辑器的克制节奏 | Palette/Skin、桌面端、数据闭环和完整质量体系不足 |
| v2 | 布局子系统专项重构 | `analyze → plan → render` 契约；Shape、锚点、FreeformLayout、字体角色；“挑模板→微调→导出”动线最清晰 | 产品总闭环、Electron、响应式、无障碍、性能预算较弱 |
| v3 | 产品、UI/UX、架构、数据、桌面和质量的总规格 | Layout/Palette/Skin/Preset 四模型；工作台三模式；统计反哺创作；Electron；测试、性能、发布门最完整 | 范围过大；部分目标被写得像当前事实；命名和 Schema 与 v1/v2 有重复或冲突 |
| 终版 | 单一权威主规格 | v1 的产品判断与节奏 + v2 的布局技术细节 + v3 的完整产品与质量框架，并按代码事实纠偏 | 目标能力完整保留；执行改用 R0–R7 纵向切片控制范围 |

     + v2 的布局运行时和 Schema 细节

## 3. 产品定位与信息架构差异

| 维度 | v1 | v2 | v3 | 终版裁决 |
|---|---|---|---|---|
| 对外叙事 | 主播“演出后台” | 直播歌单工作台，日常面 + 创作面 | 音乐主播内容与直播运营工作台 | 对外用“主播演出后台”，产品定义用“音乐主播内容与直播运营工作台” |
| 是否重写 | 不重构 | 不推翻，专项重构布局 | 不整项目重写 | 明确“不整项目重写，重构扩展层” |
| IA | 保守收敛现有导航 | 5 项实功能，布局工坊独立 | 创作/资产/直播/洞察/设置五域 | 五域作为领域结构，侧栏保持 6 项以内；布局在创作域内 |
| 占位入口 | 倾向清理 | 主题并入创作、预设为配方、历史为抽屉 | 主题/预设/历史均发展为真实能力 | 不保留“敬请期待”长期占位；先在工作台内落地，再视复杂度独立页面 |
| Preset | 主题×布局×参数组合 | “我的配方” | 完整领域资源 | 采用完整 Preset 模型，但 UI 可称“场景预设/我的配方” |

### 3.1 终版保留

- v1 的“布局是内容保鲜机制”产品论证；
- v2 的“挑模板 → 微调 → 导出”创作主线；
- v3 的五领域结构和直播前、中、后闭环。

### 3.2 终版舍弃

- 把独立技术概念都做成一级导航；
- 长期保留无功能的主题/预设/历史入口；
- 将产品继续只描述成“背景换色的海报生成器”。

## 4. UI/UX 差异

| 维度 | v1 | v2 | v3 | 终版裁决 |
|---|---|---|---|---|
| 视觉方向 | 落地既有 v2 视觉 | 保留晨光纸感，还暗色/组件/动效债 | 保留视觉，系统重做工作台 | 保留晨光纸感；暗色是演出后台模式 |
| 工作台 | 布局和主题并列 | 模板卡 + 预览 + 语义参数 | 资源栏 + 三模式画布 + 属性检查器 | 采用 v2 动线与 v3 三栏/三模式结构 |
| 预览 | 强调 FLIP/过渡 | crossfade + draft/full + hash | 加 AbortController、可执行错误 | 三者合并，快速输入只接收最后结果 |
| 参数 | ParamSpec 扩展 | 内容/版面/主题微调 | 内容/布局/视觉/背景/导出 + 专家模式 | 采用五组语义检查器，底层 ParamSpec v2 |
| 对比 | 未定义 | 未定义 | 2/4 宫格 | 保留，进入 P5，不是首个布局引擎阻塞项 |
| 撤销重做 | 未定义 | 未定义 | 完整历史栈 | 必须实现；连续输入 300ms 内合并为一次操作 |
| 响应式 | 未定义 | 未定义 | 800/1100/1440 | 保留；桌面窗口也需要适配和面板记忆 |
| 无障碍 | 基础提及 | AA + reduced motion | 完整 WCAG AA | 采用 v3 完整基线和 v1 动效降级原则 |

### 4.1 动效裁决

- v1 的场景化动效细节作为实现参考；
- v3 的统一时长/曲线表作为规范；
- 不硬性禁止动画库；先用 CSS/FLIP，复杂共享布局动画经过 POC 后再决定是否引入 Motion；
- 动效不得掩盖渲染延迟，也不得因关闭动画破坏状态反馈。

## 6. 主题模型差异

| 维度 | v1 | v2 | v3 | 终版裁决 |
|---|---|---|---|---|
| Palette | 未系统定义 | 独立 palettes | 完整领域模型 | Palette v1 只承载现有 5 颜色角色 + font roles |
| Skin | anchors 为主 | theme 内 skins 覆盖 | 独立 Skin 资源 | Skin 负责背景、主体、锚点、避让、柔光和布局默认值 |
| 坐标 | 像素示例 | 像素 + anchor 表达式 | 0–1 归一化 + px 可选 | anchors/subjects 默认 0–1，像素只做兼容输入 |
| 回退 | 未定义 | skin → palette → 默认 | Preset → Skin → Palette → Layout → 系统 | 采用 v3 五级回退链 |
| 文件目录 | 旧 themes | palettes + theme 内覆盖 | palettes + skins + data | 顶层 `themes/` 继续兼容内置资源；新模型逐步引入，不在 P1 强删旧目录 |

### 6.1 Palette 角色范围裁决

v3 一次扩至 surface/border/accent/decoration 会要求大量无收益补值。终版 Palette v1 只包含：

```text
text / label / pill / line / mist
font_roles: title / label / song / note
```

布局扩展角色由 `extra_colors()` 声明，Skin 可按布局补充；通用 UI token 不混入海报 Palette。

## 8. 技术架构差异

| 维度 | v1 | v2 | v3 | 终版裁决 |
|---|---|---|---|---|
| LayoutPlugin | 三段式契约最明确 | Python + Freeform 双载体 | LayoutDefinition + LayoutDocument | `analyze → plan → render` + 元数据定义 + 双载体 |
| Shape | anchors 隐含 | rect/ellipse/polygon | 加 path/归一化 | v1 支持 rect/ellipse/polygon/path，统一归一化坐标 |
| Canvas | 去基准魔数 | baseline + 任意尺寸 | logical/output scale、DPI | P0 先去魔数，P5 再增加 UI 新画布预设 |
| ParamSpec | 扩展建议 | slider/preset/color | 11 种 kind + 条件/分组 | 采用完整 v2，但按控件真实需求逐步实现 |
| server | app.state | deps + routers | services + routers | 先 deps，后 routers，再按复杂度提 service，路径不变 |
| Schema | 较少版本约束 | `schema: 1` | schemaVersion + 迁移 | 所有用户持久格式必须版本化、备份、可迁移 |
| 用户目录 | 未展开 | 简要提及 | Electron 完整外置 | P1 做 ADR，P7 正式落地；开发期仍兼容项目根 data |

### 8.1 `grid-wrap` 分页裁决

v2/v3 的自动分页和背景策略不应改变旧金标准：

- `grid-wrap` 兼容模式继续固定 `pages = 2`；
- 新布局可使用 `pages = auto`；
- `fixed/cycle/extend` 背景策略只对声明支持的布局启用；
- `grid-wrap` 固定两页作为兼容模式不参与自动策略；
- 未来若升级 grid-wrap 自动分页，必须作为独立版本 `grid-wrap-v2` 或显式兼容开关，不能静默改变历史预设。

### 8.2 `Song.pinned` 裁决

不新增 `pinned` 字段。主推来源按优先级：

1. Preset 手动歌曲集合；
2. 最近学会；
3. 点歌/演唱热度；
4. 用户自定义歌单。

避免为单一布局污染核心 Song 模型。

### 10.1 性能预算裁决

目标值保留，但必须区分“候选目标”和“已测基线”：

| 指标 | 候选目标 | 冻结时机 |
|---|---:|---|
| draft 热预览 P95 | ≤ 100ms | R1 首个新场景具备 draft 后实测 |

未测量前不得在状态文档中写成“已经达到”。
