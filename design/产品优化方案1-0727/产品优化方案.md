## 一、产品经理视角：产品设计审查

### 1.1 核心判断：产品已经不是"海报生成器"了

| 维度 | 起步时（7/23） | 现在（7/27） |
|---|---|---|
| 定位 | 歌单 → PNG 海报的工具 | 主播演出全周期工作台 |
| 用户旅程 | 做海报 → 发出去 | 直播前（学歌/备谱/做海报）→ 直播中（速查/点歌/看谱）→ 直播后（复盘） |
| 数据资产 | 无 | 178 首结构化曲库 + events.jsonl 事件流 + 曲谱附件 + 今晚歌单行为数据 |
| 代码事实 | engine 单功能 | 23 端点 + 4.5 个视图 + 速查窗 + 曲谱管理 |

三条用户旅程的当前覆盖度：

| 旅程 | 覆盖度 | 已闭环的能力 | 缺口 |
|---|---|---|---|
| 直播前（备） | 80% | 曲库增删改、学歌管理、曲谱附件、海报导出 | **布局保鲜（本方案核心）**、学歌打卡（S4） |
| 直播中（演） | 90% | 拼音速查、大字选调、点歌队列、T 键看谱、事件沉淀 | 全局热键/置顶壳（Phase 4 Electron） |
| 直播后（复盘） | 10% | 原始事件流已沉淀 | 统计视图、更新记录 feed（S5） |

### 1.2 判决：不重构产品，做"正名 + 收敛"

重构（推翻重来）不成立的理由：
1. 核心旅程 80-90% 已闭环，推翻等于丢掉已验证的资产；
2. 数据模型（Song/事件流/曲谱）与真实使用场景咬合良好，没有方向性错误；
3. 问题集中在"表达层"（UI 风格不统一、海报形式单一），不在"能力层"。

**建议的产品定义（收敛后）：**

```
直播弹唱主播的「演出后台」
├─ 内容生产：海报 = 主题(皮肤) × 布局(信息结构) × 画布(比例)
├─ 演出执行：速查选调 / 点歌队列 / 看谱
├─ 能力管理：曲库 / 学歌 / 曲谱
└─ 经营复盘：统计 / 更新记录
```

对外（对内亦然）沟通时逐步弃用"海报生成器"一词——它让新功能（点歌/学歌/统计）看起来像"跑偏"，实际上海报只是四大板块之一。

### 1.3 布局需求的产品论证（为什么升 P0）

海报是**给观众看的内容**，不是给自己看的工具。观众每周看同一张歌单：

- 第 1 周：新鲜，点歌率高；
- 第 3 周：视觉习惯，扫一眼就过；
- 第 5 周：审美疲劳，"还是那些歌"。

主题（皮肤）只能换氛围，**布局（信息结构）才能制造"这周歌单不一样了"的新鲜感**。因此布局套件的本质是**内容保鲜机制**，直接影响点歌率（直播间的核心指标），应与 Phase 5 同级为 P0，而非"以后再说"的增强。

### 1.4 功能缺口清单（按旅程排优先级）

| 优先级 | 缺口 | 所属旅程 | 说明 |
|---|---|---|---|
| 🔴 P0 | **布局套件 + 自定义布局** | 内容生产 | 本方案第四节，详见 |
| 🟡 P1 | S5 统计视图 + 更新记录 feed | 直播后 | 数据地基已就绪（S1-S3），只差兑现 |
| 🟡 P1 | S4 学歌打卡 | 直播前 | 小功能，为统计提供第二数据源 |
| 🟡 P1 | 海报信息升级 | 内容生产 | 新歌角标 / 本周主打 / 热度标记（事件流已能支撑） |
| 🟢 P2 | 组合预设（主题×布局×参数） | 全程 | 顺手消化"场景预设"占位视图 |
| 🟢 P2 | Phase 4 正式 Electron 壳 | 直播中 | spike 已过，剩工程化 |
| ⏸️ 暂缓 | "导出历史"占位视图 | — | 将被 S5 更新记录 feed 覆盖，届时直接删除 |

## 二、产品 + UI/UX 视角：需要改动还是重新设计

### 2.1 判决：不做第三次重设计，落地 v2 并补 4 项

UI 已经历三代：v0 晨光纸感（线上）→ v1 演出后台（交互稿）→ v2 评审优化稿（交互稿，`design/redesign-v2.html`）。v2 已正确回答场景问题（暗色后台、直播三区、WCAG AA、状态双编码、空/加载状态）。**当前真正的问题是 v2 零行代码落地，设计债务在积压**——再开一轮重设计只会让"设计稿永远比代码新"的循环继续。

落地顺序（沿用 v2 改动说明里的既定路径）：
`token + 共享组件 → 歌曲库/学歌 → 工作台 → 直播模式`，每步类型检查 + 截图回归。

### 2.2 v2 未覆盖项 ①：布局选择器（本次新需求的 UX）

布局是与主题**平行的选择维度**。工作台左栏改两段式：

```
┌────────────────┐
│ 主题 · 7        │   现有紧凑行式（缩略块+名称）
│ ┌────┐卡通音符  │
│ └────┘奶油玻璃  │
│  …              │
│ ────────────── │
│ 布局 · 6+1      │   新增：骨架线稿缩略图（非海报缩略图，
│ ▦ 网格绕排      │        用线条示意信息结构，8×14 小图标）
│ ◎ 唱片环绕      │
│ ☁ 云流          │
│ ▤ 杂志瀑布      │
│ ✦ 手账拼贴      │
│ ★ 本周主打      │
│ ⚙ 我的布局 · 新建│
└────────────────┘
```

交互细节：
- 选中布局 → 预览区 300ms 内重排（动效见 2.4）→ 右侧参数面板切换为该布局 ParamSpec（架构已支持，`/api/layouts/{id}/params`）；
- 布局项 hover 显示一句话定位（"环绕背景焦点，最出片"）；
- 「主题×布局×参数」可存为预设（P2），预设行出现在两栏顶部；
- 布局缩略骨架图随布局插件自带（插件提供 `thumbnail_svg` 字段，保证新增布局自动出现）。

### 2.3 v2 未覆盖项 ②：自定义布局编辑器（本项目最复杂的 UI）

形态：**画布上直接操作的所见即所得编辑器**（不是表单填参）。

```
┌──────────────────────────────────────────────┐
│ 工具条：▭ 矩形区  ◯ 圆形区  ◎ 环形区  │ 试渲染 保存 │
├──────────────────┬───────────────────────────┤
│                  │ 选中区域属性：              │
│   （海报预览      │  绑定内容 [分组:热门▼]      │
│    画布，直接     │  流式    [环绕▼]           │
│    拖拽出区域，    │  起始角  [-90°]           │
│    锚点吸附       │  字号    [34] 衰减 [0.9]   │
│    背景焦点       │  对齐    [沿环▼]           │
│    以磁力线显示）  │  ───────                   │
│                  │  [删除此区域]               │
└──────────────────┴───────────────────────────┘
```

- 区域三种形状：矩形 / 圆形 / 环形（对应三类流式：网格、圆周、弧线带）；
- 拖动时吸附主题 anchors（焦点、安全区边缘），磁力线反馈；
- 「试渲染」调 `/api/render` 草稿模式（skip_text=false + 布局草稿参数）实时出图；
- 保存 → 写 `data/layouts/{name}.json` → 出现在布局列表（⚙ 标识可编辑/删除）；
- 越界校验：保存前服务端冒烟渲染，内容溢出区域时高亮问题区域并拒绝保存。

### 2.4 v2 未覆盖项 ③：动效系统（"丝滑流畅"的完整规格）

现状几乎无动画（仅学歌卡片入场 stagger）。定义全站统一动效语言：

| 场景 | 动效 | 时长/曲线 | 实现 |
|---|---|---|---|
| 海报重排（切主题/布局/调参） | 旧内容 opacity→0（120ms）→ 新内容 scale(.96→1)+淡入 | 120ms ease-in + 220ms ease-out | CSS transition，双阶段 |
| 视图切换 | 内容区 translateY(8px→0)+淡入；侧栏选中态滑动 | 200ms / 150ms ease-out | CSS |
| 卡片展开/收起 | 网格行高动画 + 展开内容延迟 80ms 淡入 | 250ms spring-ish（cubic-bezier(.22,1,.36,1)） | CSS grid + transition |
| 点歌入队 | 从结果行 FLIP 飞入今晚队列 | 300ms | FLIP（getBoundingClientRect 手算，不引库） |
| 标记唱完 | 卡片下沉 6px + 划线扫过 + 落位"已唱"区 | 350ms | CSS + FLIP |
| 打卡成功 | 便签上盖"已打卡"戳（scale 1.4→1 + 旋转 -8°） | 200ms ease-out-back | CSS |
| 导出完成 | 底栏按钮 ✓ 脉冲一次 | 400ms | CSS keyframes |
| 全局降级 | `prefers-reduced-motion` 全部时长归 0.01ms | — | 已在 v2 token |

原则：动画必须传达状态因果（从哪来、到哪去），杜绝纯装饰动画；时长全部落在 150–350ms 感知甜区；不引动画库（FLIP 手算约 40 行），后续若有复杂编排再评估 Motion。

### 2.5 v2 未覆盖项 ④：海报信息升级（配合布局引擎）

事件流已能支撑的信息，布局引擎渲染时可读：

- **新歌角标**：`added_at` 距今 ≤30 天 → 歌名旁 amber 小三角（可关）；
- **热度标记**：`song_sung` 事件 TOP10 → 歌名旁小火苗/数字（L3 云流版直接以热度定字号）；
- **本周主打**：手动置顶或自动取最近 `song_learned`（L6 主打版的核心数据）；
- **页脚信息带**：可选显示"已会 N 首 · 更新于 M 月 D 日"（运营感，默认关）。

## 三、系统架构师视角：技术方案符合产品需求吗

### 3.1 健康的部分（不动）

- **渲染管线分层正确**：背景底版缓存（`_BG_CACHE`）与文字层分离，调参只重排文字（热渲染 33.8ms）；
- **插件注册表 + ParamSpec**：UI 参数面板由插件自描述驱动，加布局不用改 UI 骨架；
- **DrawContext 零件思路**：`base.py` 注释即预言——"新排版只写布局差异"；
- **数据层**：songs.json v4 迁移链、events.jsonl、tabs 存储，全部健康，本方案零改动；
- **金标准纪律**：独立预言机 + 版本化参照图，是敢动引擎的底气。

### 3.2 契约 v2：现有插件契约撑不起"自由布局"

现有契约是 `categorize() → render_page(ctx)` 两段式，隐含假设是"分组列表自上而下排"。自由布局（环绕/云流/拼贴）的思维模型是"**画布坐标 + 区域 + 约束**"。升级为三段式：

```python
class LayoutPluginV2(ABC):
    id: str; name: str; pages: int | None
    supports_avoidance: bool
    thumbnail_svg: str            # 布局选择器骨架线稿（2.2 节）

    def params(self) -> list[ParamSpec]: ...

    def analyze(self, library, events) -> LayoutInput:
        """数据准备：分组/热度/新歌标记。events 用于热度权重（可选）。"""

    def plan(self, inp: LayoutInput, spec: CanvasSpec, anchors: ThemeAnchors) -> LayoutPlan:
        """产出可序列化的布局方案：每个元素 = {text, x, y, angle, size, zone_id}。
        纯函数，不碰 PIL。可 dump JSON 供调试/编辑器预览。"""

    def render(self, ctx: DrawContext, plan: LayoutPlan) -> int:
        """只负责把 plan 画出来。返回内容结束 y（质检）。"""
```

收益：
- **plan 可序列化** → 自定义布局 = "一份 JSON plan 模板"，编辑器可直接消费/产出；
- plan 阶段可单测（断言坐标不越界、不重叠），不必逐像素；
- grid-wrap 迁移到新契约时必须保持金标准 16/16 diff=0（兼容性护栏）。

### 3.3 主题锚点元数据（"绕背景元素排字"的技术前提）

引擎目前不知道背景里唱片/花环在哪。theme.json 增加：

```json
{
  "anchors": {
    "1": {"focal_point": [540, 820], "focal_radius": 300,
          "clear_zones": [[60, 120, 1020, 300]],
          "safe_band": [100, 1450]},
    "2": {"focal_point": [540, 700], "focal_radius": 260,
          "clear_zones": [], "safe_band": [100, 1500]}
  }
}
```

- `focal_point/radius`：环绕类布局（L2/L3）的吸附圆心；
- `clear_zones`：背景留白区，自由布局优先填充；
- `safe_band`：内容允许存在的 y 区间（替代魔数 content_offset）；
- 7 套主题 × 2 页 = 14 份标注，B2 阶段人工标注（一次性工作，用预览图目测即可，误差容忍 ±40px）。

### 3.4 绘制零件库扩展（core/context.py）

| 新零件 | 签名 | 说明 |
|---|---|---|
| 弧形文字 | `draw_text_on_arc(text, cx, cy, r, start_angle, font, fill, letter_spacing)` | 逐字符沿圆弧摆放（PIL 无曲线文字，需逐字 rotate+paste）；字符级碰撞回退 |
| 旋转文字 | `draw_text_rotated(text, x, y, angle, font, fill)` | 便签拼贴用；小图 rotate(resample=BICUBIC) 后 paste |
| 区域流式填充 | `flow_fill(items, zone, font_range, weight_fn, seed)` | 云流/拼贴核心：贪心放置 + AABB 碰撞检测 + anchors 避让；seed 保证确定性 |
| 角标/徽章 | `draw_badge(x, y, kind)` | 新歌三角、热度火苗 |

### 3.5 魔数治理（借契约 v2 顺手做）

坑位 #11-14（避让降字号 34、content_offset 基准 1920、mist 底边、page_capacity 类属性）在自由布局下会放大错误。原则：**一切像素常量按画布高度比例归一化**（基准 1920 存为常量 `REF_HEIGHT=1920`，所有布局坐标定义在参考系，渲染时按比例映射到实际画布）。

### 3.6 金标准回归矩阵策略

7 主题 × 6 布局 × 2 页 = 84 组合，全锁像素不现实：

| 层级 | 覆盖 | 断言 |
|---|---|---|
| 金标准（逐像素） | 每布局 × 2 个代表主题 × 2 页（≈16-24 张新增） | diff=0 |
| 契约冒烟（全部组合） | 7 主题 × 全布局 × 2 页 | 渲染不炸 + 返回 y 在 safe_band 内 + plan 无重叠（碰撞报告为空） |
| 自定义布局 | 保存时服务端冒烟 | 越界拒绝 + 高亮问题区域 |

### 3.7 服务层小改

- 自定义布局 CRUD：`GET/POST/DELETE /api/layouts/custom`（读写 `data/layouts/*.json`，加载时 JSON Schema 校验）；
- 启动扫描 `data/layouts/` 把 DeclarativeLayout 实例注入 REGISTRY（与代码插件同权）；
- server 全局态（themes/library，坑 #9）在做布局 CRUD 时顺手收口为 app.state 依赖注入，为编辑器测试铺路。

## 四、布局系统规划（6 套内置 + 1 套自定义）

### L1 `grid-wrap` 全行网格绕排（现有，默认款）
- **定位**：信息量最大的经典目录；首次使用默认选中
- **迁移**：B1 阶段原样迁到契约 v2，金标准 16/16 diff=0 不许破

### L2 `vinyl-rings` 唱片环绕版 ⭐ 差异化主力
- **形态**：歌名沿同心圆弧排列，环绕 `anchors.focal_point`（唱片/花环/月亮）
- **内容编排**：内环 = 热度 TOP（song_sung 加权），外环 = 其余按分组；分组标签变环上刻度（如"二字·36"沿起点角摆放）
- **参数**：起始角（默认 -90°）、环数（2-4）、环间距、字号沿环衰减、单环最大容量
- **适配主题**：轻复古唱片（天作之合）、奶油花园、梦幻海洋
- **风险**：歌名长短不一导致弧上密度不均 → 字符宽度积分摆放 + 超长歌名缩字号降级

### L3 `free-flow` 云流版
- **形态**：标签云式自由流，字号按权重（热度/新歌/随机）三档以上，flow_fill 贪心填充 clear_zones
- **参数**：字号范围（24-56）、密度、权重来源、随机种子（默认歌单 hash，固定可复现）
- **适配主题**：全部（最百搭的自由款）
- **风险**：贪心放置可能留白难看 → seed 内尝试 N=50 次取覆盖率最优解（毫秒级）

### L4 `cascade` 杂志瀑布版
- **形态**：2-3 竖列瀑布，分组标签竖排贴列侧；长歌名不再被格子截断
- **参数**：列数、列间距、标签朝向（左/右/无）、列内对齐（顶/居中）
- **适配场景**：曲库 200+ 首、长歌名占比高时替代 grid-wrap

### L5 `scatter` 手账拼贴版
- **形态**：每首歌一张便签卡，确定性随机（seed=歌名 hash）微旋转 ±4°、错落拼贴；便签底色吃主题 extra_colors（卡片底/胶带色）
- **参数**：旋转幅度、卡片尺寸（随歌名长度自适应）、重叠容忍度、每页容量（自动分页）
- **适配主题**：卡通音符、青提气泡（软萌系）
- **风险**：重叠遮挡 → 碰撞检测 + 最大 3 次重试后缩小卡片降级

### L6 `stage` 本周主打版
- **形态**：上 1/3 超大字主推区（1-3 首，手动置顶或自动取最近 song_learned）+ 下 2/3 紧凑全库
- **产品价值**：海报从"目录"变"节目单"，引导观众点新歌
- **参数**：主打数量、主推区高度比、主打字号、全库区列数/字号
- **数据源**：`Song.pinned`（新增可选字段，编辑对话框加"置顶主打"开关）或自动规则

### L0 `custom` 自定义布局（声明式）

**Schema**（存 `data/layouts/{name}.json`）：

```json
{
  "version": 1,
  "id": "my-wreath",
  "name": "我的花环版",
  "pages": 2,
  "zones": [
    {"id": "z1", "shape": "ring",
     "cx": 540, "cy": 900, "r0": 260, "r1": 500,
     "flow": "arc", "start_angle": -90,
     "bind": {"source": "hot", "limit": 20},
     "font": {"size": 34, "decay": 0.9}},
    {"id": "z2", "shape": "rect",
     "x": 80, "y": 1400, "w": 920, "h": 800,
     "flow": "columns", "cols": 2,
     "bind": {"source": "all", "exclude_used": true},
     "font": {"size": 28}},
    {"id": "z3", "shape": "circle",
     "cx": 540, "cy": 900, "r": 200,
     "flow": "center",
     "bind": {"source": "literal", "text": "欢迎点歌"},
     "font": {"size": 44}}
  ],
  "label_style": {"position": "zone_edge", "size": 40}
}
```

**bind source 词汇表**：`all`（全部 active）/ `group:N`（字数分组）/ `hot`（song_sung TOP）/ `new`（近 30 天新增）/ `manual`（手动歌单，另存歌曲清单）/ `literal`（固定文案，主播名/欢迎语）/ `rest`（未被前面区域用掉的）；`exclude_used` 保证多区域不重复。

**校验规则**：加载时 JSON Schema 校验字段与取值域 → 保存时服务端冒烟渲染，plan 越界/重叠则 400 返回问题区域 id。

## 五、风险登记与待拍板决策

### 风险

| # | 风险 | 等级 | 应对 |
|---|---|---|---|
| R1 | grid-wrap 迁契约 v2 时像素漂移 | 中 | 金标准 16/16 是硬门槛，不破才许提交；先写契约再迁移，迁移 PR 只含重排不含量纲修改 |
| R2 | 弧形文字渲染质量（逐字旋转锯齿） | 中 | 4x 超采样渲染文字层再降采样；零件库统一处理 |
| R3 | anchors 人工标注误差 | 低 | 容忍 ±40px（布局算法对圆心偏移不敏感）；编辑器里加"锚点调试视图"可视化校准 |
| R4 | flow_fill 贪心结果不稳定 | 低 | seed 固定 + N 次尝试取最优，单测锁定种子结果 |
| R5 | 自定义布局被玩坏（重叠/溢出） | 中 | 保存即冒烟渲染，拒绝并可视化标注问题区域 |
| R6 | 布局编辑器复杂度失控 | 中 | 编辑器 MVP 只做矩形+环形两类区域、三类流式，圆形/复杂路径后置 |

### 待拍板

1. **L6 主打的"手动置顶"是否值得给 Song 加 `pinned` 字段**（还是只做自动规则：最近学会+热度加权）？——建议先做自动规则，不加字段；
2. **自定义布局编辑器的优先级**：先做 L2-L6 内置款验证布局需求强度，编辑器（B5）是否随之启动？——建议 B3 上线后用一周，若布局切换确实高频则 B5 提前；
3. **"导出历史"占位视图**：S5 更新记录 feed 落地后直接删除？——建议删除，导航保持 5 项上限。
