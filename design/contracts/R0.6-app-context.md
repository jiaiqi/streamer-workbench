## 1. 目标与阶段边界

本工作包把服务端从“导入时构造单例应用 + 模块级可变路径”改为显式的应用实例：

```text
AppConfig → resolve AppPaths → create_app(config)
                              ↓ lifespan
                         AppContext
                              ↓
                    当前请求 / 显式后台任务
```

目标：

1. 一个进程可创建多个路径完全隔离的 FastAPI app；
2. Router 只从当前请求取得 `AppContext`，不读取模块级路径或任务全局；
3. 初始化和关闭统一由 lifespan 管理；
4. `uvicorn server.main:app` 在迁移期继续可用；
5. R0.9 的平台默认目录、覆盖优先级与安全切换建立稳定契约。

本工作包不做：

- 不在 R0.5 关闭前开始代码实现；
- 不提前完成 R0.7 Repository 原子写、锁、崩溃恢复或 EventStore 索引；
- 不提前完成 R0.8 Pydantic/OpenAPI 类型生成；
- 不实现 R0.10 会话令牌、Electron CSP 或正式桌面壳；
- 不改变 `core/` 渲染输出、`grid-wrap` 或金标准；
- 不在测试中迁移或覆盖仓库真实 `data/`；
- 不允许 React/Electron 直接写核心用户数据。

## 2. 核心类型

### 2.1 AppConfig

`AppConfig` 是进程启动输入，不是用户目录内的 `settings.json`。建议使用冻结 dataclass：

```python
@dataclass(frozen=True)
class AppConfig:
    project_root: Path
    mode: Literal["development", "desktop", "test"] = "development"
    data_root: Path | None = None
    startup_config_path: Path | None = None
    host: str = "127.0.0.1"
    allowed_origins: tuple[str, ...] = ()
```

不变量：

- `project_root` 指向只读内置资源根；
- `data_root` 是显式覆盖，必须规范化为绝对路径；
- `mode=test` 必须显式给出临时 `data_root`，禁止回退到真实用户目录；
- `host` 的 loopback 强制和 Origin 策略由 R0.10 完成，本阶段不得设计成阻碍该安全层；
- 配置对象不保存 Repository、FastAPI app 或运行中任务。

### 2.2 AppPaths

`AppPaths` 是从单个已解析 `data_root` 派生的冻结值对象：

```python
@dataclass(frozen=True)
class AppPaths:
    project_root: Path
    themes_dir: Path
    palettes_dir: Path
    skins_dir: Path
    fonts_dir: Path
    data_root: Path
    songs_json: Path
    events_jsonl: Path
    settings_json: Path
    tabs_dir: Path
    presets_dir: Path
    layouts_dir: Path
    backups_dir: Path
    output_dir: Path
    startup_config_path: Path
```

边界：

- `themes/palettes/skins/fonts` 位于 `project_root`，按内置只读资源处理；
- `songs/events/settings/tabs/presets/layouts/backups/output` 全部位于同一 `data_root`；
- 路径派生函数是纯函数，不创建目录、不读写文件；
- 所有路径先 `expanduser()`、再绝对化/规范化；
- 不把 `data_root` 保存进该目录内的 `settings.json`，避免循环自定位。

### 2.3 AppContext

`AppContext` 是单个 app 实例的运行时依赖容器：

```python
@dataclass
class AppContext:
    config: AppConfig
    paths: AppPaths
    song_repository: SongRepository
    event_store: EventStore
    preset_repository: PresetRepository
    settings_repository: SettingsRepository
    render_service: RenderService
    export_job_manager: ExportJobManager
    themes: Mapping[str, Theme]
```

R0.6 可以用现有数据对象的临时适配器填充尚未完成的 Repository port，但 Router 的取用方式必须一次切到 `AppContext`。上下文只挂到 `app.state.context`；不得同时维护另一套模块全局真相。

## 3. create_app 与 lifespan

公开入口：

```python
def create_app(config: AppConfig | None = None) -> FastAPI: ...
```

`create_app` 只完成：

1. 解析/校验启动配置和 `AppPaths`；
2. 创建 FastAPI、middleware、静态挂载和 Router；
3. 注册 lifespan 工厂；
4. 返回尚未启动的 app。

lifespan 启动顺序：

1. 只读校验内置资源路径；
2. 校验或初始化用户数据目录的标准结构；
3. 构造 Repository/Store；
4. 加载 settings、songs、themes 等实例状态；
5. 构造应用服务和 `ExportJobManager`；
6. 原子地设置 `app.state.context`；
7. 服务才进入 ready。

关闭顺序：

1. 停止接收新后台工作；
2. 请求导出任务正常结束或取消，并等待有界时间；
3. 刷新/关闭需要收尾的 Store；
4. 释放执行器和文件资源；
5. 清除当前 app 的 context 引用。

任一步启动失败都不得留下“部分 ready”的 app、后台线程或对真实数据的半初始化写入。

## 4. 请求与后台任务依赖规则

- 提供唯一依赖 `get_app_context(request) -> AppContext`；
- Router 可从 context 获取应用服务，不直接拼接文件路径；
- Router 不 import `ROOT/DATA_ROOT/SONGS_JSON/EVENTS_JSONL/TABS_DIR`；
- 应用服务协调领域修改、Repository 写入、事件追加和缓存失效；
- 后台任务在创建时显式接收依赖及冻结输入；
- 后台任务不得通过模块变量、`request.app` 或运行中可变 `SongLibrary` 回取状态；
- 静态资源挂载目录由该 app 的 `AppPaths` 决定，不共享可变路径变量。

## 5. 数据目录解析优先级

由高到低：

1. `AppConfig.data_root`（CLI/测试/桌面父进程显式传入）；
2. 专用环境变量 `STREAMER_WORKBENCH_DATA_DIR`；
3. 平台启动配置中记录的 `data_root`；
4. `mode=development` 时使用 `{project_root}/data`；
5. desktop/production 使用平台默认目录。

平台默认目录：

| 平台 | 默认值 |
|---|---|
| Windows | `%APPDATA%/streamer-workbench` |
| macOS | `~/Library/Application Support/streamer-workbench` |
| Linux | `${XDG_DATA_HOME:-~/.local/share}/streamer-workbench` |

平台启动配置与用户数据分离，其默认位置由后续实现按平台配置目录确定。未知/空环境变量视为未设置；相对路径不静默依赖当前工作目录，必须相对于有明确定义的基准解析或直接拒绝。

## 6. 目录验证与切换契约（R0.9）

目录分类：

- `empty`：空目录，可初始化标准结构；
- `workspace`：结构和 Schema 合法，可直接使用；
- `legacy`：识别为可迁移旧版本，必须先 dry-run；
- `unknown`：包含未知冲突内容，不自动接管；
- `invalid`：不可读写、非目录、路径冲突或 Schema 损坏。

切换流程：

1. 规范化目标绝对路径；
2. 只读探测和分类；
3. 在目标旁或安全临时位置验证读写能力；
4. 如需迁移，先备份源数据，再复制到临时目录；
5. 在临时目录完成 Schema、数量、哈希和引用校验；
6. 原子发布目标数据；
7. 原子更新平台启动配置；
8. 明确返回“重启后生效”，不热切换当前 context；
9. 重启失败时继续使用旧启动配置和旧数据目录。

禁止：

- 先更新启动配置再验证目标；
- 在源目录上就地破坏性迁移；
- 失败后留下指向半迁移目录的配置；
- 自动合并未知目录中的同名文件；
- 由浏览器 `showDirectoryPicker` 或 Electron 通用文件 API直接管理核心数据。

## 7. 多 app 与测试隔离不变量

同一进程中 app A 与 app B：

- 拥有不同 `AppContext` 和 `AppPaths`；
- songs/settings/events/tabs/presets/export jobs/cache 不共享可变对象；
- A 的写入、事件和后台任务不会出现在 B；
- 关闭 A 不影响 B；
- import `server.main` 或 Router 不创建用户目录、不加载真实数据、不启动线程；
- 测试只能使用测试提供的临时目录；
- 测试顺序变化和并行运行不改变结果。

## 8. 兼容启动

保留：

```bash
uvicorn server.main:app --reload --port 8000
```

`server.main:app` 只能是：

```python
app = create_app(AppConfig.from_environment(mode="development"))
```

兼容入口不得重新引入模块级路径真相。CLI/Electron 后续可直接调用 `create_app(explicit_config)`。旧 API 路径在本阶段保持兼容；仅替换依赖来源，不改变响应和渲染语义。

## 9. 文件所有权

```text

tests/（AppContext、应用工厂、隔离和兼容回归）
README.md / ADR-003.md / ADR-005.md（仅实现事实确需同步时）
```

角色 B 在 R0.7 默认拥有：

```text
server/repositories/ 或 infrastructure/repositories/
Repository port/adapter 测试
并发写、原子替换、崩溃恢复、EventStore 索引
```

共享接口在编码前由角色 A 冻结。角色 B 不修改 `create_app/AppContext/AppPaths` 公共字段；需要调整时先提交契约变更。双方不得同时修改同一 Router。

## 11. 测试矩阵

### 11.1 AppConfig / AppPaths

- 各平台默认路径算法（mock platform/env）；
- 五级优先级逐项覆盖；
- 空环境变量、`~`、Unicode、空格和相对路径；
- `mode=test` 未指定 data_root 时立即失败；
- 只读资源与可写数据路径不混用；
- 路径解析纯函数不创建目录。

### 11.2 create_app / lifespan

- 调用 `create_app` 本身不写盘、不启动线程；
- lifespan enter 后 context 完整且 ready；
- 初始化中途失败无残留任务/半 context；
- lifespan exit 关闭任务与资源；
- `server.main:app` 可由 uvicorn 导入；
- Router import 无真实数据副作用。

### 11.3 多 app 隔离

- 两个临时 data_root 同时启动；
- A 新增/改名/删除歌曲，B 不变；
- A 上报事件，B 的 events 不变；
- A 上传/删除曲谱，B 的 tabs 不变；
- A CRUD Preset/settings，B 不变；
- 导出 job id、进度、缓存彼此隔离；
- 关闭 A 后 B API 继续可用；
- 测试反向启动和关闭顺序结果相同。

### 11.4 目录验证与回滚

- 空目录初始化；
- 合法现有工作区加载；
- v4/v5 与 Event v1/v2 的识别和迁移交接；
- 无权限、文件代替目录、损坏 JSON、未知文件冲突；
- dry-run 零写入；
- 迁移失败保留源和旧启动配置；
- 原子更新启动配置；
- 重启后生效，当前 app 不热切换；
- 重复执行幂等；
- 路径穿越和符号链接边界有明确策略及测试。

### 11.5 兼容与回归

- 现有 API 路径和响应关键字段不变；
- 旧 `grid-wrap` 金标准 16/16 `diff=0`；
- Python 单元测试全部通过；
- TypeScript `tsc --noEmit` 通过；
- 不出现 `core/` 对 FastAPI/Electron/React 的依赖。
