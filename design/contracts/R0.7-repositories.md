# R0.7 实施契约：Repository 可靠性与冻结导出输入

> 状态：接口草案冻结；依赖 R0.6 公共接口最终冻结后实施
> 主责角色：角色 B（Repository ports、文件适配器与可靠性测试）
> 集成角色：角色 A（AppContext、应用服务、RenderDocument builder 与导出任务）
> 创建日期：2026-07-29
> 上位依据：ADR-003、ADR-005 决策 1/2/3/4/6、路线图 R0.7、R0.6 AppContext 契约

## 1. 目标与阶段边界

R0.7 将 songs、settings、presets 和 events 从分散的文件函数收口为显式 Repository
port 与文件系统 adapter，并建立单进程桌面应用所需的写入可靠性：

```text
Router → Application Service → Repository Port ← File Adapter → AppPaths
                                  ↓
                         不可变/脱离存储的快照

Export Service → RenderDocument Builder → frozen RenderDocument → background job
```

目标：

1. JSON 写入使用同目录临时文件、刷盘和原子替换；
2. 每个 Repository/Store 实例拥有自己的进程内锁；
3. 写前备份可恢复，保留策略确定且不会破坏当前提交；
4. Preset 内容和 manifest 在同一受锁操作中提交，并能从任意崩溃点恢复一致；
5. EventStore 启动时建立 `event_id` 索引，幂等补报不再逐次扫描 JSONL；
6. 预览/导出任务只消费冻结的 `RenderDocument`，不持有可变曲库、settings 或 AppContext；
7. 两个 app 的 Repository、锁、索引、缓存和任务完全隔离。

本工作包不做：

- 不改变 JSON/JSONL 为 SQLite，不引入数据库或跨进程锁服务；
- 不把业务规则搬进 Repository；改名、状态转换和事件语义仍由领域/应用服务负责；
- 不在 Router 中直接构造文件 adapter；
- 不完成 R0.8 Pydantic/OpenAPI/apiClient；
- 不完成 R0.9 数据目录切换；只消费当前 app 已解析的 `AppPaths`；
- 不修改 `grid-wrap`、主题、Palette 或 16 张金标准；
- 不在 R0.6 公共接口未冻结时修改 `AppContext/AppPaths/create_app`；
- 不让 React/Electron 成为核心用户数据写入者。

## 3. 分层与依赖规则

建议目录（最终名称可随 R0.6 包结构做一次机械调整，语义不得改变）：

```text

├── ports/
│   └── repositories.py
├── repositories/
│   ├── atomic_json.py
│   ├── songs.py
│   ├── settings.py
│   ├── presets.py
│   └── events.py
└── services/

    └── export.py
```

依赖方向：

- port 只依赖领域模型、标准库类型和本层错误；
- file adapter 实现 port，可依赖 `pathlib/json/os/threading`，不依赖 FastAPI；
- Application Service 依赖 port，不依赖具体 file adapter；
- Router 只调用 Application Service；
- `core/` 不 import `server/`、FastAPI 或文件 adapter；
- adapter 不读取 `request.app`、`server.deps`、进程环境变量或模块级路径；
- 每个 adapter 构造函数必须显式接收其路径和可靠性配置。

## 4. 共享 port 类型与错误

### 4.1 版本化快照

读操作返回脱离 adapter 内部可变状态的快照：

```python
@dataclass(frozen=True)
class StoredSnapshot(Generic[T]):
    value: T
    revision: str
```

- `value` 不得与 adapter 内部缓存共享可变对象；
- `revision` 是当前规范化持久化内容的稳定摘要或等价不透明版本；
- 写入可携带 `expected_revision`，在同一锁内比较；不匹配时抛出冲突错误；
- 新文件的 revision 使用明确哨兵，不用文件 mtime 单独充当版本；
- 成功写入返回新 snapshot/revision；失败时旧 revision 保持有效。

R0.7 的进程内锁不承诺多进程并发写安全。正式桌面模式只允许一个 Python 写入权威；
若检测到已打开文件被外部修改，adapter 必须重新加载/重建索引或明确报冲突，不静默覆盖。

### 4.2 统一错误族

port 暴露可由应用服务映射的稳定错误，不泄漏 `JSONDecodeError/OSError` 作为业务契约：

```python
class RepositoryError(Exception): ...
class RepositoryNotFound(RepositoryError): ...
class RepositoryConflict(RepositoryError): ...
class RepositoryCorrupt(RepositoryError): ...
class RepositoryUnavailable(RepositoryError): ...
class RepositoryRecoveryRequired(RepositoryError): ...
```

- 错误保留原异常作为 cause，并包含安全的 path kind/operation/recovery 信息；
- 不在错误或日志中输出用户文件全文、会话令牌或不必要的绝对路径；
- R0.8 再把错误映射为统一 API `code/message/details/recovery`。

## 5. Repository ports

以下签名表达必须具备的能力；实现可使用 `Protocol`/ABC，但不得改变所有权语义。

### 5.1 SongRepository

```python
class SongRepository(Protocol):
    def load(self) -> StoredSnapshot[SongLibrary]: ...
    def save(
        self,
        library: SongLibrary,
        *,
        expected_revision: str | None,
    ) -> StoredSnapshot[SongLibrary]: ...
    def close(self) -> None: ...
```

- `SongLibrary` 的验证、v1→v5 迁移语义继续复用现有领域能力；
- 应用服务在快照副本上执行 add/update/remove，再以 expected revision 保存；
- adapter 不自行决定歌曲是否允许重名、ID 是否可改或是否追加领域事件；
- 首次把旧 Schema 持久化为 v5 前必须备份原文件；只读 load 不原地覆盖旧文件；
- 成功保存后返回重新读取/验证过的脱离快照。

### 5.2 SettingsRepository

```python
class SettingsRepository(Protocol):
    def load(self) -> StoredSnapshot[SettingsDocument]: ...
    def save(
        self,
        settings: SettingsDocument,
        *,
        expected_revision: str | None,
    ) -> StoredSnapshot[SettingsDocument]: ...
    def close(self) -> None: ...
```

- `SettingsDocument` 是验证后的值快照，不是跨请求共享的可变 dict；
- 未知字段的保留/拒绝策略必须由 Schema 明确，不能因一次局部更新静默丢字段；
- 更新采用“读取 revision → 复制并验证 → CAS 保存”，避免并发请求 lost update；
- `data_root` 不写入用户目录内 settings，遵守 R0.6 自定位边界。

### 5.3 PresetRepository

```python
class PresetRepository(Protocol):
    def list(self) -> StoredSnapshot[tuple[PresetSummary, ...]]: ...
    def get(self, preset_id: str) -> StoredSnapshot[Preset] | None: ...
    def save(self, preset: Preset, *, expected_revision: str | None) -> StoredSnapshot[Preset]: ...
    def delete(self, preset_id: str, *, expected_revision: str | None) -> bool: ...
    def duplicate(self, source_id: str, target: Preset) -> StoredSnapshot[Preset]: ...
    def recover(self) -> RecoveryReport: ...
    def close(self) -> None: ...
```

- ID 路径安全和 `custom_ids=song_id[]` 验证沿用 R0.5；
- `list()` 返回 manifest 的不可变摘要，不返回可被调用者修改的缓存 dict；
- 保存、删除、复制必须在同一 Repository 锁内更新内容与 manifest；
- `_default` 的删除/默认唯一性属于应用规则，不由文件 adapter 临时猜测；
- 删除保持可恢复：成功提交前不永久删除内容，使用 `.trash`/事务备份；
- `recover()` 只处理已知事务状态，不自动合并未知目录或静默丢弃孤儿。

### 5.4 EventStore

```python
class EventStore(Protocol):
    def append(self, event: EventV2) -> AppendResult: ...
    def get_by_id(self, event_id: str) -> EventV2 | None: ...
    def iter(self, query: EventQuery) -> Iterator[EventRecord]: ...
    def tail(self, *, limit: int, event_type: str | None = None) -> tuple[EventRecord, ...]: ...
    def flush(self) -> None: ...
    def close(self) -> None: ...
```

`AppendResult` 必须区分 `appended` 与 `already_exists`。相同 `event_id`：

- 等价内容返回已存在事件，不追加；
- 内容不同抛出 `RepositoryConflict`；
- 比较字段与 Event v2 当前幂等字段一致，不比较服务端 `recorded_at`；
- v1 历史事件可读但不伪造 event_id，不进入 v2 幂等索引。

## 6. 文件 adapter 构造与实例隔离

建议构造输入：

```python
FileSongRepository(path, backup_policy, atomic_writer)
FileSettingsRepository(path, backup_policy, atomic_writer)
FilePresetRepository(root_dir, backup_policy, atomic_writer)
JsonlEventStore(path)
```

每个实例：

- 只操作构造时传入的规范化绝对路径；
- 创建一个私有 `threading.RLock`，不得复用模块级 `_LOCK`；
- 不共享可变缓存、revision、事务目录、Event 索引或故障状态；
- 初始化/恢复由 R0.6 lifespan 调用，import 模块不读写文件；
- `close()` 幂等，关闭后写操作明确失败；
- 不在构造函数中回退到真实 data 目录；测试必须显式传临时路径。

Repository 锁的粒度是“单个公开操作及其全部文件步骤”。应用服务不得获取或持有内部锁，
也不得同时跨多个 Repository 锁形成隐式事务。跨 Repository 业务操作由应用服务明确排序，
并通过幂等命令/补偿事件处理；R0.7 不虚构文件系统跨仓储 ACID。

## 7. 原子 JSON 写入协议

所有 JSON adapter 共用同一可靠 writer，写入流程固定为：

1. 在目标文件同一目录创建唯一临时文件，权限不宽于目标策略；
2. 用 UTF-8、确定性字段/缩进规则写完整内容；
3. `flush()` 后对临时文件执行 `os.fsync()`；
4. 从临时文件重新读取并完成 JSON、Schema、计数/引用校验；
5. 如目标存在，按备份策略保存已验证的旧版本；
6. 使用 `os.replace(temp, target)` 原子发布；
7. 在平台支持时 fsync 父目录，保证目录项落盘；
8. 重新读取目标，计算新 revision，再返回成功；
9. 任一步失败清理本次临时文件，目标保持旧版本；
10. 清理过期备份只能在新目标验证成功后执行，清理失败只告警，不回滚已成功提交。

约束：

- 临时文件不得放到系统 `/tmp` 后跨文件系统 rename；
- 不使用“先 truncate 目标再写”或先删除目标的方案；
- `backup_count=0` 语义明确为禁用新备份，不删除非本 Repository 创建的文件；
- 备份名使用资源类型、UTC 高精度时间和唯一后缀，避免同秒覆盖；
- 备份内容写后校验，失败则不发布新目标；
- 备份目录来自当前 app 的 `AppPaths.backups_dir`，按 repository kind 分隔；
- Windows/macOS 的 replace、打开文件句柄和目录 fsync 差异必须封装并测试降级路径；
- 临时文件、事务标记和备份不得被普通 list API 当作业务数据。

## 8. 锁、revision 与并发语义

- 同一 Repository 的 load/save/list/get/delete/append/recover 均在私有锁内形成线性顺序；
- 锁覆盖“读当前 revision → 校验 expected revision → 备份 → 发布 → 更新缓存”的全过程；
- 返回调用者前复制/冻结领域对象，防止锁外修改内部状态；
- 两个线程基于同一 revision 写入时，恰好一个成功，另一个收到 conflict；
- 读取不得看到临时文件、半 JSON、Preset 半 manifest 或未完成的 Event 行；
- 锁不跨耗时渲染、网络或 UI 操作持有；
- Repository 内部不得回调应用服务，避免锁反转；
- 多 Repository 操作按应用服务规定的固定顺序执行，不嵌套访问 adapter 私有锁；
- 单进程限制必须写入 README/启动策略；发现第二写入进程时至少明确诊断，不宣称已支持。

## 9. Preset 跨文件一致性与恢复

Preset 的 `presets/{id}/preset.json` 和 `presets/manifest.json` 无法靠两次 `os.replace`
获得真正的多文件原子性，因此必须使用受锁的可恢复提交协议。

### 9.1 事务目录

Repository 私有目录建议为 `presets/.transactions/{transaction_id}/`，包含：

```text
transaction.json       # id、operation、preset_id、phase、目标摘要
preset.next.json       # save/duplicate 的完整新内容
manifest.next.json     # 完整新 manifest
before/                # 被替换内容/manifest 的可恢复副本或引用
```

事务文件本身也使用原子 JSON writer。`transaction_id` 不接受外部输入。

### 9.2 提交流程

在单个 PresetRepository 锁内：

1. 读取并验证当前 manifest、目标 preset、expected revision 和 ID 路径；
2. 生成完整 `preset.next` 与 `manifest.next`，验证双方摘要/字段一致；
3. 写入并 fsync 事务目录及 `prepared` 标记；
4. 保存所有将被替换/移动的 before image；
5. 原子发布 preset 内容；删除时只移动到事务可恢复区，不永久删除；
6. 原子发布 manifest；
7. 重新读取 preset 集合并验证“manifest ↔ 内容”不变量；
8. 把事务标记为 `committed` 并 fsync；
9. 提交完成后再把删除内容移入 `.trash`、清理旧事务和备份。

`list()`/`get()` 不得在未完成恢复时返回可能不一致的结果。

### 9.3 启动恢复

lifespan 构造 PresetRepository 后、app ready 前执行 `recover()`：

- 无事务标记：只读验证 manifest/内容一致；未知孤儿生成诊断，不自动删除；
- `prepared` 且没有任何目标发布：回滚/清理 staging，保留旧状态；
- 只发布 preset 或只发布 manifest：依据事务摘要幂等完成提交，或用 before image 回滚；
- 双方已发布但未标 committed：验证后补记 committed；
- 摘要不匹配、before image 缺失或状态未知：停止 ready，抛出 `RepositoryRecoveryRequired`；
- 重复执行 recover 必须幂等，不能创建第二份 preset、重复 trash 或丢失 manifest 项。

manifest 一致性至少包括：

- 每个 manifest ID 是安全单路径段且存在可读、Schema 合法的 preset；
- manifest 的 name/layout/default/timestamps 与 preset 内容一致；
- 同一 ID 只有一个活动内容；
- preset 目录中的未知孤儿被报告，不静默纳入或删除；
- `.trash/.transactions` 不出现在 list；
- 操作完成后不存在指向缺失内容的 manifest 条目。

## 10. EventStore 索引与 JSONL 可靠性

### 10.1 启动索引

EventStore 在 lifespan ready 前顺序扫描一次 JSONL，构建实例私有索引：

```text
event_id → {byte_offset, line_length, semantic_fingerprint}
```

- 只索引 Schema v2 且 event_id 合法的事件；
- 重复 ID 且内容等价只保留首条并报告重复历史；
- 重复 ID 且内容冲突视为损坏，阻止写入并要求恢复；
- 最后一条截断 JSON 可诊断为崩溃尾行并恢复到最后有效换行边界；
- 文件中段坏行、无效 UTF-8 或非法 v2 事件不得静默跳过，进入 corrupt/recovery 状态；
- v1 行保持可读，不进入 ID 索引；
- 索引不作为独立业务真相，进程重启可由 JSONL 重建。

### 10.2 append

在 EventStore 私有锁内：

1. 验证 Event v2 和 semantic fingerprint；
2. 通过内存索引 O(1) 检查 event_id；
3. 已存在则读取/比较原事件，等价返回 `already_exists`，冲突报错；
4. 新事件序列化为单行 UTF-8 JSON，禁止内嵌换行；
5. 以 append 模式写入完整行和结尾 `\n`，flush + fsync；
6. 只有刷盘成功后才把 offset/fingerprint 加入索引；
7. 写入失败不更新索引；下次启动按尾行恢复规则处理。

不得在每次 append 时调用全文件 `_find_event`。查询可继续顺序扫描，R0.7 只要求 ID
幂等索引；统计量/查询门达到数据路线图阈值后再评估 SQLite。

### 10.3 外部变更与 close

- Store 记录已知文件 identity/size；append 前发现收缩、替换或未知增长时重建索引或报冲突；
- `flush()` 在当前实现 open-write-close 时可为空操作，但语义必须存在；
- `close()` 后拒绝 append；重复 close 安全；
- 两个 app 指向不同 JSONL 时索引绝不共享；同一路径多 app 写入不受支持并应诊断。

## 11. 备份、崩溃恢复与可观测性

### 11.1 备份策略

```python
@dataclass(frozen=True)
class BackupPolicy:
    root: Path
    keep: int = 20
    enabled: bool = True
```

- songs/settings/presets 分 kind 保存，文件名唯一且可按创建顺序裁剪；
- 备份在覆盖已有有效状态前产生；首次新建无旧内容时不创建空备份；
- 损坏目标不能覆盖最近已知良好备份；应先隔离损坏文件并要求恢复；
- 自动恢复只使用刚刚完成且摘要匹配的事务 before image；普通历史备份恢复需要显式操作；
- EventStore 是追加日志，不为每次 append 复制全文件；使用尾行恢复和后续 R0.9 导入/导出备份；
- 备份保留清理不得跟随符号链接逃逸 `BackupPolicy.root`。

### 11.2 故障注入点

adapter 必须允许测试替换 writer/file operations，在以下点抛错：

- 临时文件写入前/中/后；
- flush/fsync；
- 备份复制与备份校验；
- `os.replace` 前/后；
- 父目录 fsync；
- Preset prepared、preset publish、manifest publish、committed 各阶段；
- Event 行写到一半、fsync 前、索引更新前；
- backup retention 清理。

每次故障后必须能证明：旧状态可读或启动明确进入 recovery required；不得把半状态当成功。

### 11.3 日志与报告

可靠性操作使用结构化信息：repository kind、operation、transaction/event ID、phase、result、
recovery action。不得记录完整歌曲/设置/Preset 内容。恢复报告至少包含 detected、recovered、
quarantined、unresolved 和可执行 recovery 建议。

## 12. RenderDocument 冻结输入

### 12.1 所有权与构造时点

`RenderDocument` 属于应用/渲染边界，不属于 Repository。Repository 只提供版本化快照；
Application Service 在请求线程中解析 SongQuery、Preset、settings、主题和布局，并在启动预览/
导出任务前构造完整不可变文档。

```python
@dataclass(frozen=True)
class RenderDocument:
    document_id: str
    song_snapshots: tuple[SongSnapshot, ...]
    layout: LayoutSnapshot
    palette: PaletteSnapshot
    skin: SkinSnapshot
    canvas: CanvasSnapshot
    title: str
    subtitle: str
    parameters: FrozenMapping
    page_policy: PagePolicy
    avoidance: AvoidanceSnapshot
    font: FontSnapshot
    engine_version: str
    source_revisions: SourceRevisions
```

具体字段模型由角色 A 在 R0.6/R1 渲染服务接入时定义，但以下不变量在 R0.7 已冻结：

- 文档及所有嵌套集合深度不可变，不能只冻结顶层 dataclass 而保留 dict/list；
- `song_snapshots` 保存渲染需要的值，不保存 `Song`/`SongLibrary` 可变引用；
- layout/palette/skin/canvas/parameters/page policy/avoidance/font 全部在入队前解析；
- `source_revisions` 记录 songs/settings/preset/主题等来源版本，供诊断和重现；
- 文档不保存 Repository、AppContext、FastAPI request、路径全局或运行中缓存引用；
- 输出目录、文件命名策略和授权后的目标路径作为显式 job input 冻结，不在后台重读 settings；
- `document_id` 标识内容快照；重试同一导出可复用同一文档；
- Preview、Export 和 ExportSnapshot 必须使用同一构造器与语义；
- 旧 `render_page()` 通过兼容 adapter 消费文档派生值，输出保持金标准。

### 12.2 导出任务边界

后台 job 的最小输入：

```python
ExportJobInput(
    job_id=...,
    document=render_document,
    output_target=frozen_output_target,
    event_store=explicit_event_store,
    job_state=instance_owned_state,
)
```

- job 启动后歌曲改名/删除、Preset 修改、settings/output_dir 修改均不改变本 job；
- job 不调用 Repository load、不读取 `request.app`，不访问 `_GLOBAL_*`；
- job 状态属于当前 app 的 `ExportJobManager`，关闭 app 时有界停止；
- 导出完成事件通过显式 EventStore 追加，并包含 document/job 追踪信息；
- 导出文件采用临时文件 + fsync + replace，失败不留下被当作成功的目标 PNG；
- RenderDocument 构造失败不创建 job；文件发布失败 job 明确 error，不能上报成功事件。

## 13. AppContext 接口边界

R0.6 lifespan 负责：

1. 从当前 `AppPaths` 构造四个 adapter；
2. 在 ready 前执行 Schema 校验、Preset recover 和 Event 索引构建；
3. 把它们作为 port 类型放入当前 app 的 `AppContext`；
4. 构造只依赖 ports 的 Application Services；
5. 关闭时先停止 ExportJobManager，再 flush/close Store 和 Repository。

R0.7 adapter 负责自身文件一致性，不负责：

- 解析平台默认数据目录或切换 data_root；
- 创建/替换 AppContext；
- 注册 Router、middleware 或 lifespan；
- 决定 HTTP 状态码；
- 持有 export thread pool；
- 修改另一个 app 的 Repository 或索引。

启动任一 Repository 发现不可恢复损坏时，lifespan 不得发布半完整 context。已经构造的实例按逆序
close，app 不进入 ready。关闭流程幂等；一个 close 失败不跳过其余资源关闭，并汇总诊断。

## 15. 测试矩阵

全部测试使用测试创建的独立临时目录，禁止读取/写入仓库真实 `data/`。

### 15.1 共享 writer 与备份

- 首次新建、覆盖、Unicode/空格路径和大 JSON；
- 临时文件与目标同目录；序列化/flush/fsync/replace/目录 fsync 逐点失败；
- 每个失败点旧目标保持字节和 Schema 有效，临时文件可诊断清理；
- 成功提交后目标可重读且 revision 对应内容；
- 写前备份内容与旧目标摘要一致；同秒连续备份不覆盖；
- keep=0/1/N、清理失败、无关文件和符号链接边界；
- Windows replace/打开句柄降级与 macOS/Linux 正常路径。

### 15.2 SongRepository

- 空文件/不存在、v4 只读加载、v5 往返和首次 v5 持久化备份；
- ID/title 重复、空身份和高版本 Schema 拒绝；
- 返回快照在锁外修改不污染下次 load；
- 两线程同 revision 保存恰好一成一冲突；
- save 任意故障点后旧库仍可读取；
- 两个实例不同路径不共享锁、缓存或内容。

### 15.3 SettingsRepository

- 默认值、合法更新、未知字段策略、错误类型与 revision；
- 两个并发局部更新不静默互相覆盖；
- 损坏 JSON 不以默认值覆盖，返回 corrupt/recovery；
- 原子写、备份、故障恢复和多实例隔离；
- settings 不保存 data_root，不接受路径逃逸到另一个 app。

### 15.4 PresetRepository

- list/get/save/delete/duplicate、ID 路径安全、`custom_ids` 校验；
- manifest 与内容字段/摘要一致，`.trash/.transactions` 不出现在 list；
- 同 ID 并发 save CAS 冲突，不产生半 manifest；
- prepared 前后、preset publish 前后、manifest publish 前后、committed 前后逐点崩溃；
- 每个崩溃状态重启 recover 后要么完整新状态、要么完整旧状态；
- recover 重复两次幂等，delete 不重复 trash，duplicate 不重复创建；
- 未知孤儿、缺内容、坏摘要、缺 before image 阻止 ready 并给恢复报告；
- 默认/普通 Preset、Unicode 名称、备份裁剪和多 app 隔离。

### 15.5 EventStore

- 空文件、v1/v2 混合、启动索引数量与 offset 正确；
- 新 event append 后索引更新且重启可重建；
- 同 ID 等价补报返回 already_exists 且文件行数不变；
- 同 ID 不同内容 conflict；append 路径不得全文件扫描；
- 并发相同 ID 只追加一次，并发不同 ID 全部完整落行；
- 半尾行恢复、中段坏行/非法 UTF-8/冲突旧 ID 阻止写入；
- 写半行、fsync 失败、索引更新前崩溃后的重启行为；
- 外部 truncate/replace/grow 检测；close/重复 close/close 后 append；
- 两个实例不同路径索引隔离，v1 不被伪造 ID。

### 15.6 RenderDocument 与导出

- 构造后修改 SongLibrary/Song/settings/Preset/主题参数不改变文档；
- 嵌套 list/dict 不能被调用者变更；
- 同输入产生等价文档与 source revisions；
- preview/export 使用同一文档，`grid-wrap` 输出 16/16 `diff=0`；
- job 入队后改名/删除歌曲或修改 output_dir，不改变在途输出；
- 两 app job state、Repository、EventStore 完全隔离；
- 后台任务不访问 request/AppContext/Repository load/模块全局；
- 输出写入失败不留下成功目标、不追加 poster_exported 成功事件；
- app 关闭时 job 有界完成/取消并释放资源。

### 15.7 静态边界与完整回归

- Repository/port import 不创建目录、不读取真实数据、不启动线程；
- adapter 不 import FastAPI，不访问 `server.deps` 或模块级路径；
- `core/` 不 import FastAPI/Electron/React/server adapter；
- Python 单元测试全部通过；
- TypeScript `tsc --noEmit` 通过；
- 金标准 16/16 `diff=0`；
- `git diff --check` 通过。
