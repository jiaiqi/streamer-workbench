# R0.5 角色 B 任务单：Tabs、Preset 与迁移器

> 状态：可领取  
> 前置契约：[`R0.5-song-relations.md`](R0.5-song-relations.md)  
> 建议分支：`feature/r0-tabs-presets`  
> 交付对象：角色 A

## 1. 本批目标

角色 B 本批只实现 Tabs、Preset 和数据迁移器，不修改 QuickView。完成后先交给角色 A 集成 Tabs API，再领取 QuickView 工作包。

## 2. 允许修改

```text
core/data/tabs.py
core/data/presets.py
server/routers/presets.py
tools/migrate_data.py
tests/test_unit.py（Tabs、Preset、迁移测试区）
```

如需修改 `server/routers/songs.py`，先向角色 A 提交接口变更说明；该文件当前由角色 A 持有。

## 3. Tabs 任务

1. 将所有新写入目录改为 `data/tabs/{song_id}/`；
2. `save_tab` / `delete_tab` 参数语义改为稳定 `song_id`；
3. 保持扩展名、尺寸、重名和路径穿越保护；
4. 提供旧 `tabs/{title}/` 到 ID 目录的迁移计划和执行函数；
5. 目标重名时不得覆盖，必须报告 conflict；
6. 迁移失败时保留旧目录；
7. 迁移成功后旧目录移入可恢复备份，不直接删除；
8. 第二次运行不得复制或改写已迁移文件。

## 4. Preset 任务

1. 明确 `SongQuery.custom_ids` 为 `list[str]` 的 `song_id` 集合；
2. 为旧歌名集合实现迁移；
3. 未匹配项进入 `unresolved`，不得静默丢失；
4. 拒绝重复或无效 ID；
5. 完成 Preset 创建、完整更新、读取、复制和软删除 API；
6. 保存完整 SongQuery、layout、palette、skin、canvas、params、export 和 overrides；
7. 不在本批引入 Pydantic，该项留给 R0.8；
8. 不改变 Palette v1 角色。

## 5. 迁移器任务

`tools/migrate_data.py` 增加 R0.5 关系迁移入口：

```text
--dry-run       默认或显式预演，不写入
--apply         执行迁移
--report PATH   输出 JSON 报告
```

报告至少包含：

```json
{
  "planned": [],
  "unchanged": [],
  "unresolved": [],
  "conflicts": [],
  "backups": []
}
```

执行顺序和回滚要求完全服从前置契约第 7 节。

## 6. 必须新增的测试

- ID 目录保存和重名去重；
- ID 目录删除和路径穿越保护；
- title 目录迁移为 ID 目录；
- 重复迁移幂等；
- 目标文件冲突停止且不覆盖；
- 未解析 title 进入报告；
- dry-run 不改变任何文件；
- Preset `custom_ids` 成功迁移；
- Preset 未解析项不丢失；
- Preset 完整字段 CRUD 往返；
- 软删除和 duplicate 保持现有行为。

## 7. 禁止事项

- 不修改 `.archive/` 或 `design/archive/`；
- 不修改 `Song.id` 生成规则；
- 不修改 Event v2 Schema；
- 不直接迁移仓库真实 `data/`；
- 不删除 title 兼容路由；
- 不修改 QuickView；
- 不更新金标准图片；
- 不引入 FastAPI 到 `core/`。
