## 1. 本切片范围

1. 定义框架无关的统一错误 `code/message/details/recovery/request_id`，并集中映射 Repository 错误；
2. 以 `/api/events` 与 `/api/events/report` 建立 Pydantic request/response 和错误响应范式；
3. 从 `create_app(test config).openapi()` 确定性导出 OpenAPI，并生成提交入库的 TypeScript 类型；
4. 新增不绑定 React 的 `apiClient`，集中处理 JSON、超时、取消和错误 envelope；
5. 用后端合约测试与 Node 内置前端测试守护以上边界。

## 2. 错误 envelope

```json
{
  "error": {
    "code": "event_not_found",
    "message": "未找到事件",
    "details": {},
    "recovery": "刷新后重试",
    "request_id": "req_..."
  }
}
```

- `code` 是稳定机器标识，前端不得解析 message；
- `details` 只包含安全、结构化上下文；
- `recovery` 是可选的用户下一步；
- `request_id` 可选，本切片允许尚无追踪 middleware 时为空；
- Repository conflict/corrupt/unavailable/recovery_required/closed 映射集中定义，不散落 Router。

## 3. 模型与兼容策略

- Event v2 显式 `song_id` 请求使用完整强类型信封；R0.5 title 兼容字段暂时保留为可选字段；
- 响应模型保留当前字段，不借类型化删除兼容行为；
- Pydantic 拒绝未知字段，避免写入端悄悄接受拼写错误；
- 本切片不修改 presets/render/export Router，也不批量迁移歌曲页面。

## 4. OpenAPI 与 TypeScript

- `tools/export_openapi.py` 只用临时 data_root 构造 app，不读取或写入真实用户数据；
- `tools/generate_api_types.py` 确定性生成 `ui/src/api/generated.ts`；
- OpenAPI JSON 是中间产物，不提交；生成的 TS 类型提交并由 CI 检查无漂移；
- 生成命令必须可在 macOS/Windows 的项目 Python 环境运行。
