# R0.7 Preset Application Service 契约

> 状态：已实现
> 最后更新：2026-07-29
> 上位依据：ADR-005、R0.7 Repository 契约、活跃路线图 R0.7/R0.11

## 1. 目标与边界

`FilePresetRepository` 已负责 manifest、item、trash 和 transaction journal 的原子提交与启动恢复；`PresetApplicationService` 在其上统一用户可见业务规则：

- 创建或完整更新场景预设；
- 查询列表与完整预设；
- 复制、软删除和切换默认预设；
- 管理服务端身份、创建时间、默认状态和 Repository revision/CAS；
- 将稳定业务错误交给 HTTP 适配层映射。

Router 不再读取 Repository 快照、决定 expected revision、生成 Preset ID 或直接编排跨文件提交。Service 不 import FastAPI，不读取全局路径。

## 2. 服务端持有字段

- 新建未提供 ID 时，由服务生成 `preset_<random>`；客户端不能通过 `is_default=true` 把普通新预设伪造成默认；
- `_default` 作为兼容预设，首次创建时默认；
- 新建 `created_at` 使用服务端带时区时间，更新保留原创建时间；
- 更新保留 Repository 当前 `is_default`，默认切换只能调用专用用例；
- Repository 在保存时生成 `updated_at`；
- `SongQuery.custom_ids` 保存前必须通过稳定 `song_id`、重复项和结构校验。
- 旧 `schema_version` 和空白名称属于客户端业务校验错误，必须返回 400，不能下沉为 RepositoryCorrupt。

## 3. CAS 与并发

- 创建使用 `MISSING_REVISION`，同 ID 并发创建只能有一个成功；
- 更新使用读取到的 item revision；
- 删除使用目标 item revision；
- 默认切换使用 manifest revision，由 Repository 在一个可恢复事务中更新所有受影响 item 和 manifest；
- RepositoryConflict 不被转换成业务 400，由统一 API Repository 映射返回 409。

## 4. 默认与删除规则

- 任意现有预设可以通过 `set_default` 成为当前默认；
- 客户端不能在完整更新负载中直接改变默认状态；
- 当前默认预设和兼容 `_default` 不可删除，必须先切换默认；
- 复制永远生成非默认的新身份；
- 删除继续使用 Repository 的可恢复 soft-delete/trash 语义。

## 5. HTTP 契约

- `GET /api/presets`：摘要列表；
- `GET /api/presets/{id}`：完整预设；
- `POST /api/presets`：创建或完整更新；
- `POST /api/presets/{id}/duplicate`：复制；
- `DELETE /api/presets/{id}`：软删除；
- `POST /api/presets/{id}/default`：切换默认。

业务错误统一返回带 `request_id` 的 JSON envelope：缺失为 `preset_not_found`，非法负载为 `invalid_preset`，默认保护为 `default_preset_protected`。Repository 错误继续使用全局错误映射。

## 6. 自动化证据

- 创建、更新、复制、删除、默认切换和默认保护完整闭环；
- 服务端字段不能被完整更新负载覆盖；
- 非法 SongQuery 和缺失目标返回稳定业务错误；
- 同 ID 双线程创建由 missing revision CAS 保证一成一败；
- Router 的全部写入口只委托 Application Service；
- 真实 FastAPI HTTP 覆盖 CRUD、默认切换与错误 envelope；
- AppContext 注入的服务与当前 PresetRepository 实例绑定；
- Repository 自身崩溃恢复、manifest/item/trash 一致性测试继续作为下层质量门。
