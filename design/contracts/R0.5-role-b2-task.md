# R0.5 角色 B2 任务单：QuickView 身份与离线事件

> 状态：可领取  
> 基线分支：`feature/r0-song-relations`  
> 基线提交：角色 A 派发本任务时的分支 HEAD

> 前置契约：[`R0.5-song-relations.md`](R0.5-song-relations.md)

## 1. 目标

将 QuickView 队列、已唱状态、localStorage 和离线补报从 title 身份切换为 `song_id`，并用生成于客户端的稳定 `event_id` 实现 Event v2 幂等补报。


如需修改 `server/routers/events.py`、`server/routers/songs.py` 或 Python 测试，先向角色 A 提交接口缺口；不得自行放宽已冻结 Event v2 信封。

## 3. 前端 Song 契约

`ui/src/types.ts` 的 `Song` 必须新增：

```ts
id: string;
```

所有队列关系以该 ID 为准。搜索、展示和排序仍可使用 title。

## 4. QueueItem

```ts
interface QueueItem {
  song_id: string;
  title_snapshot: string;
  sung: boolean;
  added_at: number;
}
```

约束：

- 去重、移动、标记已唱和删除全部按 `song_id`；
- 当前曲库存在该 ID 时显示最新 `Song.title`；
- 当前曲库不存在时显示 `title_snapshot` 并给出缺失状态；
- 改名不能产生第二个队列项；
- `title_snapshot` 在加入队列时记录，不作为身份键。

## 5. PendingEvent

```ts
interface PendingEvent {
  event_id: string;
  type: "queue_added" | "song_sung";
  song_id: string;
  title_snapshot: string;
  occurred_at: string;
  source: "quick-view";
}
```

约束：

- 事件产生时立即生成并持久化稳定 `event_id`；
- 重试不得生成新 ID；
- 必须提交完整 Event v2 信封；
- 上报成功后才从 pending 队列删除；
- 网络失败、非 2xx 和页面重载均不能丢失 pending；
- 补报保持原始 `occurred_at` 和顺序；
- 后端返回 event_id 冲突时保留事件并呈现可诊断错误，不无限静默重试。

浏览器中优先使用 `crypto.randomUUID()`，事件 ID 格式为 `evt_<uuid 去横线>`；若环境不支持，需要等价的高熵降级实现，不得用时间戳单独充当 ID。

## 6. localStorage 版本与迁移

使用带版本信封的存储，不再直接保存数组：

```ts
interface QuickViewStorageV2 {
  version: 2;
  queue: QueueItem[];
  pending_events: PendingEvent[];
}
```

必须兼容当前旧结构：

```ts
{ title: string; sung: boolean; addedAt: number }
{ type: string; title: string; ts: string }
```

迁移规则：

1. title 在当前 songs 中唯一匹配时转换为 `song_id + title_snapshot`；
2. 无法匹配的旧 queue 项保留为可见 unresolved，不静默丢失；
3. 无法匹配的旧 pending event 不自动上报，保留诊断信息；
4. 多个旧 title 项解析到同一 ID 时稳定去重，保留最早加入时间和已唱真值；
5. 迁移成功后写入 v2 信封；
6. 重复加载 v2 不产生任何变化；
7. JSON 损坏时不得覆盖原值，界面进入可恢复错误状态。

如果为了表达 unresolved 需要给 v2 增加明确字段，先更新实施契约并通知角色 A。

## 7. 纯函数边界

建议将以下逻辑从 React 组件抽到 `ui/src/quick-view/`：

- `migrateStorage(raw, songs)`；
- `resolveQueueItem(item, songsById)`；
- `enqueue(queue, song)`；
- `toggleSung(queue, songId)`；
- `moveQueueItem(queue, songId, direction)`；
- `createPendingEvent(type, song, now, uuid)`；
- `flushPending(events, reporter)`。

这些函数不读取 DOM，便于后续测试和 Electron 复用。

## 8. 必须证明

- 两首同 title 不会出现（后端已拒绝重复 title），但身份逻辑仍只使用 ID；
- 改名后队列保持同一项并显示新 title；
- 删除歌曲后 snapshot 仍可见；
- 旧 queue 成功迁移；
- 旧 queue 未解析项不丢失；
- v2 重复读取幂等；
- queue 操作全部按 ID；
- pending 失败后保留；
- 重试复用 event_id；
- 成功后删除对应 pending；
- 乱序网络响应不会误删其他事件；
- TypeScript 检查通过。

- 不放宽 Event v2 必填字段；
- 不删除 title 兼容上报；

- 不把 localStorage 提升为业务真相；
- 不提前改造全部前端 API（属于 R0.8）；
