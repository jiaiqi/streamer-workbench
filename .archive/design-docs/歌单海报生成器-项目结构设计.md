## 三、theme.json 格式

由旧脚本 `THEMES` 字典 1:1 映射而来，7 个主题全部可无损迁移。

### 3.1 Schema

```jsonc
{
  "name": "海洋柔光",                 // 显示名 = 目录名
  "version": 1,
  "output_prefix": "梓涵吃不饱-AI海洋歌单-柔光UI版",
  "backgrounds": {                    // 每页背景，文件名相对主题目录
    "1": "background-1.png",
    "2": "background-2.png"
  },
  "watermark_fix": false,             // 是否需要左下角「AI生成」水印修复
  "styles": {                         // 每页配色，5 个颜色角色
    "1": {
      "text":  [43, 84, 78],          // 歌名 RGB
      "label": [36, 110, 96],         // 标签文字 RGB
      "pill":  [188, 224, 210, 130],  // 标签底色 RGBA
      "line":  [232, 146, 118],       // 标签下划线 RGB
      "mist":  [255, 255, 255, 66]    // 柔光 RGBA
    },
    "2": { "…": "同上结构，允许两页不同色" }
  },
  "font": null,                       // 可选：主题级字体覆盖，null = 用全局字体
  "palette_ref": null,                // 预留（三期）：引用 palettes/ 下的色板名，拆分后替代 styles
  "source_image": null,               // 预留（四期）：主题制作向导的参考图路径
  "auto_generated": false,            // 预留（四期）：是否由向导自动生成
  "featured_artists": null,           // 可选（三期）：擅长歌手标记，如 {"artists": ["曾轶可","汪苏泷","花粥"], "marker": "♡"}
  "notes": "背景为用户供图/AI 生成，生图提示词见歌单-排版一文档"   // 可选备注
}
```

### 3.2 迁移对照（旧 THEMES → theme.json）

| 旧字段 | 新字段 | 说明 |
|---|---|---|
| `prefix` | `output_prefix` | 直接拷贝 |
| `bgs` 元组 | `backgrounds.1 / .2` | 直接拷贝 |
| `watermark` | `watermark_fix` | 直接拷贝 |
| `style[1]/style[2]` | `styles.1 / .2` | RGB/RGBA 元组转数组 |
| （无） | `font` | 新增能力，7 个主题先全填 null |
| 脚本顶部注释里的背景来历 | `notes` | 保留知识，如奶油玻璃/轻复古唱片=用户供图 |

### 3.3 loader 校验规则

- `styles` 必须含 5 个角色、两页齐全；RGBA 的 alpha 缺失时默认 255 并警告（pill/mist 除外，它们必须显式给 alpha）。
- 背景文件不存在 → 该主题在列表中灰显并提示，不崩溃。
- 新增主题 = 新建目录 + theme.json，App 重启或点「刷新」即出现，**零代码改动**。

## 四、数据模型（Song / songs.json / 学歌生命周期）

> 2026-07-23 需求更新：歌曲从「一个歌名」升级为带元数据的实体，并支持学歌管理。

### 4.1 Song 模型（`core/data/songs.py`）

```python
@dataclass
class Song:
    id: str                    # 内部标识（slug 或短 uuid）
    title: str                 # 歌名，唯一性校验的主要依据
    artists: list[str] = []    # 歌手（对唱/翻唱可多个）；歌手分区排版的数据基础
    lyricist: str = ""         # 作词
    composer: str = ""         # 作曲
    key: str = ""              # 选调，如「G 调」（吉他弹唱字段）
    capo: int = 0              # 变调夹品数，0 = 不夹
    difficulty: str = ""       # 简单/中等/困难，学歌优先级参考
    tabs: str = ""             # 谱子链接或来源说明
    status: str = "active"      # active 已会（上海报）/ draft 未会
    tags: list[str] = []       # 如「小甜歌」，供未来按风格分类
    pinyin: str = ""           # 歌名拼音首字母，入库自动生成（「枫」→ F）；多音字可手工覆盖
    added_at: str = ""         # ISO 日期
    notes: str = ""            # 备注，如「副歌要降 key」
```

### 4.2 songs.json

```jsonc
{
  "version": 1,
  "songs": [ { "id": "…", "title": "枫", "artists": ["周杰伦"], "status": "mastered", "…": "…" } ]
}
```

- 现有 178 首：`status=mastered`，仅 title 必填，元数据留空后补；**字数分组不写进 JSON**——由分类规则从 title 派生（顺序与源 md 一致，渲染结果不变）
- `学歌.md` 5 首：`status=learning`，artists 从「歌手 歌名」格式解析（薛之谦/南拳妈妈/五月天）
- 拼音生成依赖 `pypinyin`（加入 requirements）

### 4.3 学歌生命周期（SongLibrary 内置操作）

```
draft 未会 ──「学会了」──→ active 已会（上海报）
                                                    ↑                    │
                                                    └──── 恢复 ──────────┘
```

- `mark_learned(id)`：status 改 mastered 后，该歌**自动**按字数分类规则进入后续渲染的歌单——从「学会」到「上海报」零手工迁移
- 海报渲染**只取 active**；draft 不出现在海报上
- 数据模型和生命周期操作在 MVP 就实现；一键「学会了」按钮提到 MVP（已决策），完整管理界面（增删改、备注）属二期

### 4.4 校验

- 查重：title 完全相同即拦截（歌手辅助人工确认）
- 统计：mastered 总数与源 md 逐条比对（金标准测试的一部分）
- pinyin：字段已有值则不重新生成，允许多音字手工修正

### 4.5 速查、批量导入与备份（核心逻辑 MVP 实现，UI 二期）

- **速查**：`SongLibrary.search(query) -> Song | None`——按 title 精确/模糊匹配，返回 status 供速查窗口显示「已会 ✅ / 在学 📖 / 不会 ❌」；直播场景使用频率最高的接口
- **批量导入**（`core/data/importer.py`）：粘贴文本一行一首，支持「歌手 歌名」或纯歌名两种格式，解析 → 查重 → 默认 `status=learning` 入库；返回逐行结果报告（成功/重复/格式错误）
- **自动备份**：`SongLibrary.save()` 写入前把现有 songs.json 复制到 `data/backups/songs-YYYYMMDD-HHMMSS.json`，只保留最近 20 份；防止元数据累积成果被误操作清掉
- **原子写**：save() 必须先写 `songs.json.tmp` 再 `os.replace()` 替换正式文件——写到一半崩溃/断电不会留下半个 JSON；与自动备份配合形成数据安全闭环

## 五、核心引擎接口

### 5.1 CanvasSpec（`core/spec.py`）

把现在散落在 `compose()` 里的全局常量和开关收拢成一个显式参数对象。画布尺寸为自由参数（不再用 bool 切换），避让区以 Rect 列表暴露给排版插件：

```python
@dataclass(frozen=True)
class CanvasSpec:
    width: int = 1080
    height: int = 2400                 # 自由参数，不再由 bool 推导
    avoid_zones: tuple = ()            # 禁文区列表，每个元素为 (x0, y0, x1, y1)；空=不避让
    margin: int = 58
    font_song: int = 36               # avoid_zones 非空时引擎自动降 34
    font_label: int = 40
    row_h: int = 44
    label_h: int = 74
    sec_gap: int = 26
    # r_below 已下沉到 DrawContext（2026-07-25 执行），CanvasSpec 只保留 avoid_zones 几何定义

    @property
    def content_offset(self) -> int:
        """内容居中偏移：height > 1920 时下移居中，等于旧脚本的 OFF。"""
        return max(0, (self.height - 1920) // 2)

    # r_at() 已下沉到 DrawContext（2026-07-25 执行），排版插件通过 ctx.r_at() 调用

# 画布预设（UI 下拉选项，不是引擎逻辑）
CANVAS_PRESETS = {
    "抖音全屏 9:20": CanvasSpec(width=1080, height=2400, avoid_zones=((940, 1080, 1080, 2400),)),
    "标准 9:16":     CanvasSpec(width=1080, height=1920),
    # MVP 只实现以上两个；接口支持自由参数，后续加预设不改引擎
    # "小红书 3:4": CanvasSpec(width=1080, height=1440),
    # "B站横版 16:9": CanvasSpec(width=1920, height=1080),
}
```

参数面板的每一项 = CanvasSpec 的一个字段，UI 改参数 = 构造新 CanvasSpec 重渲染。

### 5.2 Style（`core/style.py`）

### 5.3 engine 合成管线（`core/engine.py`）

```
render_page(theme, layout, library, spec, page) -> PIL.Image
```

流程（与旧 `compose()` 严格同序，保证像素一致）：

1. 读背景 → `watermark_fix` 则去水印 → 全屏延展（顶部 80px 拉伸 + 模糊接缝）
2. 画柔光层（避让版底边 1498+OFF，否则 1410+OFF）→ **底版缓存**：按 (主题, 页, 画布规格) 缓存「背景+柔光」合成结果，参数调整（字号/边距/栏数）只重排文字层——预览 < 500ms 的关键
3. 加载字体（song/label 两个字号）
4. 构造 `DrawContext`，调 `layout.render_page(ctx, page)`
5. 返回 RGB 图（保存/预览由调用方决定）

## 六、排版插件接口

### 6.1 基类（`core/layouts/base.py`）

```python
@dataclass(frozen=True)
class ParamSpec:
    """暴露给右侧参数面板的可调项，UI 据此动态生成控件。"""
    key: str            # 对应 CanvasSpec 字段或插件自有参数
    label: str          # 显示名，如「歌名字号」
    kind: str           # "int" | "color" | "bool" | "choice"
    default: object
    min: int | None = None
    max: int | None = None
    choices: list | None = None

class LayoutPlugin(ABC):
    id: str                              # "grid-wrap"
    name: str                            # "全行网格绕排版"
    pages: int | None = None             # 固定页数（如 2）；None = 自动分页（按 page_capacity）
    page_capacity: int | None = None   # 自动分页单页最大内容高度（px）；None = 按 spec.height 动态计算（height − 顶部/底部安全区），按分类边界切页
    supports_avoidance: bool = True      # 是否支持 avoid_zones 避让（grid-wrap=True，极简清单版可能=False）

    @abstractmethod
    def params(self) -> list[ParamSpec]: ...

    @abstractmethod
    def categorize(self, library: SongLibrary) -> list[PageSections]:
        """分页 + 每页的分类清单。grid-wrap 返回：
        第1页 [一字,二字,三字,四字]，第2页 [五字,六字,长歌名/英文]"""

    @abstractmethod
    def render_page(self, ctx: DrawContext, page: int) -> int:
        """把该页内容画到 ctx 画布上。返回内容结束 y（供质检/柔光校验）。"""
```

### 6.2 DrawContext（`core/context.py`）

插件能用到的一切，既有「原料」也有「公共绘制能力」（从旧脚本提炼的共用函数）：

```python
@dataclass
class DrawContext:
    draw: ImageDraw.ImageDraw     # PIL 画笔
    spec: CanvasSpec              # 画布/避让参数（排版插件通过 DrawContext.r_at() 自行解读避让）
    style: Style                  # 本页颜色角色
    font_song: ImageFont.FreeTypeFont
    font_label: ImageFont.FreeTypeFont

    # 公共绘制能力（旧脚本已有，原样提炼，所有排版可复用）
    def draw_label(self, x, y, text): ...        # 胶囊标签（旧 draw_label）
    def draw_grid(self, songs, cols, y0, x0, x1): ...   # 全行分布网格（旧 draw_grid）
    def draw_grid_wrap(self, songs, cols, y0, x0) -> int: ...  # 同列减栏绕排（旧 draw_grid_wrap）
```

**设计意图**：新排版（便签拼贴/歌手分区…）写的时候，胶囊标签、网格、绕排这些「零件」开箱即用，插件只写布局差异。`draw_label` 等方法内部严格照抄旧实现，保证 grid-wrap 渲染结果与现状像素级一致。

### 6.3 插件注册

`core/layouts/__init__.py` 维护注册表；MVP 手写一行注册，后期如需再改目录扫描。
